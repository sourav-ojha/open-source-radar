## Today's Best Discoveries

### 1. SIMURG — 8.2/10
**Decision:** PROTOTYPE

**What it is** — A numpy-only, CPU-only Python library that watches an LLM's token stream character-by-character while it is still generating and aborts mid-flight when it detects decoding corruption (repetition collapse, cross-lingual drift, template/token leakage, structural garbage), so the host can regenerate before a user sees it. Backed by a 13-page technical report, not just a README claim.
**Why I should care** — Any self-hosted or quantized model in a pipeline occasionally derails, and this is fast enough (claimed 197,632 chars/sec on a laptop CPU vs. a model's ~250 chars/sec output rate) to never be the bottleneck, catching corruption within ~590 characters of onset.
**What it could replace** — Hand-rolled regex/heuristic repetition and language-drift detectors that most teams under-invest in.
**Ways I could use it** — Sidecar guard for any self-hosted/quantized model call; gate on any OpenAI-compatible streaming endpoint; failure-mode telemetry on which prompts/models derail most.
**Agent opportunity** — Reusable output-quality guard for any agent orchestration layer that streams model output; could be wrapped as an HTTP sidecar for JS/TS stacks.
**Integration effort** — Medium: trivial in Python (`pip install simurg`, 3 lines), needs a sidecar wrapper from a Node-first stack.
**Maturity** — Experimental — created 2026-07-20, v1.0.3, ~30 commits from 2 contributors, 39 stars/15 forks after ~6 weeks.
**License** — Apache-2.0, no restrictions.
**Alternatives** — Hand-rolled heuristics (status quo); Guardrails/NeMo Guardrails (validate completed output, not streaming, heavier to integrate).
**Why this one** — Solves a narrow real problem with a paper-backed, CPU-cheap approach rather than a heavyweight validation framework; explicitly and correctly scopes itself out of factuality checking (pairs with grounding, doesn't replace it).
**Recommendation** — Prototype it in front of any self-hosted/quantized model call; too new to trust unverified for anything user-facing.

### 2. Saccade — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A Node-native MCP server plus Chrome/Edge extension that gives an AI agent a leased, single-writer semantic view of one authorized browser tab with revision deltas, instead of repeated full-page transfers, with actions that wait locally and return a verified semantic-transition receipt.
**Why I should care** — Browser-automation agents built on naive scrape-and-click loops burn tokens and break on dynamic content and unverified actions — exactly the failure mode that would hit an agent automating the MSSP admin portal or a third-party SaaS console with no API.
**What it could replace** — Hand-built page-state diffing, action-verification, and tab-isolation logic in a browser-agent integration.
**Ways I could use it** — Automating admin-panel/SaaS-dashboard tasks with no API; long dynamic forms; agent workflows that must stay attached to a human's already-authenticated browser session.
**Agent opportunity** — Six MCP tools (capabilities, tab list/open, semantic read/act) usable directly via `npx -y @nanlogic/saccade mcp` in any MCP-compatible client.
**Integration effort** — Low to try (`npx` install, Node 18+), Medium to depend on given the prerelease unpacked-extension packaging.
**Maturity** — Experimental — created 2026-07-28, ~74 commits, 1 contributor, 2 stars. Publishes an honest head-to-head benchmark against Playwright (no blanket winner) rather than overclaiming.
**License** — Apache-2.0, no restrictions.
**Alternatives** — Playwright/Puppeteer driven directly by an agent (mature, deterministic, not built for live-session/verified-action semantics); hosted browser-agent infra like Browserbase (not self-hosted).
**Why this one** — Fully JS/TS-native (no foreign-ecosystem tax), and the self-published honest benchmark against Playwright is an unusually strong rigor signal for a single-contributor, 5-week-old project.
**Recommendation** — Trial it against a real internal admin-panel automation task; track as unproven infrastructure, not a Playwright replacement.

### 3. Verb Authority — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A Python library that scans exported AI-agent tool schemas (including MCP schemas) into a per-argument "authority map" — which arguments must come from trusted application code vs. which the model may legitimately fill — and provides a runtime gate that blocks a call when untrusted data tries to author a trusted-only argument.
**Why I should care** — Standard tool schemas have no way to express "the `to` field must come from an authenticated session, not from a webpage the model just read" — that gap is exactly the shape of a real class of prompt-injection attacks against tool-calling agents, directly relevant to any agent tooling built here and to MSSP client work.
**What it could replace** — Hand-written, easily-skipped per-tool authority checks and audit logic for agent tool-call arguments.
**Ways I could use it** — Free schema-scan audit step before shipping any custom MCP server or agent tool; runtime gate for tools with a genuinely sensitive fixed argument; a teaching example when reviewing third-party agent tools.
**Agent opportunity** — Standalone agent-tool-security building block; usable as a CI schema audit or an inline runtime boundary; has an optional Pydantic AI adapter.
**Integration effort** — Low for CI-based schema auditing; Medium to wire the runtime gate into a live non-Python agent process.
**Maturity** — Experimental — created 2026-05-26, ~86 commits from 2 contributors, but 0 GitHub stars and the maintainer explicitly labels it "early, research-grade work," "not production-ready." v0.10.0-beta.14 is the first PyPI release.
**License** — Apache-2.0, no restrictions.
**Alternatives** — General prompt-injection defenses that operate on content (input sanitization, LLM classifiers on tool results) rather than argument provenance; most agent frameworks have no equivalent today.
**Why this one** — Narrow, correctly-scoped, and backed by a documented case-study/evidence directory including a real frozen Playwright schema, not synthetic examples only — despite zero stars, the engineering discipline (skipped beta identifiers, security-disclosure process, contribution fixture format) reads as serious.
**Recommendation** — Run the schema scanner as a free audit against any MCP server or agent tool evaluated here; treat the runtime gate as an experiment, not a production control.

### 4. SSH Ache — 7.4/10
**Decision:** PROTOTYPE

**What it is** — A local-first, open-source desktop SSH client (Tauri 2/Rust + React) with terminal, SFTP, port forwarding, and a host/key vault, plus an opt-in MCP server letting an AI agent run commands over saved hosts under a default-deny, per-command-approval, audit-logged security model.
**Why I should care** — Wiring a coding agent to operate remote infra directly is an obvious productivity move and an obvious injection-attack surface; this is one of the few SSH+agent integrations seen so far with a genuinely considered security posture (explicit written warning about prompt injection via earlier command output) rather than a raw exec bridge.
**What it could replace** — A custom approval-gated exec bridge between an agent and a fleet of SSH hosts, plus whatever terminal+SFTP-client combo is in daily use now.
**Ways I could use it** — Daily-driver SSH/SFTP client for personal and MSSP infra work; supervised agent access to one disposable/staging host for routine ops; GUI port-forwarding/SOCKS management.
**Agent opportunity** — MCP server over local HTTP/JSON-RPC exposing `list_hosts` and `run_command`, each call requiring in-app approval unless a host is explicitly set to unattended Auto-allow.
**Integration effort** — Low: desktop download, MCP toggled on per host, bearer-token-authenticated and bound to localhost.
**Maturity** — Emerging — created 2026-07-20, ~11 commits, 1 contributor, 1 star, v0.9.0. "Community edition" language signals a separate paid Teams tier exists.
**License** — Apache-2.0 for the reviewed client; a separate paid "SSH Ache Teams" product is not reviewed here.
**Alternatives** — Termius (mature, cloud-based AI agent, closed-source); Tabby (open-source, mature, third-party community MCP plugin bolted on); Electerm and similar (no AI-agent story).
**Why this one** — The default-deny/per-command-approval/audit-log design is materially more careful than a raw agent-exec bridge, though it competes purely on that design against much more mature core SSH clients.
**Recommendation** — Try as a daily-driver client given the security-conscious design; experiment with the agent bridge only on disposable hosts, and don't treat the local secrets store as encrypted at rest (it isn't — full-disk encryption is the real protection).

## Small but High-Leverage Utility
**Deslop** ([fayerman-source/deslop](https://github.com/fayerman-source/deslop), MIT, 18 stars) is a portable "skill" file for coding agents (Claude Code, Gemini CLI, Google Antigravity) that teaches plain-English legal-writing discipline — killing legalese doublets, nominalizations, throat-clearing, and the broader pattern of verbose "AI slop" prose. It's a single skill file, not infrastructure, but the leverage is real: dropped into any agent's skill directory, it changes the quality of every generated doc, PR description, or client-facing writeup that agent produces afterward, for zero ongoing integration cost.

## Worth Watching
- **Kiso** ([oak-invest/kiso](https://github.com/oak-invest/kiso), Apache-2.0, 33 stars) — a CLI plus MCP server that publishes "Open Knowledge Format" bundles as static sites and exposes them to AI agents. The docs-to-MCP pattern is generically useful, but OKF itself is a brand-new Google spec with no visible independent adoption yet — needs the underlying format to gain traction, or a Kiso-specific bundle format that doesn't require OKF, before it's worth adopting.

High traction for a 7-week-old repo, which is itself worth watching for hype-vs-substance, but no deep review done yet — needs a clearer articulation of what "agent-native" project management actually does differently from Plane/Huly before it earns a full writeup.
