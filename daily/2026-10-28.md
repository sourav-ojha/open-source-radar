# Open Source Radar — 2026-10-28
_Rotation slot 1 — AI agents, MCP, coding productivity_

## Executive Summary
Today's slot-1 sweep found three genuinely distinct additions rather than more entrants in the already-saturated "agent orchestrator"/"agent sandbox" waves: a crowdsourced, evidence-graded corpus of agent-failure fix lessons (MisakaNet), a suite of 240 structured-output MCP tool wrappers aimed squarely at cutting agent context spend on common dev CLIs (Pare), and a statement-level policy/audit gateway for letting agents touch Postgres without a raw credential (Midplane). Two actively-tracked projects — Paseo and schemagate — both shipped meaningful architecture-level updates this week (cross-machine agent delegation; a LlamaIndex integration plus a new row-inspecting MCP tool). Generic "coding agent orchestration" and "agent skill registry" GitHub searches again surfaced mostly same-day noise, including a confirmed template-spam wave from a single org posting near-identical "GenPark" agent-governance repos across two GitHub accounts.

## Today's Best Discoveries

### 1. MisakaNet — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A git-backed, community-curated corpus of "evidence-graded" failure/fix lessons for coding agents, served over an MCP server (plus WebMCP, A2A, `llms.txt`). An agent hitting an error searches the corpus before re-debugging from scratch; a miss files an intake that can become a reviewed lesson.
**Why I should care** — This is a different shape of "agent memory" than what's already in the catalog (MemPalace, Hippo, deja-vu) — those are personal session history; this is a shared, versioned, reviewed knowledge base any agent can query cold.
**What it could replace** — The repeated 15-30 minute debugging detour for errors common enough that someone already solved and documented them.
**Ways I could use it** — Query mid-task via the hosted MCP endpoint (no install); wire it into an agent's error-handling loop; use the GitHub Action to check CI failures against the corpus automatically; contribute intakes to build a team-internal fix log; mirror the published hash-verified dataset privately.
**Agent opportunity** — Purpose-built MCP tool (8 tools, `misakanet_search` / `misakanet_submit_intake` documented) plus a GitHub Action for CI-triggered lookups.
**Integration effort** — Low: the hosted endpoint needs no install; local stdio server and PyPI library are also available.
**Maturity** — Emerging. GitHub API confirmed Apache-2.0, 543 stars, 227 forks, 27 subscribers, created 2026-04-29, pushed same day as this review. Self-reported retrieval benchmark (R@1 0.446 on 267 queries) is modest and below the project's own target.
**License** — Apache-2.0, confirmed via API. No commercial-use restrictions; contributed lessons carry the same license with a DCO sign-off.
**Alternatives** — MemPalace, Hippo, deja-vu (personal agent memory, not a shared corpus).
**Why this one** — It's the first entrant in this niche that's explicitly a shared, reviewed, versioned public corpus rather than a personal memory store — closer to a package-advisory database than to agent memory in the usual sense.
**Recommendation** — Prototype: wire the hosted MCP endpoint into a real coding-agent session and see how often it surfaces something useful for this profile's stack (Node/Mongo/AWS) before trusting it further. Downside is bounded since the agent still executes any suggested fix under its own guardrails.

### 2. Pare — 7.3/10
**Decision:** PROTOTYPE

**What it is** — A suite of 28 MCP server packages (240 tools) wrapping common dev CLIs — git, GitHub, npm/cargo/go/bun/deno/dotnet/ruby/jvm, build/lint/test runners, docker/k8s/terraform/trivy/ssh, ripgrep/curl/psql/redis — each returning schema-validated structured JSON instead of raw terminal text.
**Why I should care** — A meaningful share of a long coding-agent session's context budget goes to verbose CLI output (test runs, installs, build logs). Pare attacks this at the source for exactly the tool surface (git, npm, docker, test runners, Postgres/Redis) this profile uses daily.
**What it could replace** — Hand-written, one-off MCP wrappers per CLI tool, and the agent tool-use errors that come from parsing scraped terminal text.
**Ways I could use it** — Swap raw `git status`/`npm test`/`docker ps` calls for structured equivalents; use the `full` preset across a polyglot repo; scope which tool domains an agent session can reach via env-var filtering; use the terraform/trivy/k8s servers for structured infra inspection.
**Agent opportunity** — Native MCP `outputSchema` usage reduces a class of agent parsing errors versus scraping CLI text; filtering env vars keep context cost down.
**Integration effort** — Low: one `npx @paretools/init` command, though the README itself recommends installing only 2-4 of the 28 servers rather than everything.
**Maturity** — Emerging. GitHub API confirmed MIT, 139 stars, 16 forks, 0 subscribers, created 2026-02-10, pushed 2026-10-28. CI, coverage, and OpenSSF badges present; token-savings benchmark covers only 8 of 240 tools and is self-reported.
**License** — MIT, confirmed via API. No restrictions.
**Alternatives** — Headroom, Paritok, squeeze (already catalogued) — those compress whatever output an agent already received; Pare instead makes the tool call itself return structured output natively.
**Why this one** — Different mechanism than the generic-compression tools already tracked, and covers the specific CLI surface (git/npm/docker/test) this profile touches most.
**Recommendation** — Prototype with the 2-4 servers most relevant to this stack rather than the full preset, and measure whether structured output actually reduces agent tool-use errors.

### 3. Midplane — 6.9/10
**Decision:** PROTOTYPE

**What it is** — A self-hostable gateway between AI agents (over MCP) and Postgres: every statement is parsed with Postgres' own parser, checked against a per-table policy with pre-aggregation masking, logged to a hash-chained local audit trail, and only then executed. Writes can require approval bound to the exact statement and row count reviewed.
**Why I should care** — Letting an agent touch Postgres today is usually all-or-nothing (a raw connection string). Midplane's parse-then-policy-then-audit pipeline is governance this profile would otherwise have to hand-build before trusting an agent with real data — relevant both to his own products and to the MSSP/PTaaS compliance context.
**What it could replace** — A multi-week, hand-built SQL-statement-aware policy/audit/masking layer.
**Ways I could use it** — Give an agent scoped, masked, audited Postgres access instead of a raw credential; require approval on agent-issued writes; enforce "writes need a `WHERE`" and similar guardrails; keep a tamper-evident log of agent DB activity.
**Agent opportunity** — MCP-native by design; the taint/containment rule (write access closes once an agent reads an untrusted/secret-labeled column) is a pattern worth studying generally.
**Integration effort** — Medium: the Docker Compose quickstart is simple, but the full policy language is only documented externally and the approval workflow needs invite-only Cloud access.
**Maturity** — Experimental. GitHub API confirmed MIT, 5 stars, 1 fork, 0 subscribers, created 2026-04-29, pushed 2026-10-28. CI, signed/provenance Docker images, a SECURITY.md, and a runnable local quickstart — but security claims ("a mask or policy can't be bypassed") are unaudited and unbenchmarked in the repo.
**License** — MIT, confirmed via API. No restrictions; Cloud tier terms undocumented and invite-only.
**Alternatives** — Hand-rolled read-only DB users + Postgres RLS (no per-statement audit or pre-aggregation masking); generic API gateways (not statement-aware).
**Why this one** — Statement-level parsing plus masking-before-aggregation is a meaningfully stronger guarantee than RLS alone, and it's the first entrant in this specific agent-DB-governance niche seen on the radar.
**Recommendation** — Prototype the local-mode Docker Compose quickstart against a non-production database to evaluate the policy/masking behavior directly; do not rely on the unaudited security claims without independent verification.

## Meaningful Updates

**Paseo** — v0.12.0 → v0.14.0-beta.1; previously filed PROTOTYPE at 7.8. Added cross-machine agent delegation (`paseo host add` over SSH/relay — one daemon can hand work to another machine's daemon), per-agent plugin tool/MCP-server configuration at session open, and collapsible conversation-turn summaries. This is a real architecture step: Paseo moves from "control one machine's agents from anywhere" toward "coordinate a small fleet of machines' agents from one place." Does this change the recommendation: No, still PROTOTYPE — the delegation feature is beta and worth retesting specifically. Catalog updated: Yes.

**schemagate** — v1.10.0 → v1.14.0; previously filed PROTOTYPE at 8.0. Added a LlamaIndex retriever (new framework integration alongside the existing LangChain one), a `deep_answer` MCP tool that lets the model inspect a bounded row sample before answering (opt-in, off by default), reranker summary-width tuning, a bounded-timeout fix for hung catalogue re-reads, and a fix for a trailing-sentence SQL-injection-adjacent parsing bug. Does this change the recommendation: No, still PROTOTYPE, but `deep_answer` is worth testing directly since it moves schemagate from pure schema-filtering toward a bounded, opt-in data-aware answering step. Catalog updated: Yes.
