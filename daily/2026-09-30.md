# Open Source Radar — 2026-09-30
_Rotation slot 1 — AI agents, MCP, coding productivity_

## Executive Summary
Today's slot is the most heavily worked seam in the catalog, so the useful signal was in
narrow, well-differentiated niches rather than more coding-agent-harness clones. The
standout pattern: three independent same-week projects (Abide, jevgrep, and Worth-
Watching entry mu) all reach for a cheap, typed "judge model" — a small decision model
that answers one bounded probability question instead of a full generative call — as a
sidecar to the main coding agent. That's a genuine emerging primitive in agent
engineering, not one vendor's marketing angle, and worth tracking independent of whether
any single implementation sticks. Separately, agent memory got a real new idea (explicit
wrongness/decay instead of pure accumulation) and agent-cost observability got a FinOps-
flavored entrant distinct from the debugging/security tools already catalogued.

## Today's Best Discoveries

### 1. Hippo (hippo-memory) — 7.8/10
**Decision:** PROTOTYPE

**What it is** — Local SQLite memory for coding agents (Claude Code, Codex, Cursor,
OpenClaw, OpenCode, Pi, any MCP client) with git-trackable markdown mirrors and
zero-dependency BM25 search by default.
**Why I should care** — every agent-memory tool already in the catalog (mex, LightAgent,
Commonly, Edda, LightMem) just accumulates facts; Hippo is the first to model "this
turned out wrong" as a first-class signal — mark a memory wrong and it ranks down,
`hippo supersede` retires it entirely.
**What it could replace** — re-explaining the same correction to a coding agent across
sessions; memory tools that degrade into equal-weight noise over time.
**Ways I could use it** — wire into this radar repo or any actively agent-worked repo
via `hippo init`; let an agent self-install via `llms-install.md` and `hippo doctor`; use
the markdown mirrors for normal git-based review of what the agent "remembers."
**Agent opportunity** — MCP server plus native hooks for six agent runtimes; broadest
compatibility surface reviewed this run.
**Integration effort** — Low. `npm install -g hippo-memory && hippo init`, zero runtime
deps for the default path; embeddings and a hosted reranker are opt-in only.
**Maturity** — Emerging (created 2026-03-15, actively maintained, npm 1.52.9).
**License** — MIT, zero-dependency default — the most self-hostable find this run.
**Alternatives** — mex, LightAgent, Commonly, Edda, LightMem — none model decay.
**Why this one** — the supersede mechanic is a genuinely new idea in a crowded niche, not
a rehash.
**Recommendation** — Try it on a real, actively agent-worked repo for a few weeks before
depending on it.

### 2. jevgrep — 7.6/10
**Decision:** PROTOTYPE

**What it is** — a CLI (`jg`) plus installable agent skill that uses a cheap judge model
to rank relevant files/declarations for a natural-language question, returning source
excerpts so a coding agent skips its own exploratory grep/read cycle.
**Why I should care** — the "agent reads six files to find the one that matters" tax
shows up on every non-trivial task on a MERN/Node/React codebase; jevgrep's own 10-task
SWE-bench comparison reports the same 8/10 task completion at ~30% lower cost.
**What it could replace** — the manual habit of pointing an agent at the right file, and
part of the token cost of agent-driven exploration.
**Ways I could use it** — `jg skill` to teach Claude Code/Codex/OpenCode to call it
automatically before implementing cross-cutting changes.
**Agent opportunity** — ships through the existing vercel-labs/skills installer, so it
plugs into an agent-skill workflow with no bespoke integration.
**Integration effort** — Low. `npm install -g @dzhng/jevgrep`; requires a key for one of
several judge-model providers.
**Maturity** — Very early — repo created 4 days before this review, but built by a known
open-source author (dzhng, of the widely-used "deep research" project) with 5 active
contributors and a disclosed benchmark.
**License** — MIT; depends on an external judge-model endpoint (several provider choices).
**Alternatives** — plain ripgrep + agent judgment; embedding/RAG-based code search tools.
**Why this one** — deliberately keeps the search step cheap via a typed judge model
rather than adding a heavier RAG layer.
**Recommendation** — Low-risk trial; treat the cost-reduction claim as unproven until it
has more runway.

### 3. Abide — 7.5/10
**Decision:** PROTOTYPE

**What it is** — hooks into Claude Code, Codex, and OpenCode and checks every edit
against prose project rules in `AGENTS.md`/`CLAUDE.md` — the kind no linter can check —
using the same cheap typed judge model pattern as jevgrep, at ~300ms and a fraction of a
cent per check.
**Why I should care** — this repo's own `AGENT.md` is exactly the kind of unenforceable-
by-linter rule set Abide targets. Its own benchmark replayed 93 real Claude Code sessions
against their own `AGENTS.md` and found a rule broken on 1 turn in 13, from the first
edit.
**What it could replace** — manual review passes that exist purely to catch drift from
rules that aren't codeable as lint rules (premature abstraction, error-handling policy,
architectural constraints).
**Ways I could use it** — run against this radar repo's own `AGENT.md`, or against team
conventions on any repo where a coding agent does unattended work.
**Agent opportunity** — CLI hooks (`npx @coldtea/abide init`) for Claude Code, Codex,
OpenCode; no MCP server.
**Integration effort** — Low, but core function depends on an external TypeSafe API or
Vercel AI Gateway key — not fully self-hostable.
**Maturity** — Experimental. Created ~12 days ago, npm 0.0.7, no tagged GitHub release,
two visible contributors — the disclosed, reproducible benchmark is unusually rigorous
for this age, but there's no track record yet.
**License** — MIT on the code; real external API dependency for the judge model.
**Alternatives** — linters (can't express these rules), manual review, agent self-review.
**Why this one** — the calibrated-probability-not-prose design is what makes checking
every single edit economically sane for the first time.
**Recommendation** — Cheap, near-free trial on a non-critical repo; hold off on anything
load-bearing given the 0.0.x maturity and external API dependency.

### 4. Agent Console — 7.2/10
**Decision:** PROTOTYPE

**What it is** — local-first observability for Claude Code/Codex sessions: tokens, cache,
models, and estimated cost, on one machine or joined across a small team's machines via a
self-hosted hub, with optional OpenTelemetry/Prometheus/Grafana integration.
**Why I should care** — this is a FinOps angle on agent usage, distinct from the
debugging/security angle already covered by AgentSight, Headroom, and SIMURG in the
catalog — relevant for tracking agent-assisted development cost, including on the
MSSP/PTaaS side where cost accountability across contractors matters.
**What it could replace** — guessing at agent spend from a provider dashboard that
doesn't break usage down by project or person.
**Ways I could use it** — solo local cost tracking; a self-hosted team hub if working
with contractors; "presenting mode" to show agent usage/cost to a client without leaking
real names.
**Agent opportunity** — reads agent transcripts directly; optional OTel/gateway ingest.
**Integration effort** — Medium for the team hub, low for solo local use.
**Maturity** — Experimental by age (10 days old) but unusually rigorous supply-chain
practice for that age: OpenSSF Scorecard, Apple notarization, SBOM, signed attestations,
a documented threat model.
**License** — MIT.
**Alternatives** — AgentSight, Headroom, SIMURG, mcpsnoop — none frame this as team-wide
cost accounting with a presenting mode.
**Why this one** — the only entry in the observability niche built around "how much is
this costing, per person, per machine."
**Recommendation** — Run locally for a week to see real cost patterns before committing
to the team-hub feature.

## Worth Watching
- **ZCode** (zai-org/ZCode) — Z.ai's (Zhipu AI's) official coding-agent workbench:
  desktop app, browser UI, and terminal agent in one repo, Apache-2.0, 7,201 stars /
  2,187 forks in 10 days. Genuinely backed by a real AI lab, but it's a full IDE-class
  competitor to Cursor/Claude Code rather than an embeddable component — would need to
  see non-Chinese-market adoption and a clear "why this over what I already use" before
  it's worth a full entry.
- **mu** (qybaihe/mu) — a coding agent built on `pi` with a "judgment kernel": 35 named
  decision points per turn, each routable to a cheap local judge (Laya), the same "Jev"
  model as Abide/jevgrep, or any LLM. Contributors include Armin Ronacher and Mario
  Zechner — real engineering pedigree. Pre-release (npm 0.1.7); would need a stable 1.0
  and English-first docs (current README is multi-language, early) to be worth adopting
  rather than just studying the decision-point architecture.
- **SkillEvaluator** (NVIDIA/SkillEvaluator) — official NVIDIA framework for validating,
  deduplicating, and live-evaluating AI agent skills, backed by an arXiv paper and part
  of NVIDIA's Verified Skills pipeline. Directly relevant to authoring/vetting Claude
  Code skills, but full value is tied to NVIDIA's own catalog/SkillSpector/Harbor
  pipeline; would be more interesting with a clearly documented standalone path for
  vetting a single custom skill outside that pipeline.
