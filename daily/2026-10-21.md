_Rotation slot 1 — AI agents, MCP, coding productivity_

## Executive Summary
Today's biggest signal wasn't any single discovery — it was the state of the GitHub search results themselves. Generic "coding agent" and "agent orchestration" keyword searches returned almost nothing trustworthy by star count alone: new and unknown repos routinely showed star:watcher ratios of 49:1 to 267:1, a much more extreme version of the fake-engagement pattern first flagged on 2026-10-18. Subscriber count, contributor diversity, and commit-message substance did the real discriminating work this run. Underneath that noise, two genuine, differentiated finds stood out in the "structured agent-driven development" space — one from AWS Labs, one from an independent single-maintainer project solving the same problem at much lower overhead — plus a codebase-intelligence MCP server and a data-engineering agent that both showed real, multi-contributor, actively-released substance.

## Today's Best Discoveries

### 1. AI-DLC Workflows — 8.0/10
**Decision:** PROTOTYPE

**What it is** — AWS Labs' open-source, harness-neutral workflow engine: a deterministic 5-phase/33-stage process with 14 agents, human approval gates, and a 121-event audit trail, layered onto Claude Code, Codex CLI, Cursor, Kiro, opencode, and GitHub Copilot via thin per-harness adapters.
**Why I should care** — Most "spec-driven development" tools in this space are single-author side projects. This one is backed by an official AWS org, has real multi-contributor commit activity, near-daily preview releases, and genuinely supports six different agent harnesses instead of locking into one.
**What it could replace** — Hand-written CLAUDE.md conventions and ad-hoc slash commands for enforcing review/approval gates on agent-driven work.
**Ways I could use it** — Force a design+security review gate before an agent touches code on a change that matters; get a persistent audit trail across a multi-session feature build; run the same workflow whether today's agent is Claude Code or Codex CLI; use the phase-gate/audit-trail design as a reference architecture even without full adoption.
**Agent opportunity** — The harness-neutral design is itself the agent opportunity: one workflow definition across six different agent CLIs.
**Integration effort** — Low. Curl/PowerShell installer, one config command (`aidlc config --harness <name>`), invoke via `/aidlc`.
**Maturity** — Emerging. Created Nov 2025, 5,433 stars / 979 forks / 51 subscribers, 10+ distinct real contributors, not archived.
**License** — MIT-0 (MIT No Attribution) — the most permissive common OSS license, verified via GitHub API.
**Alternatives** — MoAI-ADK (catalogued, Claude Code-specific); Spec Kitty, buildermethods/agent-os, GSD Pi (evaluated previously, saturated wave, no standout); ai-coding-project-boilerplate (below — the lightweight counterpart).
**Why this one** — Official AWS backing plus genuine multi-harness support, where the rest of this niche is single-author and single-tool.
**Recommendation** — Prototype on a real feature, specifically a higher-stakes one where the audit trail has standalone value.

### 2. ChunkHound — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A local-first codebase-intelligence MCP server and CLI: Tree-sitter parsing across a dozen+ languages, semantic + regex code search, git-history search (by commit/tag/branch/range), and web research grounded back to the local codebase with cited answers.
**Why I should care** — Most code-search-for-agents tools stop at "find relevant code." ChunkHound adds git-history-aware search and cited external-web grounding in the same tool — useful for "did this already get fixed" or "does this still match the vendor's docs" questions that come up constantly in unfamiliar codebases.
**What it could replace** — Manually grepping git log/blame history, and separately opening docs in a browser, while an agent works.
**Ways I could use it** — Grounded Q&A over a large unfamiliar codebase; git-history search when tracking down when/why a behavior changed; combined local+web research in one query; fully local indexing via Ollama when content can't leave the machine.
**Agent opportunity** — Ships as an MCP server directly — drops into Claude Code, Cursor, or any MCP-capable agent with no wrapping needed.
**Integration effort** — Low. `pip install chunkhound`, configure `.chunkhound.json`, point an MCP client at it.
**Maturity** — Emerging-to-established. Created June 2025, 1,454 stars / 142 forks / 7 subscribers, PyPI package, Discord community, 1,332 commits, v6.1.0 released the day before review.
**License** — MIT, verified via GitHub API.
**Alternatives** — mex and Semble (both catalogued, PROTOTYPE 8.1) cover local code search but lack git-history search and cited web grounding; zvec-grep (Worth Watching previously) is narrower still.
**Why this one** — The git-history-search and cited-web-research features are genuinely missing from the already-catalogued alternatives in this niche.
**Recommendation** — Prototype as an MCP server on an unfamiliar or legacy codebase, specifically testing the two differentiating features.

### 3. ai-coding-project-boilerplate — 7.4/10
**Decision:** PROTOTYPE

**What it is** — A TypeScript project starter purpose-built for structured Claude Code development. `npx create-ai-project` scaffolds a TS/Node repo with Biome, Vitest, and a project-level CLAUDE.md pre-wired, plus slash commands (`/implement`, `/design`, `/plan`, `/build`, `/review`, `/diagnose`) in two modes — Normal (design + security review gates, lint/test after each task) and Lite (checks run once before review).
**Why I should care** — This is the direct, lightweight counterpart to AI-DLC Workflows above: same core idea, scoped to one language and one harness, with an explicit lower-overhead mode. Since Claude Code is the tool this radar itself runs on and TypeScript/Node is core to the stack, it's about as direct a fit as a discovery gets.
**What it could replace** — Writing a CLAUDE.md and custom slash commands from scratch on every new TypeScript project.
**Ways I could use it** — Bootstrap a new TS/Node service or micro-SaaS repo with guardrails already wired in; Lite Mode for fast solo work, Normal Mode when a change needs a documented design+security pass; `/project-inject` to record project context once per project.
**Agent opportunity** — Directly structures Claude Code usage on a project via commands, specialized agents, and skills.
**Integration effort** — Low. `npx create-ai-project my-project`, `pnpm install`, start Claude Code.
**Maturity** — Experimental-to-emerging. Created July 2025, single-maintainer (667 of ~673 commits), 234 stars / 28 forks / 3 subscribers, v2.2.2 released a week before review.
**License** — MIT, verified via GitHub API and the npm registry.
**Alternatives** — AI-DLC Workflows (far heavier, team-scale, 6 harnesses); MoAI-ADK (cost-routing focus, not workflow structure).
**Why this one** — The explicit Normal/Lite mode tradeoff is a genuinely useful, reusable idea even outside full adoption.
**Recommendation** — Try it as the default scaffold on the next new TypeScript project.

### 4. Datus Agent — 7.2/10
**Decision:** PROTOTYPE

**What it is** — A CLI-first data-engineering agent with a semantic layer ("Dosi") compiling one business-domain model into SQL for 13+ dialects across 21 database adapters. Exposes a REST/MCP API (`Datus-API`, `datus-mcp`) and chat surfaces (web, Slack, Feishu, VS Code).
**Why I should care** — Natural-language-to-SQL and giving an agent safe, schema-aware warehouse access both otherwise mean hand-building a text-to-SQL pipeline. This compiles to Postgres among its dialects and exposes the result over MCP, so any MCP-capable agent gets it without custom glue.
**What it could replace** — A hand-built text-to-SQL pipeline or schema-context layer for an LLM querying a database directly.
**Ways I could use it** — Natural-language-to-SQL against Postgres; MCP-exposed semantic layer for a coding agent instead of schema-blind raw SQL; one semantic model shared across CLI, Slack bot, and application code.
**Agent opportunity** — Native MCP server (`datus-mcp`); subagents/skills follow the agentskills.io convention; plugin framework for external integrations.
**Integration effort** — Medium — connecting a real data source and building out the semantic model is more involved than a drop-in tool.
**Maturity** — Emerging, pre-1.0 (v0.4.3). Created July 2025, real company behind it, 10 distinct contributors, 1,860 stars / 275 forks / 23 subscribers.
**License** — Apache-2.0 — note the GitHub API's automated field misreports this as NOASSERTION; the actual LICENSE file, read directly, is genuine Apache-2.0 text.
**Alternatives** — Canner/WrenAI (catalogued, broader governed text-to-SQL/GenBI); OtterMind/Chat2DB (narrower, no semantic layer).
**Why this one** — Fits the Postgres/data-engineering axis directly and ships the semantic layer over both CLI and MCP, not just a chat surface.
**Recommendation** — Hands-on trial against a real Postgres dataset before any production use; still pre-1.0.

## Small but High-Leverage Utility
**catnap** (`LippInc/catnap`) is a Claude Code mod that makes Claude compact its own conversation at a clean task boundary instead of wherever Claude Code's own auto-compact happens to fire mid-task. It works with three context-usage thresholds (a soft nudge at 50%, a stricter one at 60%, Claude Code's own auto-compact kept as a 70% backstop) and a `compact_now` tool Claude calls itself; a `session.compact` hook then substitutes Claude's own handoff note for the default summarization pass, so the agent picks back up from exactly where it left off rather than from a lossy auto-generated summary. It's genuinely well-engineered — thoughtful about failure modes (managed-settings environments where the hook gets blocked, subagents being excluded, the token cost of the nudge notes) — but it's four days old with four stars and a single contributor, so it's flagged here rather than formally catalogued. Worth knowing about if mid-task auto-compact has ever derailed a long Claude Code session, which it reliably does.
