# Open Source Radar — 2026-09-20
_Rotation slot 5 — self-hosted SaaS alternatives, productivity_

## Executive Summary
Slot 5's usual topic set (time tracking, invoicing, project management, habit tracking, personal finance, helpdesk) is currently in a heavy same-week hype wave — dozens of near-identical, near-zero-star repos across every one of those niches, a pattern this radar has now seen repeatedly for self-hosted PaaS and incident-management tools too. Underneath the noise, two genuinely distinct finds surfaced: Pad, a project-management tool built explicitly for the "agent starts every session blank" problem rather than bolted-on AI features on top of a Linear clone; and Kaneo, a mature, actively maintained, in-stack (TypeScript/React/Postgres) minimal self-hosted PM tool. LibreDesk and solidtime round out the self-hosted-SaaS-replacement theme with a credibly backed helpdesk and a modern time tracker, both directly applicable to the MSSP/PTaaS billing and support context. One suspicious-growth repo (edgeever) was caught and rejected on fork/star/subscriber ratios alone.

## Today's Best Discoveries

### 1. Pad — 8.3/10
**Decision:** PROTOTYPE

**What it is** — A single Go binary bundling a CLI, a local web UI, and a native AI-agent skill for project management, positioned explicitly as "Linear/Jira for the agent era."
**Why I should care** — Every fresh coding-agent session currently starts blank on project context; Pad gives the agent a place to read and write goals, decisions, and task state itself, with a real human-facing Kanban/list/table UI on top — not a REST API bolted onto a human-only tool.
**What it could replace** — Ad hoc `AGENTS.md`/`TODO.md` files, and the recurring "re-explain the project to the agent" tax at the start of every session.
**Ways I could use it** — Local task board for personal/client projects with CLI access from scripts; `/pad` skill installed into Claude Code/Cursor for direct agent read/write; wiki-linked specs and a Specify workflow before an agent starts building; multi-agent audit trail when running more than one coding agent against a project; Idea Canvas for early brainstorming.
**Agent opportunity** — This is itself an agent-automation product: ships a `.claude-plugin` directory and a distributable skill/plugin, with explicit support for 8 coding-agent tools (Claude Code, Cursor, Codex, Windsurf, OpenCode, GitHub Copilot, Amazon Q, JetBrains Junie).
**Integration effort** — Low. `brew install` or Docker; `pad init` handles setup end to end; no account or server required for local use.
**Maturity** — Emerging. Created 2026-03-26 (~6 months old), 181 stars, weekly releases (latest v0.16.0), single-maintainer-dominant (`xarmian`, 1,825 commits) with a few smaller contributors.
**License** — Apache-2.0. No commercial-use restrictions.
**Alternatives** — Beads (catalogued — Dolt-backed task graph, no human UI), ctx (catalogued — session-history recall, not forward task management), Linear/Jira/Notion (cloud PM with only third-party agent integrations).
**Why this one** — The agent-identity-attribution design (a clear precedence order for who made each write, human or which named agent) and the breadth of agent-tool support are more thought-through than the OpenClaw-specific `FlowBoard`, which covers similar ground but is packaged as a plugin tied to one platform.
**Recommendation** — Prototype against one real project already using a daily coding agent; verify the `/pad` skill gets used unprompted once the novelty wears off.

### 2. Kaneo — 7.9/10
**Decision:** USE NOW

**What it is** — A minimal, self-hosted project-management tool deliberately stripped of the notification and workflow sprawl of larger PM suites — TypeScript/React/Postgres, MIT.
**Why I should care** — It's in-stack (not a foreign ecosystem to adopt), mature, and a realistic replacement for a Linear/Jira subscription or a heavier self-hosted alternative like OpenProject.
**What it could replace** — Per-seat Linear/Jira/Asana cost, or the setup overhead of heavier self-hosted PM tools when the real need is just a clean Kanban board.
**Ways I could use it** — Self-hosted personal/team board for side projects and client work; reference implementation for a React+TS+Postgres admin dashboard; source of reusable board/task-list UI patterns for an internal admin panel.
**Agent opportunity** — Ships its own `skills/`, `AGENTS.md`, and `CLAUDE.md` at the repo root — native AI-coding-agent-skill support already exists in the project.
**Integration effort** — Low. Docker Compose, Helm charts for Kubernetes, or a companion `drim` CLI installer with automatic HTTPS and Postgres provisioning.
**Maturity** — Mature for its age. Created 2024-12-31, 9,136 stars, 802 forks (healthy ~9% ratio), near-daily pushes, latest release v2.25.0 (2026-09-17), real contributor spread beyond the maintainer.
**License** — MIT. No restrictions.
**Alternatives** — Plane, Vikunja, Focalboard, Huly; Taskosaur (rejected 2026-09-13 for BSL misrepresented as open source).
**Why this one** — Explicit minimalism as the differentiator against feature-heavy alternatives, plus a genuinely healthy multi-contributor project rather than a single-maintainer side project.
**Recommendation** — Install as a personal or small-team PM board before reaching for a heavier self-hosted alternative or paying for Linear/Jira seats.

### 3. LibreDesk — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted, single-binary omnichannel customer support desk (live chat + email, unified inbox, help center, SLA tracking, AI-assisted replies), Go + Vue, backed by Zerodha Tech.
**Why I should care** — The MSSP admin-portal SaaS and PTaaS partnership both plausibly need a client support inbox; this replaces Zendesk/Intercom's recurring per-seat cost with a self-hosted binary that ships webhooks and an HTTP/JSON API.
**What it could replace** — Zendesk/Intercom/Freshdesk subscription cost, or building a bespoke ticketing/chat-widget system from scratch.
**Ways I could use it** — Client support inbox for the MSSP portal handling both email and an embeddable live-chat widget; internal IT-style help desk; AI-assisted first-response drafting grounded in a self-hosted knowledge base.
**Agent opportunity** — Documented HTTP/JSON API and webhooks make it feasible to wire ticket creation/status into an existing agent pipeline; no MCP server exists yet, so that would need to be built.
**Integration effort** — Low for a hosted trial (Railway 1-click provisions Postgres + Redis automatically); Medium for full self-hosting.
**Maturity** — Established. Created 2024-05-12, 2,944 stars, 278 forks, latest release v2.8.0 (2026-08-22), backed by Zerodha Tech — a meaningfully stronger continuity signal than a typical solo project.
**License** — **AGPL-3.0, flagged loudly.** Fine for running your own support desk internally; would matter only if a modified version were exposed as a hosted service to third parties.
**Alternatives** — Chatwoot (mainstream, already known), Zendesk, Intercom, Freshdesk.
**Why this one** — Single-binary deployment with an embedded frontend is a meaningfully lower operational bar than Chatwoot's Rails + Sidekiq + Redis + Postgres stack.
**Recommendation** — Trial via Railway's one-click deploy against a real (even small) support inbox before committing to full self-hosting, given the AGPL terms.

### 4. solidtime — 7.3/10
**Decision:** PROTOTYPE

**What it is** — A modern self-hosted time-tracking app for freelancers and agencies: projects, tasks, clients, billable rates, multi-organization support, and direct import from Toggl/Clockify/CSV. Laravel + Vue, AGPL-3.0.
**Why I should care** — Billable time and client-rate tracking are a real recurring need for MSSP/PTaaS client engagements; direct import support from the two most common SaaS incumbents makes switching cost low.
**What it could replace** — A Toggl/Clockify/Timely subscription, or a spreadsheet tracking billable rates per client/project.
**Ways I could use it** — Track billable hours across client engagements with per-client billable rates; run multiple organizations if managing more than one client-facing stream; import existing Toggl/Clockify history.
**Agent opportunity** — None built in; a documented Laravel-based API could be scripted against for automated invoicing/reporting, but this is manual-integration work, not a ready agent capability.
**Integration effort** — Medium. Needs a standard Laravel stack (PHP, database, queue worker) — heavier to operate than a single binary, though used standalone rather than integrated at the code level.
**Maturity** — Established. Created 2024-01-16, 8,928 stars, 508 forks, latest release v0.20.1 (2026-09-16) — still pre-1.0 despite the age and star count.
**License** — **AGPL-3.0, flagged loudly.** Unaffected for internal/own-business use; matters only for hosted resale of a modified version.
**Alternatives** — Kimai (mainstream, long-established, not treated as a new discovery), Toggl, Clockify.
**Why this one** — A more modern UI/UX and multi-organization model versus Kimai's older, more enterprise-oriented interface — worth a side-by-side trial rather than taking either project's own framing at face value.
**Recommendation** — Trial against one real client engagement's time tracking before migrating fully off an existing tool, given the pre-1.0 version.

## Small but High-Leverage Utility
**GithubStarsManager** (`AmintaCCCP/GithubStarsManager`, MIT, 3,589 stars) is a local-first Electron desktop app that puts AI semantic search, auto-categorization, per-repo Q&A, an MCP server, and release tracking on top of a personal GitHub-stars collection. It's meta-relevant here: the exact problem it solves — a growing pile of discovered repos that becomes unsearchable and untriaged — is the same one this radar exists to manage, just for raw starred repos instead of a curated catalog. Filed as PROTOTYPE; worth pointing it at an existing star collection as a low-risk trial, and it's a plausible first-pass triage tool for radar-style discovery volume before something reaches deep review.
