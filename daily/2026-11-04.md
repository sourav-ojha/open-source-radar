# Open Source Radar — 2026-11-04
_Rotation slot 1 — AI agents, MCP, coding productivity_

## Executive Summary
Today's strongest thread is AI-agent trust and verification: Tracekit signs every tool call an agent makes into a tamper-evident, Certificate-Transparency-style hash chain, and Tracely turns an agent's actual production failures directly into CI regression tests with no hand-authored eval dataset — two different answers to "how do I actually trust what my agent did." A third find, earshot, is further afield but remarkable: it gives a coding agent the ability to hear, critique, and synthesize audio, documented with an unusual level of honest self-criticism about its own models' limits. A recurring theme worth naming explicitly: three of today's four catalogued finds carry an elevated stars-to-subscribers ratio (136:1 to 423:1) — the same signal this radar has used before to reject thinner repos — but each pairs it with real fork counts and active open issues, which the clear-cut fake-engagement cases rejected previously did not have. They were catalogued on substance with the ratio flagged, not treated as automatically disqualifying. Two rejections are worth remembering: a same-day "agent action authorization gateway" (decionis/agent-safe-pipeline) turned out to be a classic open-core trap whose open-source half "decides nothing itself," and a "connect agents to real iPhones" repo (phone-harness/mcp) turned out to be nothing but setup docs for a hosted SaaS connector — not deployable open source at all.

## Today's Best Discoveries

### 1. Tracekit — 8.0/10
**Decision:** PROTOTYPE

**What it is** — A tamper-evident audit trail for AI-agent tool calls: every call is policy-gated before it runs, then signed into an append-only hash chain modeled on Certificate Transparency, producing one `.tkb` file per run that anyone can verify offline.
**Why I should care** — An agent with shell/DB/API access can edit its own log after the fact; the project's own demo shows an agent deleting 43 of 128 orders, then editing both its log and a naive audit record to hide it. Tracekit's signed records fail verification the moment one is altered — directly relevant to the MSSP/PTaaS context, where a verifiable record of what an agent did against client systems is a real compliance artifact.
**What it could replace** — A hand-rolled "log everything the agent does" setup that trusts the agent's own process to keep an honest record.
**Ways I could use it** — wrap a Claude Code session with `tracekit init --dev` for a verifiable run record; retroactively audit existing session history with `tracekit audit --since 7d`; gate an agent's sandbox-escape retries behind a signed human approval; add the same guarantee to a LangChain/MCP-based internal tool; build an "auditable agent actions" feature for an MSSP admin portal on the open `.tkb` format.
**Agent opportunity** — Three-line integration (`pip install tracekit-ai`, `tracekit.instrument()`); stable support for Claude Code, OpenAI Agents SDK, LangChain/LangGraph, Claude Agent SDK, MCP; experimental support for a further ~18 frameworks and sandbox runtimes.
**Integration effort** — Low for local/dev use; Medium to get the production posture (signer isolated from the agent, with an independent witness) the security claims depend on.
**Maturity** — Emerging. 39 days old, PyPI package at v1.5.3, 407 stars/59 forks/3 subscribers, 50 open issues.
**License** — MIT, no restrictions.
**Alternatives** — Plain application logging (editable by the agent); OpenTelemetry tracing (observability, not tamper-evidence); decionis/AgentSafe (rejected today — see below).
**Why this one** — It's the first tool found applying Certificate-Transparency-style signed, witness-cosigned records specifically to agent tool-call logs, with an open file format and independent verifiers rather than asking you to trust its own viewer.
**Recommendation** — Wrap one real agent session with filesystem/DB/API access, deliberately try to make it hide an action, and confirm verification actually fails before relying on it for anything resembling a compliance claim.

### 2. earshot — 7.4/10
**Decision:** PROTOTYPE

**What it is** — Gives a coding agent hearing: a CLI, Python API and MCP server that describes what an audio file sounds like, scores how well it matches a text description, finds the best moment in a long recording, tells real recordings from code-synthesized ones, and critiques a video's sound design against professional launch films — plus a code-based sound-effect synthesizer the agent can iterate on by listening.
**Why I should care** — An agent that writes the code for a demo video or game still can't tell whether a hit lands on the cut or a UI click sounds cheap; earshot turns that into something an agent can reason about in text, closing a real gap for anyone shipping video/audio alongside a product.
**What it could replace** — Manually eyeballing spectrograms or re-listening to sound-effect iterations by hand; stock SFX licensing for simple UI sounds.
**Ways I could use it** — `earshot critique` as an automated scorecard on a product demo video before it ships; `earshot sfx`/`kit` to generate royalty-free UI sounds from code; a CI sanity check on generated/uploaded audio assets; the MCP server for an agent to iterate on a media asset directly.
**Agent opportunity** — Native MCP server keeping models loaded between calls; the forge/fit loop (generate, measure objectively, critique in words, repeat) is a reusable agent-iteration pattern beyond audio.
**Integration effort** — Medium: `git clone` + `pip install -e`, Python 3.10+ and ffmpeg on PATH, ~1.1GB of model downloads on first use; no PyPI package yet.
**Maturity** — Experimental. 20 days old, v0.4.0, single maintainer, 3,811 stars/243 forks/9 subscribers.
**License** — MIT, no restrictions.
**Alternatives** — Manual QA by ear (status quo); stock SFX libraries (licensing cost, no code-native iteration); an audio-LLM critique call (supported as an optional consent-gated path, not the default).
**Why this one** — Its own "Honest limits (Goodhart)" section candidly discloses that its search can satisfy its own models without the sound actually improving, and reports a disclosed blind test (8 of 15 correct, near chance) rather than claiming an unverified win — a level of self-criticism rarely seen in a 20-day-old repo.
**Recommendation** — Try it directly on one real demo video or a handful of UI sound effects to judge output quality firsthand before adopting it into any pipeline.

### 3. Tracely — 7.1/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted, trace-native CI/CD pipeline for AI agents: every production agent trace is graded as it lands, failures are clustered into issues, a failing run is frozen into a hermetic replayable regression case, and a PR that would reintroduce the same failure is blocked — with the production trace itself standing in for a hand-authored eval dataset.
**Why I should care** — Every agent-eval tool seen in this catalog so far asks for a hand-authored dataset that goes stale as the product changes. "The recorded run is the test" removes that authoring step entirely, if the clustering and replay hold up in practice.
**What it could replace** — Hand-authoring and maintaining an eval dataset for an LLM-agent feature; a custom "did this agent regress" CI gate built from scratch.
**Ways I could use it** — self-host the stack via the one-click Railway/Railyard template; instrument an agent with the `tracelyai-sdk` Python SDK over OTLP; use a frozen failure case as a CI gate so a fixed regression can't silently ship again.
**Agent opportunity** — PyPI SDK with automatic + manual tracing over OTLP; an agent-skill integration lets a coding agent query Tracely directly during development.
**Integration effort** — Medium: a five-service self-hosted stack (API, worker, UI, Postgres, ClickHouse, Redis, MinIO), though the one-click deploy template removes most manual setup.
**Maturity** — Experimental/pre-release. 24 days old, 1,214 stars/141 forks/3 subscribers, 21 open issues, no tagged GitHub release yet (PyPI SDK at 0.0.1).
**License** — MIT, no restrictions.
**Alternatives** — whatbroke (already catalogued — narrower before/after behavioral diffing, not a full trace-to-CI-gate pipeline); hand-authored eval suites; plain OpenTelemetry dashboards.
**Why this one** — The "production trace becomes the regression test" framing is a genuinely different, lower-authoring-effort workflow than every other agent-eval approach catalogued so far.
**Recommendation** — Stand up the Railway template against one real agent integration's traces and judge whether the automatic failure clustering produces regression cases worth keeping, before going further — the missing release tag argues for caution over immediate adoption.

## Small but High-Leverage Utility
**agentring** — a self-hosted MCP server, REST API, and Android app that lets a coding agent reach you by phone call (even on a locked device, bypassing Doze) with a voice AI that explains why it's calling and hands the transcript back, and lets you call your agents back by voice. Runs over your own VoIP server with no Twilio account or per-minute billing (a hosted option exists at agentring.io for anyone who doesn't want to run a server). The "run the migration and call me if anything fails" pattern is a genuinely different notification channel from the usual Slack-message-nobody-saw-in-time problem. Pre-release, tested so far on a single phone (Pixel 6, Android 16) per the project's own disclosure — worth trying personally on one real long-running job before depending on it for anything time-sensitive.
