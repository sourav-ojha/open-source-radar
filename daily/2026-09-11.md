# Open Source Radar — 2026-09-11
_Rotation slot 3 — developer utilities, debugging, testing_

## Executive Summary
Today's slot skewed toward the AI-agent-leverage axis more than the utility axis
itself: the strongest finds are a zero-config server-side HTTP inspector for
Node/Next.js, a tool that gives coding agents runtime verification of their own
changes instead of trusting a screenshot, a CPU-only code-search engine claiming
~99% fewer tokens than grep+read, and a Rust terminal database workbench with a
built-in MCP server. The "code search for agents" niche is clearly heating up —
dozens of near-identical entrants surfaced in one search pass, two of which
(Semble, zvec-grep) are genuinely differentiated and well-documented rather than
copy-paste clones. Also worth a callout: a tiny GPL-3.0 tool (ClAudit) that reads
your Claude Code session history, scrubs PII with an LLM, and auto-files public
GitHub issues on your behalf — interesting idea, but the "trust an LLM scrubber,
then post publicly" mechanism is a real privacy risk, so it's filed as rejected
rather than recommended.

## Today's Best Discoveries

### 1. netbridge — 8.2/10
**Decision:** USE NOW

**What it is** — a zero-config CLI that wraps `fetch` and `http`/`https` in every
Node process your dev command spawns (Next.js worker processes included) and
streams a live network-tab UI: headers, full bodies, timing, and the pid that
made the call.
**Why I should care** — server-side outbound HTTP calls in a Next.js/Express
backend are completely invisible to browser DevTools; every existing workaround
(the experimental Node inspection flag, OpenTelemetry, MITM proxies) is broken or
painful in a different way.
**What it could replace** — ad-hoc `console.log` debugging, and the
cert-juggling/TLS-downgrade dance of mitmproxy/Charles/Proxyman for this specific
use case.
**Ways I could use it** — debug a broken third-party API integration in a Server
Component; inspect Express/NestJS outbound calls during local dev; filter out
noisy OpenTelemetry exporter traffic while chasing a real bug; export a session
as HAR or copy a single request as curl/fetch for a bug report.
**Agent opportunity** — no MCP surface yet, but it can export a captured request
directly as an AI prompt for pasting into an agent session.
**Integration effort** — Low: `npx netbridge -- <dev command>`, no install, no
proxy, no certificates.
**Maturity** — Very early: created 2026-06-12, 3 stars, single maintainer, no
tagged GitHub releases (npm registry at v0.4.0 is the real source of truth).
**License** — MIT, no restrictions.
**Alternatives** — Browser DevTools (blind to server traffic), Node's
`--experimental-network-inspection` (doesn't reach Next.js worker processes),
OpenTelemetry (no bodies), MITM proxies (cert/TLS friction).
**Why this one** — it's the only approach that actually reaches instrumentation
into every child process a framework spawns, via `NODE_OPTIONS` environment
inheritance rather than a CLI flag.
**Recommendation** — install it today; the integration cost is one command and
the risk is zero since it never touches production.

### 2. Semble — 8.1/10
**Decision:** PROTOTYPE

**What it is** — a CPU-only, zero-dependency code search library/MCP server for
coding agents: indexes a repo in ~500ms, answers queries in ~1ms, and returns
only relevant snippets at a claimed ~99% fewer tokens than grep+read.
**Why I should care** — every large-repo agent session burns token budget on
exploratory grep loops; a genuine reduction on that specific cost is a direct,
measurable win on both spend and turnaround time.
**What it could replace** — the multi-tool grep-then-read exploration loop an
agent runs before it finds the relevant code.
**Ways I could use it** — MCP-server install for Claude Code/Cursor/Codex;
`semble search` from a script needing a fast answer without a full agent
session; scope out a candidate dependency by indexing its git URL before
cloning; `find-related` to jump to structurally similar code in an unfamiliar
repo.
**Agent opportunity** — ships as an MCP server, a CLI usable via AGENTS.md/
CLAUDE.md, and an installable dedicated sub-agent — this is agent infrastructure
by design.
**Integration effort** — Low: `uv tool install semble && semble install`, no API
keys, no GPU.
**Maturity** — Emerging but fast-growing: created 2026-04-06, already 6,049
stars, latest tag v0.5.6 (2026-09-05), only 3 open issues.
**License** — MIT, no restrictions.
**Alternatives** — zvec-ai/zvec-grep (Node.js/TS, fuses ripgrep+BM25+vector
search, also searches docs/structured data, 3,379 stars, Apache-2.0) is a
genuine direct competitor worth trying given a Node/TS-first stack; Semble was
picked as primary for its published, reproducible benchmarks and simpler
CPU-only model.
**Why this one** — a concrete, reproducible benchmark (NDCG@10 0.854, ~340x
faster indexing) rather than just a positioning claim.
**Recommendation** — install against one real large repo and compare token usage
directly against a normal grep+read agent loop before standardizing on it.

### 3. Reticle — 7.7/10
**Decision:** PROTOTYPE

**What it is** — a dev-only SDK + MCP server that lets a coding agent verify its
own change against the real running app (network calls, store, console, DOM)
and get back pass/fail/"couldn't tell" with the file:line to fix, instead of
trusting a screenshot or its own claim.
**Why I should care** — the most common agent-development failure mode is an
agent confidently reporting "done" over something that's actually broken;
Reticle targets that exact gap.
**What it could replace** — manually re-testing every agent-claimed "feature
complete" change by hand.
**Ways I could use it** — gate an agent's "done" claim on an actual verdict
after any agent-driven UI/full-stack change; instrument an Electron/Tauri app
during agent-driven development.
**Agent opportunity** — MCP server plus a Claude Code plugin and `/reticle`
slash command — directly wired into an existing agent workflow.
**Integration effort** — Medium: framework build-plugin install (Vite/Next.js/
Babel) plus MCP registration, though scripted via an auto-detect CLI path.
**Maturity** — Emerging: created 2026-06-11, 465 stars, latest tag v2.13.1
(2026-09-02); 100 open issues against 465 stars signals real rough edges.
**License** — **Split per package, flagged loudly.** The embeddable SDK
(`@reticlehq/core`/`browser`/`react`/`next`/build plugins) is Apache-2.0. The
actual verification server (`@reticlehq/server`, `@reticlehq/test`) is under the
Functional Source License 1.1 — free for internal/dev/eval use, restricted only
from being offered as a competing product, converting to Apache-2.0 two years
after each release. Enterprise features are additionally gated behind a paid
subscription for production use.
**Alternatives** — Playwright/browser-use agents (no structured store/network/
console evidence bundle the same way); Chrome DevTools MCP (protocol-level
inspection, no pass/fail verdict loop).
**Why this one** — nothing else in this space returns a typed pass/fail verdict
with a fix location across both web and desktop (Electron/Tauri) targets.
**Recommendation** — try it on one real agent-driven change to see whether the
verdict loop catches something a manual review would have missed. Worth noting:
the install instructions explicitly script the agent to ask the user to star the
repo after a successful run — a growth-hacking pattern baked into the tool
itself, not a dealbreaker but worth knowing before pasting the install prompt
verbatim.

### 4. narwhal — 7.6/10
**Decision:** PROTOTYPE

**What it is** — a single static Rust binary: a vim-mode terminal SQL editor
plus DBA-grade tooling (schema diff, audit log, capability-gated plugin sandbox,
ER diagrams, SSH tunnels, secret vault) plus a built-in MCP server, across
Postgres, MySQL, SQLite, DuckDB, ClickHouse, and SQL Server.
**Why I should care** — it collapses a terminal DB client and an agent-facing
database bridge into one binary with no proxy to maintain, for the Postgres side
of the work.
**What it could replace** — a separate GUI DB client (DBeaver/TablePlus) plus a
hand-rolled MCP database bridge.
**Ways I could use it** — day-to-day Postgres/MySQL work from the terminal;
`narwhal mcp --read-only` to let an agent explore schema and run queries
safely; generate a dialect-aware DDL diff before hand-writing a migration.
**Agent opportunity** — built-in MCP server over stdio with a documented
read-only mode and per-connection guards.
**Integration effort** — Low: single static binary via install script,
Homebrew, AUR, Nix, or `cargo install`.
**Maturity** — Emerging: created 2026-05-27, 43 stars, latest tag v2.3.0
(2026-06-09), 6 open issues, distributed through real package channels.
**License** — MIT OR Apache-2.0 (dual, standard Rust convention). GitHub's API
reports `NOASSERTION` because it doesn't parse the dual `LICENSE-MIT` +
`LICENSE-APACHE` file pair — confirmed genuine via the repo's file listing.
**Alternatives** — DBeaver/TablePlus/pgAdmin (GUI-first, no MCP surface);
already-catalogued LibreDB Studio (broader data-format support, also no MongoDB);
thorstenfoltz/octa (desktop app, 20+ formats, also ships an MCP server — closer
competitor, not independently reviewed this run).
**Why this one** — the MCP server plus read-only guard is the most direct
agent-database bridge found this run.
**Recommendation** — try it as the terminal Postgres client and agent MCP bridge,
with the clear caveat that it has no MongoDB support and so only covers part of
the stack.

## Small but High-Leverage Utility
**ctxdu** (richardysx/ctxdu) — `du(1)` for a coding agent's context window. It
reads the session transcripts Claude Code and Codex already write to disk and
gives an itemized breakdown of what's actually filling the context (CLAUDE.md,
memory index, skills listing, MCP server schemas) instead of just a percentage.
Single zero-dependency file, MIT, `--mcp --probe` even measures the real schema
cost of each configured MCP server by connecting to it directly — directly
useful for anyone regularly hitting compaction and wanting to know why. Very
new (0 stars, created 2026-09-09, not yet published to npm) and worth trying
directly from the cloned repo rather than treating it as a stable dependency
yet.

## Worth Watching
- **zvec-ai/zvec-grep** — Node.js/TS tool fusing ripgrep, BM25, and vector
  search for humans and agents (3,379 stars, Apache-2.0, npm-published). A
  legitimate direct alternative to Semble with a stack that matches a Node/
  TS-first environment better; not independently deep-reviewed since it competes
  directly with today's pick, but worth a hands-on trial.
- **morluto/flameox** — an MCP-native profiler that coordinates py-spy, Memray,
  Perfetto, OTLP, and torch profiler behind one bounded-evidence interface for
  coding agents (121 stars, MIT). Genuinely differentiated concept, but the
  managed-provider list is Python/ML-tooling-specific and the documentation is
  dense with unusual "authority model" jargon that made maturity hard to judge
  quickly — revisit once the docs settle or a non-Python provider appears.
- **rowhitswami/flakestat** — local CLI flaky-test detector across pytest,
  Jest, go test, and JUnit, no SaaS, no account (0 stars, created 2026-09-06).
  Solves a real, recurring pain point but is two days old at review time; would
  need actual usage history and at least one tagged release before trusting it.

## Rejected / Duplicate Candidates
- **sworrl/ClAudit** — reads local Claude Code session transcripts, scrubs PII
  with an LLM, and auto-files public GitHub issues against
  `anthropics/claude-code` for false-positive safety blocks. Interesting idea
  and GPL-3.0/FOSS, but the core mechanism — trust an LLM-based PII scrubber,
  then post the result publicly, continuously and automatically — is a real
  privacy risk for anything touching non-public code or client work, and its
  value is community advocacy rather than personal productivity.
- **Code-search-for-agents hype wave** (octocode, codesage, githits-cli,
  open-codebase-index, code-index-mcp, Argyph, file-scanner-mcp, and a dozen
  more, mostly surfaced in one search pass) — duplicate/hype wave; Semble and
  zvec-grep were the two genuinely differentiated, well-benchmarked entrants
  worth tracking, the rest showed no clear distinction from each other or from
  already-catalogued mex/ripwire.
- **Schema-diff wave** (foxschema, SqlSchemaDiff, ts-schema-diff,
  sqlite-schema-diff, and ~15 more, mostly 0-9 stars) — duplicate/immature;
  bikeshedder/tusker (18 stars, Apache-2.0, PostgreSQL-specific, created 2023)
  is the most mature single entry but still too small a community to recommend
  over hand-writing migrations for now.
- **API-testing-CLI wave** (quicpulse, multimeter, resterm-runner, tstr,
  apiwright, and ~10 more) — duplicate/immature; none showed clear
  differentiation from established tools (Postman, Bruno, Hurl) already assumed
  known.
- **Test-data-generator wave** (~25 near-identical repos, mostly 0 stars,
  created within days of each other) — duplicate/hype; no standout entry.
- **keploy/keploy** and **MCPJam/inspector** — both surfaced with real
  traction (18,453 and 2,195 stars respectively) but are already-established
  names in their spaces (API/E2E test generation from traffic; MCP server
  testing/debugging, overlapping with already-catalogued mcpsnoop); no material
  new development flagged this run to justify a fresh write-up.
