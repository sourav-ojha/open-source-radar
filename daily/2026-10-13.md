# Open Source Radar — 2026-10-13
_Rotation slot 7 — experimental projects and hidden gems_

## Executive Summary
Today's strongest find sits at the intersection of two things I care about directly: coding-agent tooling and security. nono is a zero-setup sandbox for running agents like Claude Code with least-privilege filesystem/network/credential policies, built by the team behind Sigstore and carrying real production validation rather than just a pitch. Around it, a genuinely useful but very young cluster: a self-hosted PDF accessibility checker with an unusually rigorous benchmark, a self-hosted merge gate that quizzes PR authors on their own (possibly AI-written) diffs instead of reviewing the code, and a personal-AI-agent access broker. The GitHub search layer for "agent sandbox" and "agent memory" today also surfaced a huge same-day wave of near-identical, low-traction repos — a reminder that this specific niche is now trend-chasing territory, and nono's production validation is what separates it from the pack rather than the category itself.

## Today's Best Discoveries

### 1. nono — 8.6/10
**Decision:** USE NOW

**What it is** — A zero-setup, zero-latency sandbox for running coding agents (Claude Code, Codex, Cursor-style CLIs, OpenCode, Hermes, Copilot, OpenClaw) with least-privilege filesystem, network, and credential policies. No daemon, container, or VM — process-level sandboxing on macOS, Linux, and Windows (WSL2).
**Why I should care** — I run agents against real repos with real credentials daily; nono scopes exactly what an agent session (and, separately, each tool it shells out to) can touch.
**What it could replace** — Hand-rolled wrapper scripts or trusting an agent's own judgment about what it should touch; a from-scratch least-privilege sandbox would be weeks of security engineering.
**Ways I could use it** — Run Claude Code/Codex scoped to a task; proxy a GitHub token through its credential proxy so `gh`/`git` only get filtered API access, not a raw env var; pull reviewed policy profiles from its registry instead of writing my own; nest tighter sandboxes around delegated tools so an agent's broad grants don't flow down to everything it calls.
**Agent opportunity** — Purpose-built for wrapping coding-agent CLIs directly; FFI bindings (Rust/Python/TypeScript/Go) mean the policy engine is embeddable inside a custom orchestrator; ships a GitHub Action (agent-sign) for commit signing.
**Integration effort** — Low: one install command (curl/Homebrew/Nix), policies pulled from a public registry.
**Maturity** — Emerging (pre-1.0, README notes API churn still possible), but with an OpenSSF Best Practices badge and a working CI pipeline.
**License** — Apache-2.0, no commercial restrictions.
**Alternatives** — AgentVM/DeepClause (catalogued, WATCH) is WASM-based and less mature; AgentKernel (catalogued, PROTOTYPE) uses microVMs for stronger but heavier isolation; Pikopod (catalogued) solves a different problem entirely (API-failure simulation).
**Why this one** — Built by maintainers associated with Sigstore (the supply-chain attestation standard behind PyPI/npm/Homebrew/Maven Central), and its nested per-tool command sandboxing — a delegated tool does not inherit the parent session's broad grants unless its own policy says so — is a meaningfully more careful model than the flat single-policy approach most competitors in this space ship.
**Recommendation** — Install and try it against a real agent session this week; the main open question is pre-1.0 API stability, not the security model.

### 2. outloud — 8.1/10
**Decision:** USE NOW

**What it is** — A zero-dependency PDF accessibility checker (PDF/UA-1 + WCAG 2.2) that runs in the terminal, CI, or a local browser app, with 35 semantic rules beyond what key-existence validators like veraPDF and PAC check.
**Why I should care** — Any product that generates or accepts PDFs and sells into enterprise/government customers eventually hits an accessibility compliance requirement; this is an install-and-run way to check before it becomes a procurement blocker.
**What it could replace** — PAC (Windows-only, proprietary) or a slow JVM-based veraPDF run; building semantic accessibility rules from scratch is a multi-week correctness project.
**Ways I could use it** — CI gate on generated invoices/reports; one-off terminal check before a client deliverable; SARIF output wired into GitHub code scanning; compare a remediated PDF against its original to confirm nothing was lost.
**Agent opportunity** — Usable directly as a Python library inside an automated document-QA pipeline; SARIF output with a one-line fix per finding is a natural fit for a coding-agent CI loop.
**Integration effort** — Low: `pipx install outloud`, no runtime dependencies beyond Python 3.10+.
**Maturity** — Emerging — first PyPI release six days before this review, repo under a month old.
**License** — Apache-2.0, no commercial restrictions.
**Alternatives** — PAC (closest feature match, Windows-only); veraPDF (JVM, reference conformance validator, outloud is calibrated to match it 160/160 on its own test set but faster); pdfa11y (faster still, but misses most of outloud's semantic-layer findings per the maintainer's own comparison doc).
**Why this one** — An unusually rigorous, dated, reproducible benchmark for a two-week-old project, plus an explicit "what it is not" section disclaiming certification/legal-advice status — more intellectual honesty than most tools this young bother with.
**Recommendation** — Install it; negligible adoption cost for a narrow, well-tested tool.

### 3. vibecheck — 7.1/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted GitHub merge gate that tests whether a PR's author understands their own change before it can merge, by generating questions from the diff and LLM-grading the author's plain-English answers — rather than reviewing the code itself.
**Why I should care** — As more code ships from coding agents, the bottleneck shifts from writing code to someone actually understanding it before it merges; this targets that exact failure mode instead of being another AI code reviewer.
**What it could replace** — Nothing directly — it's a new check layered onto existing review, aimed at the "LGTM, CI green" rubber-stamp problem specifically.
**Ways I could use it** — Add it as a branch-protection check on a repo with heavy AI-assisted contribution; run it on my own PRs to confirm I actually understood what my agent produced; use it as a cheap filter for drive-by AI-generated PRs on an open-source project.
**Agent opportunity** — The diff-to-exam-sheet-to-blind-grading pattern is reusable for verifying human comprehension of any AI-generated artifact, not just code.
**Integration effort** — Medium: self-host Docker + Postgres, BYOK Anthropic key, one workflow file, a branch-protection rule.
**Maturity** — Experimental — about one month old, 5 stars, solo maintainer.
**License** — MIT, no commercial restrictions.
**Alternatives** — roborev (catalogued) reviews the code itself and feeds findings back into the agent session; generic AI PR-review bots optimize for finding bugs, not verifying author comprehension — vibecheck's angle is genuinely distinct.
**Why this one** — Two live demo PRs linked in its own repo (one passing, one failing) are unusually concrete proof the mechanism works, for a project this size.
**Recommendation** — Worth a trial on a side project or low-stakes repo before trusting it anywhere business-critical.

### 4. Personal Agent Proxy — 6.9/10
**Decision:** PROTOTYPE

**What it is** — A self-hostable access-control and audit layer for personal AI agents (Claude, ChatGPT, Grok, etc.): connect personal services once, grant each agent granular revocable permissions, and get an audit log, without copying the underlying service's data into the agent vendor's own database.
**Why I should care** — As personal AI agents from multiple vendors each want access to email/calendar/etc., a single self-hosted permission broker in front of all of them beats granting each vendor's agent its own direct OAuth access.
**What it could replace** — Ad hoc, per-vendor OAuth grants with no unified audit trail.
**Ways I could use it** — Scope a personal assistant agent to one connected service without exposing the whole account; audit what an agent actually did across connected services; run multiple agents against the same accounts with independently revocable permissions.
**Agent opportunity** — Explicitly agent-agnostic middleware, positioned to sit in front of whichever agent product a user chooses.
**Integration effort** — Medium: self-hosting the Bun/TypeScript monorepo plus Postgres; permission/connection mechanics are not documented outside the hosted docs site.
**Maturity** — Experimental — 7 days old, 95 stars (fast growth), 2 contributors, no tagged releases yet.
**License** — MIT, no commercial restrictions.
**Alternatives** — Stashbase CLI (catalogued, PROTOTYPE) is narrower — a secrets/egress proxy specifically for coding agents, not a general personal-service permission broker.
**Why this one** — Confirmed as a real, substantial codebase (dashboard, docs, Postgres package, Docker/Render deploy) rather than a landing-page repo, which is not true of most same-shape projects surfacing in this niche right now.
**Recommendation** — Watch and maybe test with a throwaway connection; not yet ready to trust with real account access given its age and undocumented internals.

## Small but High-Leverage Utility
**outloud** (full writeup above, also counted among today's best discoveries) earns a second mention here specifically as a utility: `pipx install outloud && outloud report.pdf` is a two-second accessibility check that replaces either a Windows-only GUI tool or a slow JVM validator, with no upload and nothing leaving the machine. For any product that ships PDFs to end users, this is cheap insurance against an accessibility complaint or a failed procurement checklist.

## Worth Watching
- **Capsule** (capsulerun/runtime, Apache-2.0, 300★) — a WASM runtime that sandboxes individual Python/TypeScript functions as resource-limited tasks via a `@task` decorator. Narrower than nono (function-level, not full agent-session sandboxing) and solo-maintained; would become interesting if it grows a multi-contributor base or demonstrates real production use beyond its own docs.
- **chkit** (obsessiondb/chkit, MIT, 37★) — a Drizzle-style schema/migration/backfill CLI for ClickHouse. Off my core Postgres/Mongo stack today, but worth a second look if a ClickHouse-backed analytics need ever comes up.
- **vne** (pro-vi/vne, MIT, 0★) — a tiny CLI letting a coding agent work with `.env` files it's blocked from reading directly (finds keys, checks what's missing, runs commands with them loaded). Genuinely clever narrow idea; too early (0 stars, 9 days old) to trust yet, but worth a revisit if it gets any independent traction.
