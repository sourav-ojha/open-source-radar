# Open Source Radar — 2026-11-11
_Rotation slot 1 — AI agents, MCP, coding productivity_

## Executive Summary
Today's slot-1 sweep turned up three themes: LLM-judge/agent-evaluation frameworks are
maturing past raw "LLM-as-judge" prompts into validated grader libraries with published
benchmarks (OpenJudge); cost-conscious terminal coding agents are now engineering
prompt-cache discipline directly into the agent loop rather than relying on a gateway
layer (Dao Code); and established security vendors (Cisco, Snyk) are now shipping
dedicated MCP-server security scanners, with Cisco's multi-engine entrant clearing the
bar over an already-crowded wave of indie scanners. Two previously catalogued agent-
infrastructure tools — Tracekit and LoongSuite Pilot — both shipped real new capability
rather than routine patches, and are logged as Meaningful Updates.

## Today's Best Discoveries

### 1. MCP Scanner (Cisco AI Defense) — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A multi-engine security scanner for MCP servers and tools, combining
YARA rules, LLM-based behavioral analysis, Cisco's hosted inspection API, pip-audit CVE
scanning, VirusTotal binary-hash lookups, and sandboxed PyPI package execution in one
CLI/REST API/SDK.
**Why I should care** — This is the broadest MCP-server scanner evaluated here so far:
static + behavioral + dependency + binary-malware checks in one place, from a vendor with
an ongoing incentive to keep detection rules current.
**What it could replace** — Manual audit of a third-party MCP server's tools, prompts,
dependencies, and bundled binaries before trusting it.
**Ways I could use it** — Vet a third-party MCP server before adding it to an agent's
toolset; run pip-audit CVE scanning on an MCP server's dependencies in CI; catch missing
timeout/retry handling in an internal MCP server; scan bundled binaries against
VirusTotal hashes; build an MSSP-portal "scan this MCP server" feature on top of the
CLI's JSON output.
**Agent opportunity** — CLI + REST API + Python SDK; pairs with OpenJudge's Skill Graders
and the catalogued SkillSpector as independent, overlapping trust checks.
**Integration effort** — Medium. `pip install cisco-ai-mcp-scanner`; core engines are
fully self-hosted, two optional engines call hosted third-party services.
**Maturity** — Emerging-to-established (14 months old, 1,116 stars, active release
cadence, current tag 4.8.7).
**License** — Apache-2.0 for the core engines; no restrictions.
**Alternatives** — SkillSpector (catalogued, targets Agent Skills not general MCP
servers); Snyk Agent Scan (free CLI explicitly unstable, nudges to Snyk's paid Evo
platform); mcp-watch, Mcpwn (single-engine, narrower).
**Why this one** — Multi-engine design is genuinely broader than any single-technique
scanner catalogued to date.
**Recommendation** — Run it against any third-party MCP server before adopting it; cross-
check findings against SkillSpector on the same target.

### 2. OpenJudge — 7.6/10
**Decision:** PROTOTYPE

**What it is** — Alibaba AgentScope's open-source evaluation framework for AI agents: 50+
validated graders (general quality, agent trajectory/tool-selection/memory/plan,
multimodal) plus an Agent-Skill security-grader taxonomy, with a Streamlit UI and public
benchmarks (PawBench, Reference Hallucination Arena).
**Why I should care** — LLM-as-judge is easy to prototype and easy to get subtly wrong.
OpenJudge packages graders for the dimensions that matter for agents specifically and
publishes benchmarks showing they correlate with ground truth, rather than asserting it.
**What it could replace** — Hand-rolled LLM-as-judge prompts and ad hoc eval scripts for
agent QA.
**Ways I could use it** — Grade agent trajectories/tool-selection/memory before shipping
an internal agent; run a Skill Grader pass over Claude/Codex Agent Skills as a second
opinion alongside a dedicated security scanner; score RAG/chatbot output quality without
hand-writing eval prompts; benchmark models/harnesses on a custom task set.
**Agent opportunity** — Python SDK/CLI; Skill Graders complement today's MCP Scanner and
the catalogued SkillSpector on Agent Skill vetting.
**Integration effort** — Low. `pip install py-openjudge`, library not infrastructure.
**Maturity** — Emerging (~8 months old, weekly releases, v0.2.5).
**License** — Apache-2.0; no restrictions.
**Alternatives** — promptfoo / DeepEval / RAGAS (general LLM eval, less agent-specific);
hand-written LLM-as-judge prompts (status quo).
**Why this one** — Agent-trajectory/tool-selection/memory graders plus a benchmark suite
proving the graders work, not just asserting it.
**Recommendation** — Try its graders against a real internal agent's trajectories and
compare the verdicts to manual review before relying on it as a gate.

### 3. Dao Code — 7.1/10
**Decision:** STUDY

**What it is** — An open-source TypeScript terminal coding agent engineered around
DeepSeek V4's cache pricing: byte-stable prompt prefixes and cache-reusing session forks
make cross-session memory and a continuous self-correction layer cost almost nothing in
tokens.
**Why I should care** — Most agent cost-reduction tools work at a gateway/proxy layer;
this bakes cache-reuse discipline into the agent's own prompt construction — a different,
more durable lever, and one worth studying independent of DeepSeek itself.
**What it could replace** — Nothing directly adoptable for a Claude/Codex-centric
workflow, but the architecture pattern is reusable.
**Ways I could use it** — Study the byte-stable-prefix + cache-reusing-fork technique for
a self-built agent harness; run it against DeepSeek V4 for cheap exploratory work; use it
as a price-performance comparison point against Claude Code/Codex.
**Agent opportunity** — MCP/Skills/Hooks support, Claude Code config compatible.
**Integration effort** — Medium — value depends on actually running DeepSeek as the
backing model.
**Maturity** — Emerging (786 stars, MIT, CI in place; no tagged release since v0.4.7 on
2026-07-18 despite commits through 2026-10-28).
**License** — MIT; no restrictions.
**Alternatives** — Claude Code / Codex / Cursor (mainstream, pricier); GLM Coding Plan
(scarce quota); Chronos and other DST-style tools (catalogued, different focus).
**Why this one** — The cache-reuse-by-design architecture, not the DeepSeek-specific
framing, is the transferable idea.
**Recommendation** — Read the prompt-construction code for the byte-stable-prefix
technique; don't adopt the tool itself unless already using DeepSeek.

## Meaningful Updates

**Tracekit** — PROTOTYPE 8.0 -> 8.2/10. v1.5.3 -> v1.6.0: new hooks for Kilo Code and
Qwen Code (Windows/PowerShell), plus experimental Devin CLI/Desktop support; new policy
TK-A055 blocks destructive database drop/reset commands and TK-F009/F015 flag
PowerShell-profile writes as harness-setting changes; added "model receipts" verifying
weights files written during a call; Go verifier reaches parity with the Python/
TypeScript verifiers. This is real new policy enforcement and agent coverage, not routine
patching. Catalog updated: Yes.

**LoongSuite Pilot** — PROTOTYPE 8.2 -> 8.4/10. v1.6.0 -> v1.16.0 (157 -> 250 stars). Most
notable: a local Agent Interceptor (v1.11.0) that redacts API keys, cloud AccessKeys,
private keys, and database URLs from agent tool-call input/output before it leaves the
machine — directly relevant to the MSSP/PTaaS client-data context. Also added GitHub
Copilot CLI, Doubao Workspace, and a Qoder AgentLoop plugin as new agent integrations.
Catalog updated: Yes.

## Small but High-Leverage Utility
**modelplan** (MIT, 41 stars) answers a narrow, concrete question that comes up every
time a coding-agent task starts: which model, at which reasoning effort, is actually worth
the extra cost for this kind of task? It ships live, checkable public benchmark data
(cost-per-task and ability deltas per effort step) as a CLI/Skill/plugin inside Claude
Code, Codex, and the terminal, and calls out when a pricier effort setting buys nothing.
For anyone paying per-token across several coding-agent subscriptions, that's a direct,
recurring cost decision made with data instead of habit.
