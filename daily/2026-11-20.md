# Open Source Radar — 2026-11-20
_Rotation slot 3 — developer utilities, debugging, testing_

## Executive Summary
Today's standout came from a `topic:terminal-multiplexer` search rather than a
debugging-specific one: herdr, a single-binary Rust runtime purpose-built for coding
agents, sitting at 51,963 stars and 8 months old with no prior entry in this catalog —
the gap itself is notable given the scale. The same search exposed a genuinely crowded
2026 wave of "terminal for AI agents" projects, including a second huge entrant
(manaflow-ai/cmux, 28,840 stars) held out on a macOS-only platform mismatch. Elsewhere,
a deterministic NestJS static analyzer built explicitly to catch AI-agent mistakes and a
mature multi-protocol NoSQL desktop client rounded out a stack-relevant day.

## Today's Best Discoveries

### 1. herdr — 9.0/10
**Decision:** USE NOW

**What it is** — A single Rust binary that acts as the runtime coding agents live in:
it keeps agent terminals running in a background server across client detach, SSH
drops, and (with opt-in agent-recovery) a server restart; unifies local and saved SSH
machines in one window; marks every pane working/blocked/idle; and exposes a CLI/socket
API so agents can spawn panes and prompt each other. It runs Claude Code, Codex, Cursor,
OpenCode, and others unmodified rather than wrapping them.
**Why I should care** — This radar itself runs as a long, unattended agent session —
exactly the workload herdr targets. A dropped SSH connection or closed laptop killing an
in-progress agent run is a real, recurring failure mode this removes outright.
**What it could replace** — A hand-rolled tmux/screen setup plus custom scripting to
track which of several parallel agent panes is stuck waiting on input.
**Ways I could use it** — Detach from a long Claude Code session and reattach later from
a different machine; drive agents on several remote hosts from one window; spot a
blocked agent pane at a glance across a fleet of parallel runs; let one agent spawn and
prompt another via the socket API; extend it with marketplace plugins instead of
building custom tooling.
**Agent opportunity** — This is agent infrastructure by design: a CLI/socket API meant
for agents to drive directly, plus a documented path for adding herdr support to a new
agent harness.
**Integration effort** — Low: one binary via `curl | sh`, Homebrew, or mise; no external
server dependency. Windows support is explicitly beta.
**Maturity** — Emerging but battle-tested: created 2026-03-27 (~8 months), 51,963
stars, 4,206 forks, 117 subscribers, 528 open issues — real engagement at real scale.
Latest tagged release v0.9.5 (2026-10-14), pre-1.0.
**License** — Apache-2.0, no restrictions.
**Alternatives** — manaflow-ai/cmux (28.8k stars, comparable ambition, but Ghostty-based
and macOS-only); tmux/screen (persistent but not agent-aware); a wave of much smaller
2026 entrants (frankenterm, wmux, cornercase-terminal, orchbee, ThinkTerm, horizon).
**Why this one** — Cross-platform, agent-native by design (not a terminal emulator with
agents bolted on), and the only entrant in this niche with a real third-party plugin
marketplace already formed around it in under a year.
**Recommendation** — Install it and run one real multi-day Claude Code session through
it before relying on it for anything important.

### 2. nestjs-doctor — 8.4/10
**Decision:** USE NOW

**What it is** — A deterministic, non-LLM static analysis tool for NestJS. It reads
every `@Module()`, provider, HTTP endpoint, and ORM entity from source and scores the
project 0–100 across ~52 security/correctness/architecture/performance/schema rules,
explicitly positioned to catch mistakes an AI coding agent introduces — scans are
reproducible, so the same code scores the same regardless of which model wrote it.
**Why I should care** — NestJS is part of his core stack, and the workflow is
AI-agent-heavy. This is a cheap, deterministic backstop for exactly the failure mode
that creates: a missing guard, `synchronize: true` left on, a fire-and-forget promise.
**What it could replace** — Hand-built NestJS-specific ESLint rules for the same
checks, and manual line-by-line review of an agent's NestJS output for this class of
mistake.
**Ways I could use it** — Install the agent skill so a scan reruns automatically after
every agent edit; gate CI on only the findings a PR introduces via the included GitHub
Action; use the HTML report's module graph and ORM ER diagram when onboarding onto an
unfamiliar service; author project-specific rules via the included rule-creation skill.
**Agent opportunity** — First-class skills for Claude Code, Cursor, Codex, OpenCode,
Windsurf, and Gemini CLI, designed to run unprompted right after an agent writes NestJS
code.
**Integration effort** — Low: `npx nestjs-doctor@latest .`, no install required.
**Maturity** — Emerging: created 2026-02-18 (~9 months), active npm/VS Code
distribution. 185 stars, 4 subscribers, 7 forks on GitHub — thin community signal there,
though the npm/VS Code presence suggests real usage beyond star-watching.
**License** — MIT, no restrictions.
**Alternatives** — NestLens (already catalogued — runtime monitoring, a different layer
entirely); SonarQube (heavier, not NestJS-aware); hand-rolled ESLint rules.
**Why this one** — Complements rather than duplicates NestLens: static source analysis
versus runtime observation, both legitimately useful on the same NestJS service.
**Recommendation** — Run it against one existing NestJS service and read the findings
before deciding whether to install the agent skill or wire it into CI.

### 3. DocKit — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A native desktop GUI (Tauri/Rust) unifying Elasticsearch, OpenSearch,
DynamoDB, MongoDB, and EasySearch in one app, with a Monaco query editor and optional
bring-your-own-key natural-language-to-query assistance. Its own README frames it as a
replacement for Kibana and the AWS Console.
**Why I should care** — Covers MongoDB (core stack) and Elasticsearch/OpenSearch
(AWS-adjacent infra) in one native app, with DynamoDB coverage as a bonus — real
reduction in context-switching for ad hoc database debugging.
**What it could replace** — A separate Compass window, a Kibana/OpenSearch Dashboards
browser tab, and an AWS Console tab for a quick DynamoDB lookup.
**Ways I could use it** — Browse Mongo collections or ES/OpenSearch indices without a
browser tab; generate ad hoc queries from natural language, editable before running;
check a DynamoDB table without opening the AWS Console.
**Agent opportunity** — A companion MCP server (geek-fun/data-studio) is listed on the
MCP Toplist registry, though its feature parity with the desktop app wasn't
independently verified this run.
**Integration effort** — Low: desktop app install, no server component.
**Maturity** — Mature for this niche: created 2023-07-22 (3+ years), 1,145 stars, 72
subscribers, 122 forks — a healthy ~16:1 star-to-subscriber ratio.
**License** — Apache-2.0, no restrictions.
**Alternatives** — MongoDB Compass (Mongo-only); Kibana/OpenSearch Dashboards (need the
full stack running); AWS NoSQL Workbench (DynamoDB-only); mqlens-mongodb (newer,
thinner, Mongo-only desktop alternative seen the same day).
**Why this one** — The only multi-protocol entrant in today's crowded native-DB-client
wave with real multi-year engagement rather than a few weeks of fresh stars.
**Recommendation** — Point it at one existing MongoDB or Elasticsearch/OpenSearch
deployment and see whether it actually replaces the tab-switching in practice.

## Small but High-Leverage Utility
**mq** — a jq-like query language and CLI for Markdown, written in Rust, with a REPL, an
experimental step debugger, an LSP/VS Code extension, and a Docker image. Narrow but
genuinely useful: pulling structured content out of or into Markdown from a shell
pipeline or CI script, including LLM prompt/output processing, without fragile
regex/sed scripting. MIT, single-maintainer, explicitly "under active development" so
syntax may still shift.
