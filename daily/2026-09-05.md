# Open Source Radar — 2026-09-05
_Rotation slot 4 — data, search, documents, RAG_

## Executive Summary
Today's document/RAG-focused slot surfaced a genuinely strong batch: a mature local-first
agentic RAG library with a production-grade ingester (haiku.rag), a well-executed
self-hosted NotebookLM clone that's most of the way to a shippable research-notebook
product (OpenNotebookLM), a very new but seriously engineered embedded vector database with
real benchmarks and drop-in adapters for LangChain/LlamaIndex/mem0 (LodeDB), and a genuine
hidden gem — a three-star local semantic-search daemon built specifically for a Claude
Code-heavy workflow (Quarry). The GitHub search surface for "RAG"/"vector database" was
otherwise dominated by AI-slop reskins of the same idea and a wave of auto-generated
"independent API profile" repos from a single org (api-evangelist) — both filtered out
below.

## Today's Best Discoveries

### 1. haiku.rag — 8.3/10
**Decision:** PROTOTYPE

**What it is** — Local-first agentic RAG library/CLI/MCP server: hybrid vector+full-text
search with reciprocal rank fusion, multimodal embeddings, reranking, vision QA, and a
production ingester service, all on an embedded LanceDB with no server required.
**Why I should care** — It's one of the few local-RAG projects that goes past the
ingest-and-ask demo: a persistent-queue ingester with retries and a dead-letter queue, an
MCP server for direct use from Claude Desktop/Claude Code, and Docling-based chunking that
preserves page numbers and section headings for real citations.
**What it could replace** — Hand-rolling hybrid search, cross-modal embeddings, and a
document-intake pipeline separately.
**Ways I could use it** — Citation-backed Q&A over internal docs; MCP server exposed
directly to Claude Code; the production ingester as the intake layer for a document
pipeline needing retries and a dead-letter queue; the sandboxed "analyze" capability for
cross-document aggregation questions.
**Agent opportunity** — Ships an MCP server out of the box (`haiku-rag mcp --stdio`).
**Integration effort** — Medium — Python-only (`pip install haiku.rag`), needs an embedding
provider configured; fits a Node/TS stack via subprocess, MCP, or REST rather than natively.
**Maturity** — Mature — active since October 2024, 588 stars, 11 contributors, CI + docs
site.
**License** — MIT, no restrictions.
**Alternatives** — LlamaIndex/LangChain hand-rolled RAG stacks, Danswer/Onyx, txtai,
OpenNotebookLM (below — webapp-first vs. this library/CLI-first design).
**Why this one** — Genuinely production-shaped ingester component (persistent queue, dead
letter queue, FastAPI control plane), not just a retrieval demo.
**Recommendation** — Prototype as an MCP-exposed document knowledge base.

### 2. OpenNotebookLM — 8.2/10
**Decision:** PROTOTYPE

**What it is** — Self-hosted alternative to Google's NotebookLM: import PDFs, web pages,
and YouTube transcripts; get cited answers back to the source. Next.js frontend + FastAPI
backend, local SQLite, hybrid dense+BM25 retrieval, any LLM provider or none (extractive
fallback).
**Why I should care** — It's most of the scaffolding for a small research/notebook SaaS
already built and Dockerized: non-enumerable per-account isolation, hybrid retrieval, and
four "Studio" output generators (Markdown report, audio summary, mind map, narrated
slideshow) from the same project summary.
**What it could replace** — Building a citation-backed document Q&A tool with auth and
multi-format export from scratch.
**Ways I could use it** — Personal/team knowledge base with cited Q&A; confidential-document
research on a self-hosted machine; fork-and-reskin base for a small paid research product;
auto-generated onboarding briefings (mind map + narrated slideshow).
**Agent opportunity** — No MCP server yet, but the FastAPI backend (docs at `/docs`) is a
clean surface to wrap as one or call directly from a coding agent.
**Integration effort** — Low — `docker compose up -d --build` after setting
`JWT_SECRET_KEY`; deliberately fails fast if misconfigured.
**Maturity** — Emerging — created 2025-08-11, one tagged release (v0.1.0, 2026-08-25), 243
commits, but all from a single contributor.
**License** — MIT, no restrictions.
**Alternatives** — Google NotebookLM (closed), Khoj, Quivr, Danswer/Onyx, haiku.rag (above).
**Why this one** — The auth and data-migration care (404-not-403 to prevent ID
enumeration, documented cross-version migration steps) suggests it could survive contact
with a real second user, unlike most single-dev clones.
**Recommendation** — Stand up locally to evaluate as a personal research tool or product
starting point; don't rely on it for anything important yet given the single-maintainer
risk.

### 3. LodeDB — 7.9/10
**Decision:** PROTOTYPE

**What it is** — Embedded, on-disk vector database (Rust core, Python package) positioned
as a drop-in durable backend for LangChain, LlamaIndex, and mem0, with GPU-resident batched
search, incremental persistence, multimodal indexing, and Swift/iOS bindings.
**Why I should care** — Its own benchmark table claims an order-of-magnitude-plus win on
durable writes and single-query latency over sqlite-vec and qdrant specifically, plus
drop-in adapters for frameworks likely already in an AI stack.
**What it could replace** — Standing up a separate vector DB service (Qdrant/Milvus) for a
self-hosted semantic-search or agent-memory feature.
**Ways I could use it** — Swap-in vector store behind an existing LangChain/LlamaIndex/mem0
integration; local agent-memory backend via its MCP server
(`lodedb mcp install --client claude-code`); GPU-resident batched search; `lodedb migrate`
to move an existing pgvector/Qdrant store onto a local file.
**Agent opportunity** — MCP server ships specifically for coding-assistant memory, with
one-line install for Claude Code, Claude Desktop, Cursor, Codex, LM Studio.
**Integration effort** — Low — `pip install "lodedb[embeddings]"`, prebuilt wheels for
Linux/macOS/Windows, nothing to compile.
**Maturity** — Emerging — created 2026-06-14 (~3 months old), 98 stars, 2 contributors,
company-backed (Egoist Machines, Inc.).
**License** — Apache-2.0 core, unrestricted commercially; separate paid Enterprise tier for
support/BYOC is optional.
**Alternatives** — sqlite-vec, LanceDB, Qdrant, pgvector, Chroma, Milvus.
**Why this one** — Real benchmark methodology (published, reproducible scripts) rather than
a bare speed claim, plus adapters that make swapping it in low-effort.
**Recommendation** — Hands-on latency/footprint test against whatever currently backs any
LangChain/LlamaIndex/mem0 usage; treat the vendor's benchmark numbers as a hypothesis, not
a verified fact, until tested independently.

### 4. Quarry (punt-quarry) — 7.8/10
**Decision:** USE NOW

**What it is** — A local semantic-search daemon for AI coding agents and humans: indexes
20+ document formats with a local ONNX embedding model into LanceDB, serves search over
CLI/MCP/HTTP from one long-running `quarryd` process, and auto-indexes the current project
at Claude Code session start.
**Why I should care** — It's purpose-built for exactly a Claude Code-heavy workflow — a
daemon-plus-thin-clients design that loads the embedding model once, not a generic RAG
toolkit with an MCP wrapper bolted on.
**What it could replace** — The gap between "grep the codebase" and "stand up a real RAG
stack" for agent-facing semantic recall, entirely offline.
**Ways I could use it** — Semantic search over the current project directly from Claude
Code; a local knowledge-search layer for any MCP client without a cloud embedding API; one
daemon serving CLI/MCP/hooks instead of reloading a model per call.
**Agent opportunity** — Ships a Claude Code plugin
(`claude plugin install quarry@punt-labs`) and session-start hooks for automatic indexing.
**Integration effort** — Medium — Homebrew tap or curl-sh installer, `quarry install` sets
up the daemon and TLS certs; macOS Apple Silicon and Linux only, no Windows.
**Maturity** — Emerging — created 2026-02-08, already v3.2.1 (matches PyPI), CI configured,
effectively a two-person effort (one human, one Claude-Code-attributed committer).
**License** — MIT, no restrictions.
**Alternatives** — ripgrep/grep (lexical only), ctx (catalogued 2026-09-04 — session-
transcript recall, complementary not competing), Cursor's built-in indexing (cloud-based,
IDE-locked), free-search-mcp/RivalSearchMCP (web/document search, not local project
search).
**Why this one** — Built by someone dogfooding their own Claude Code workflow (a
"Working Backwards" PRFAQ is in the repo), not retrofitted from a generic RAG library.
**Recommendation** — Install — local-only, MIT, doesn't touch product code, directly
improves an existing Claude Code workflow today.

## Worth Watching
- **FlowCraft** (`GizClaw/flowcraft`, 415 stars, MIT, Go) — a modular Go SDK for AI agents
  (execution engine, memory contracts, provider adapters, sandboxing) with per-module
  semver releases (`vessel/`, `voice/`, `sdkx/`) but no top-level "core" release yet. The
  architecture (contracts-first, provider adapters plugged in like the inference layer) is
  worth studying, but adopting it means buying into a full Go agent framework — would need
  a stable core release and a clearer on-ramp before it's worth more than reading the docs.
- **RivalSearchMCP** (`damionrashford/RivalSearchMCP`, 127 stars, MIT) — an MCP server
  aggregating 5 web search engines, 9 social platforms, 6 academic databases, and news
  sources with no API keys and no in-server LLM (deterministic, structured output for agent
  chaining). Interesting for agent research workflows, but the primary install path is a
  hosted remote MCP server (`RivalSearchMCP.fastmcp.app`) rather than fully local-first;
  would want to confirm the local `fastmcp run` path is equally maintained before relying on
  it.
- **engram** (`poorants/engram`, 0 stars, MIT, Go) — a "networked PARA knowledge brain for
  coding agents": a shared Postgres-backed store an agent writes conclusions into and a
  later session (different repo, different machine) searches instead of re-investigating.
  One static binary (MCP server + CLI), full-text search over chunks with heading paths, a
  link-integrity linter, and per-document revision history. Created literally the day
  before this review — too early to trust, but the cross-session-knowledge-persistence
  problem it's attacking is real and under-addressed; worth another look once it has more
  than a few days of history.
