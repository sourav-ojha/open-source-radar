# Open Source Radar — 2026-09-16
_Rotation slot 1 — AI agents, MCP, coding productivity_

## Executive Summary
Today's discovery pass surfaced a small number of genuinely differentiated finds inside
a very noisy AI-agent-tooling landscape (dozens of near-identical memory/gateway/agent
orchestration repos again dominated raw search results — the same saturated waves flagged
on prior runs). The standouts split into two useful clusters: agent-native project state
(Beads' dependency-graph task tracker, Graphify's multimodal knowledge-graph skill) and
agent runtime hygiene (Headroom's context compression, AgentKernel's Firecracker
sandboxing, cc-audit's supply-chain scanner for Claude Code artifacts). One tracked
project, It's a Plan, crossed from pre-1.0 to a genuine v1.0.0 with a real architecture
change worth noting.

## Today's Best Discoveries

### 1. Beads — 8.6/10
**Decision:** PROTOTYPE

**What it is** — A distributed, Dolt-backed graph issue tracker built for coding agents:
a dependency-aware, mergeable task graph instead of a markdown TODO list.
**Why I should care** — Long agent sessions and multi-agent branches lose state
constantly; Beads gives an agent a real backlog to query/claim/close instead of
re-deriving "what's left" from scattered notes every session.
**What it could replace** — Ad-hoc AGENTS.md task lists, hand-rolled agent-task-queue
scripts, and markdown TODO files that drift or conflict on merge.
**Ways I could use it** — `bd ready`/`bd claim`/`bd close` as the actual agent task loop;
`bd init --stealth` for personal use on someone else's repo; epics/subtasks for a large
refactor; `bd remember` for persistent project memory across sessions.
**Agent opportunity** — Native setup for Claude Code, Codex CLI, Factory Droid, Cursor;
a separate `beads-mcp` PyPI package exposes the graph to any MCP client.
**Integration effort** — Low for solo trial; Medium once relying on Dolt-remote sync
across multiple machines/agents.
**Maturity** — Mature: 27,188 stars, 489 contributors, v1.3.0, built by Steve Yegge's
Gastown org.
**License** — MIT (Dolt dependency is Apache-2.0). No commercial restrictions.
**Alternatives** — Markdown TODO/AGENTS.md lists, Linear/Jira/Plane MCP integrations.
**Why this one** — Structured, dependency-aware, collision-safe task graph is a genuinely
different design from either markdown notes or a hosted PM tool's MCP bolt-on — and
distinct from the already-rejected agent-*memory* wave, which is about semantic recall,
not task state.
**Recommendation** — Install on one real project for a week; adopt the claim/close loop
before deciding on the git-native sync model for team use.

### 2. Graphify — 8.5/10
**Decision:** PROTOTYPE

**What it is** — A Claude Code skill (`/graphify`) that turns any folder — code, docs,
PDFs, screenshots, whiteboard photos — into a queryable, persistent knowledge graph
using deterministic AST parsing plus Claude vision, with no vector store and no server.
**Why I should care** — Doubles as codebase-onboarding tooling and a "second brain" for
scattered research notes; the multimodal handling (PDFs, photos) is what separates it
from the code-only graph tools already in the catalog.
**What it could replace** — Manually written onboarding docs, ad-hoc "how does this
connect" investigation across a mixed pile of notes/papers/screenshots.
**Ways I could use it** — `/graphify .` for a structural map of a codebase;
`/graphify add <arxiv-url>` to pull external material in; `--wiki` for an
agent-crawlable internal knowledge base; `graphify hook install` to keep the graph
current automatically after every commit.
**Agent opportunity** — Native MCP stdio server (`--mcp`); claims 71.5x fewer tokens per
query on a mixed corpus vs. reading raw files, with worked examples checked into the
repo to verify the number.
**Integration effort** — Low — `pip install graphifyy && graphify install`, then
`/graphify` inside Claude Code.
**Maturity** — Mature by traction (118,116 stars, 266 contributors, v0.9.62) though
young by age (created April 2026) — verified not a fork via the API, watchers count
matches stars.
**License** — Apache-2.0. No commercial restrictions.
**Alternatives** — ripwire (already catalogued) covers deterministic code-only
call-graphs; Graphify is broader and concept-oriented, so the two are complementary.
**Why this one** — Deterministic, provenance-labeled (EXTRACTED/INFERRED/AMBIGUOUS)
graph construction instead of a vector store, plus genuinely multimodal input handling.
**Recommendation** — Run it once on a real mixed corpus (a codebase plus its docs, or a
personal notes folder) and check the token-reduction claim holds before relying on it.

### 3. Headroom — 8.3/10
**Decision:** PROTOTYPE

**What it is** — A local context-compression layer for AI agents: compresses tool
outputs, logs, files, RAG chunks, and conversation history before they reach the LLM,
usable as a library, proxy, MCP server, or one-command wrapper around 15+ agent CLIs.
**Why I should care** — Directly cuts token cost on Claude Code/Codex sessions already
run daily, with a wrap-and-forget integration (`headroom wrap claude`) that requires no
workflow change.
**What it could replace** — Hand-rolled truncation/summarization of tool output — the
real default in most agent setups today.
**Ways I could use it** — `headroom wrap claude` for zero-effort compression; `headroom
proxy` for a language-agnostic drop-in; cross-agent shared memory across Claude/Codex/
Gemini/Grok; `headroom learn` to mine failed sessions into CLAUDE.md corrections
automatically.
**Agent opportunity** — MCP server exposing `headroom_compress`/`headroom_retrieve`/
`headroom_stats` directly to any MCP client.
**Integration effort** — Low, with a documented ONNX Runtime workaround needed on Intel
macOS.
**Maturity** — 72,362 stars, 265 contributors, v0.37.0, Trendshift #1-of-the-day badge.
**License** — Apache-2.0. Compression runs locally; no data leaves the machine per the
README.
**Alternatives** — mcp-compressor (already catalogued) compresses tool *schemas*;
Headroom compresses tool-call *outputs* and logs — a different layer of the same
problem, not a straight substitute.
**Why this one** — Broadest scope of any compression tool reviewed so far (logs, JSON,
prose, code, cross-agent memory) rather than a single-purpose MCP-schema compressor.
**Recommendation** — Wrap one real Claude Code workflow and check `headroom dashboard`
savings before deciding whether to keep it on permanently.

### 4. AgentKernel — 7.6/10
**Decision:** PROTOTYPE

**What it is** — Runs AI coding-agent commands in real Firecracker microVMs (AWS
Lambda's isolation tech) on Linux/KVM, with Docker/Podman/Apple Containers fallbacks,
plus a network-layer secret-injection proxy so credentials never enter the sandbox.
**Why I should care** — Most "sandboxed" agent setups are just a shared-kernel Docker
container; this gives real hardware-level isolation on the exact tech behind AWS Lambda
— directly legible given an AWS-heavy background — plus a genuinely different
credential-handling model worth studying on its own.
**What it could replace** — Plain Docker-as-sandbox for agent-executed shell commands
where actual isolation matters; ad-hoc secret-injection-via-env-vars.
**Ways I could use it** — `agentkernel run npm test`/`pytest`/`cargo build` with
auto-detected images; per-branch persistent sandboxes for parallel agent work; the
Gondolin secret-injection pattern for any pipeline where the executor shouldn't hold the
real credential; signed execution receipts for an auditable run record.
**Agent opportunity** — Sits directly under any agent CLI that shells out to run
commands; MCP support for Firecracker lifecycle/file/exec delegation.
**Integration effort** — Medium — real isolation needs a Linux/KVM host; other platforms
get a materially different (container-based) fallback.
**Maturity** — Emerging: 59 stars, 2 contributors, v0.20.1 — small team, deep feature set.
**License** — MIT. No commercial restrictions.
**Alternatives** — AgentVM/DeepClause (already catalogued, WATCH) — WASM-based, weaker
isolation but no KVM/root requirement; plain Docker/Podman; hosted options like E2B.
**Why this one** — Verified in the README (not just marketing copy) that it genuinely
uses Firecracker/KVM, with each fallback's real isolation level clearly documented.
**Recommendation** — Test on a Linux/KVM box specifically to evaluate the Firecracker
isolation and secret-injection pattern before considering it beyond experimentation.

## Small but High-Leverage Utility
**cc-audit** — a single Rust binary that statically scans third-party Claude Code
Skills, Hooks, and MCP configs for data exfiltration, prompt injection, and
overpermissive tool access before you install them. Anthropic's own docs say it doesn't
audit third-party MCP servers, so this closes a real gap with a five-second scan
(`cc-audit check ./skill/`) or a pre-commit hook (`cc-audit hook init`) — cheap insurance
against installing an untrusted skill or MCP config from a marketplace. MIT-licensed,
small (24 stars, 5 contributors) but actively maintained with CI, codecov, and docs.rs
documentation.
