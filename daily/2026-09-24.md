# Open Source Radar — 2026-09-24
_Rotation slot 2 — product infrastructure, APIs, backend components_

## Executive Summary
Today's slot rewarded a narrower, more targeted discovery pass than usual: instead of
one broad keyword search, GitHub topic-scoped queries (`topic:secrets-management`,
`topic:crdt`, `topic:admin-panel`, `topic:workflow-engine`, and similar) across the
product-infrastructure surface turned up mostly household names already excluded by
spec (Kong, Airflow, Temporal, Grafana, Metabase, and dozens of admin-dashboard
templates). The signal was in a handful of AI-agent-adjacent backend components instead:
a runtime security control plane for coding agents, a context layer that teaches agents
to query a warehouse correctly, a TypeScript SaaS-foundation framework explicitly built
for multi-engineer AI-assisted development, and a mature TypeScript data-access library
mid-rewrite. All four sit at the intersection of this profile's two primary axes —
product-building leverage and AI-agent leverage — rather than in either alone.

## Today's Best Discoveries

### 1. Prismor — 8.3/10
**Decision:** PROTOTYPE

**What it is** — Self-hosted runtime control plane for AI coding agents, covering
prompt-injection detection, supply-chain/IOC scanning, secrets cloaking, an MCP policy
gateway, per-agent IAM, and a hash-chained, Ed25519-signed audit trail, mapped explicitly
to the OWASP LLM Top 10.
**Why I should care** — It's the broadest self-hosted AI-agent governance tool found so
far, and it's directly relevant to both daily coding-agent use and the MSSP/PTaaS side of
the business.
**What it could replace** — Piecemeal hand-rolled hooks for blocking secret exfiltration
or destructive commands, plus manual compliance-mapping work for client security reviews.
**Ways I could use it** — Front every MCP server through its policy gateway; run in
observe mode to baseline a team before enforcing; give each coding agent/subagent a named
IAM identity; generate a signed attestation bundle for a client engagement; use the LLM
proxy mode to govern agents that can't be hooked directly.
**Agent opportunity** — MCP gateway, CLI, and an LLM-traffic proxy that reshapes every
proposed tool call into the same judged event regardless of which agent framework issued
it.
**Integration effort** — Low for the core (`pip install prismor && prismor setup`);
Medium for the deeper features (LLM proxy, inference hooks, IAM).
**Maturity** — Emerging (created Feb 2026, real multi-contributor project, unusually fast
release cadence — v1.54.1 in 7 months).
**License** — Apache-2.0, no commercial restrictions.
**Alternatives** — Preloop (narrower MCP/cost gateway, catalogued 2026-09-09),
Destructive Command Guard (command-pattern blocking only), duncatzat/vigils, halofyai/halofy
(AGPL-3.0).
**Why this one** — Only entrant this run combining prompt-injection detection,
supply-chain scanning, IAM, and a signed, standards-mapped attestation bundle in one
Apache-2.0 tool.
**Recommendation** — Install in observe mode on a low-stakes repo first; evaluate the
attestation-bundle feature specifically against the MSSP/PTaaS use case before enabling
`enforce` anywhere that matters.

### 2. ktx — 8.0/10
**Decision:** PROTOTYPE

**What it is** — A local-first, self-improving context layer that teaches coding/data
agents to query a warehouse accurately, combining raw-table introspection, existing
semantic layers (dbt, LookML, Metabase), and wiki knowledge into one CLI+MCP surface with
approved, reusable metric definitions.
**Why I should care** — Directly targets AI-agent leverage over an actual Postgres or
MongoDB production database, instead of letting an agent reinvent SQL logic on every
question.
**What it could replace** — A hand-built text-to-SQL pipeline for an "ask your data"
feature; ad-hoc, inconsistent agent-written SQL against production databases.
**Ways I could use it** — Point it at a Postgres/Mongo database for governed agent
queries; ingest an existing dbt or Metabase semantic layer plus the team wiki into one
searchable surface; use `ktx sl` / `ktx wiki` directly from a terminal for fast lookups.
**Agent opportunity** — CLI + on-demand local MCP daemon purpose-built for Claude Code,
Codex, Cursor, and OpenCode.
**Integration effort** — Low (`npm install -g @kaelio/ktx && ktx setup`); read-only
against the warehouse, runs entirely locally.
**Maturity** — Emerging (created May 2026, ~1,600 stars, Y Combinator-backed; no tagged
release since July despite continued commits — track `ktx status` directly).
**License** — Apache-2.0, no commercial restrictions.
**Alternatives** — Cube.js, dbt Semantic Layer/MetricFlow, WrenAI (GenBI), getnao/nao
(same niche, license unclear, not deep-reviewed).
**Why this one** — Ingests existing semantic layers *and* wiki content into one surface
with contradiction detection, rather than being yet another standalone semantic layer.
**Recommendation** — Trial against a non-critical Postgres or MongoDB database; review
the telemetry docs first (opt-out usage telemetry, PostHog-routed crash reports that can
include local paths/username).

### 3. Open Mercato — 7.7/10
**Decision:** PROTOTYPE

**What it is** — Open-source TypeScript/Next.js "AI-Engineering Foundation Framework"
for CRM/ERP/commerce backends: multi-tenant RBAC, modular domain entities, event
workflows, dynamic forms, and ready-made CRM/Sales/OMS modules claiming to leave a
product "80% done," plus explicit AI-coding-agent skills so agents know where generated
code belongs.
**Why I should care** — Squarely targets the "shorten the path from idea to a shippable
paid product" axis on a stack already in daily use (TypeScript, Next.js), and directly
addresses the "AI agent writes code but doesn't decide where it goes" problem that shows
up once more than one or two engineers share a codebase with coding agents.
**What it could replace** — Weeks of scaffolding for multi-tenant RBAC, dynamic
entities/forms, and CRM/ERP domain logic on a new SaaS backend.
**Ways I could use it** — Bootstrap a multi-tenant B2B ordering portal or CPQ flow; stand
up a customer/partner self-service portal with configurable dynamic forms; expose a
headless typed API platform shared across web/mobile; use it as a reference for
structuring multi-tenant RBAC even without full adoption.
**Agent opportunity** — Ships explicit "architecture-aware AI harness" skills for
Cursor/Claude Code/Codex covering everything from adding a data table to shipping a full
feature with tests.
**Integration effort** — High — a framework to build on, not a library to drop in;
requires Docker for Postgres/Redis/Meilisearch infra.
**Maturity** — Emerging (created Sept 2025, real multi-contributor project — top
contributor 3,367 commits, four others 240–488 — but 1,241 open issues against 1,769
stars signals active early-stage churn).
**License** — MIT, no commercial restrictions, no per-seat pricing.
**Alternatives** — Hand-rolled Next.js + Prisma scaffold, Medusa.js (commerce-only),
NocoBase (already mainstream, no-code), Frappe/ERPNext (Python, not TS).
**Why this one** — TypeScript-native, explicitly designed around multi-engineer
AI-assisted development consistency rather than just being another admin-panel
generator.
**Recommendation** — Spike a small internal tool or a new client micro-SaaS on it before
committing a production product, given the high issue count and architectural
commitment it asks for.

### 4. ZenStack — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A TypeScript data layer for Node.js/Bun: a Prisma-compatible
schema-first ORM with built-in declarative access control, automatic CRUD API
generation, TanStack Query hooks, Zod schema generation, and a Kysely-based typed query
builder. V3 is a ground-up rewrite replacing the Prisma engine itself with an in-house
Kysely-based engine.
**Why I should care** — Removes a recurring source of backend bugs — hand-written
per-endpoint access-control logic — by moving authorization into the schema, on a stack
(TypeScript/Node, Prisma-adjacent) already in use.
**What it could replace** — Hand-written authorization middleware scattered across API
endpoints; a separate CRUD-API/hooks-generation step.
**Ways I could use it** — Add it to an existing Prisma backend to move access control
into the schema; scaffold a new project for typed CRUD APIs and TanStack Query hooks out
of the box; use the Kysely escape hatch instead of raw SQL.
**Agent opportunity** — Not agent-specific, but a schema that declares data shape and
access rules together gives a coding agent one place to look for both.
**Integration effort** — Low — pure TypeScript library, CLI-driven init on new or
existing projects.
**Maturity** — Established (created 2022, 2,945 stars, active Discord, named sponsors)
but currently in the early-stability window of the V3 rewrite.
**License** — MIT, no commercial restrictions.
**Alternatives** — Plain Prisma + hand-written guards, Supabase RLS (Postgres-locked),
CASL/Casbin (authz-only), Hasura (GraphQL-first, heavier).
**Why this one** — Unifies schema, access-control policy, typed CRUD API, and frontend
query hooks in one TypeScript-native toolchain, which none of the alternatives do
together.
**Recommendation** — Try on a non-critical Postgres-backed service first, given V3's
engine is recent, before migrating anything access-control-sensitive.

## Small but High-Leverage Utility
**Router.so** (`9d8dev/router`, AGPL-3.0, 382 stars) is a self-hostable, headless form
handling and lead-routing backend — the kind of small, boring, always-needed piece every
landing page or MVP needs, with a hosted form UI, a WordPress block/shortcode, and
Resend-based email delivery included. It's worth owning once and reusing across every
future side project or client micro-SaaS instead of adding another monthly
Formspree/Basin/Getform line item. AGPL-3.0 is fine for self-hosted/internal use but
would need attention if a modified version were ever offered as a hosted service to
third parties; no tagged GitHub release yet, so track `main` directly.

## Run Notes
Discovery relied entirely on the GitHub Search API: an initial broad `in:readme,
description` pass sorted by `updated` proved too noisy (returned essentially random
recently-pushed repos with a loose keyword match) and was abandoned in favor of 12
`topic:`-scoped queries sorted by stars, covering secrets management, audit logging,
CRDT/realtime, admin panels, object storage, business intelligence, API gateways, form
builders, workflow engines, file upload, authorization, and collaboration tools. Six
candidates were taken to deep review (repo metadata, releases, contributor lists, and
full README) via parallel `api.github.com` calls; `registry.npmjs.org` was used to
cross-check ktx's and ZenStack's published versions against GitHub tags. WebSearch and
Hacker News were not used this run — the topic-scoped GitHub Search API alone surfaced
enough differentiated volume for slot 2. No sources failed or were skipped.
