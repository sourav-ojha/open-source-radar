## Today's Best Discoveries

### 1. Benjamin-Plus Skill — 8.4/10
**Decision:** USE NOW

**What it is** — A JetBrains-authored coding-agent skill teaching five token-efficiency habits (consolidate lookups, read only necessary file portions, check dependencies once, rely on task-defined verification, poll builds sparingly), distributed as a ~3KB injectable payload rather than an installable tool.
**Why I should care** — It's a measured, not claimed, cost reduction on the exact coding-agent workflows already in daily use — a paired A/B study across 80 SkillsBench tasks on Claude Sonnet 5 showed -17.9% median cost, and a cross-platform Java-task run showed a statistically significant -4.4% cost (p=0.003) with quality unchanged.
**What it could replace** — Nothing built — it's a free efficiency layer on top of existing agent usage, at zero workflow change.
**Ways I could use it** — Drop into `~/.claude/settings.json` hooks or any AGENTS.md today; bundle into a personal "agent starter kit" applied across every repo; stack under project-specific skills as a baseline.
**Agent opportunity** — Works with Claude Code and Codex CLI natively; adapts to any agent accepting system-prompt injection.
**Integration effort** — Low — paste a ~3KB payload into a hook or system prompt, no package manager, no build.
**Maturity** — Emerging — created 2026-08-17, 303 stars, MIT, actively pushed as of 2026-08-27.
**License** — MIT, no restrictions.
**Alternatives** — Ad-hoc personal prompt tweaks (no measured effect); other unvalidated "prompt engineering" skill repos.
**Why this one** — It's the rare agent-skill repo backed by an actual benchmark rather than a marketing claim, from a credible source (JetBrains).
**Recommendation** — Install now — it's free, low-risk, and reduces cost on workflows already running daily.

### 2. fx (Vercel Labs) — 8.0/10
**Decision:** PROTOTYPE

**What it is** — A ~7.8MB, embeddable coding-agent harness written in Zig, styled as a Unix-like CLI (not a heavyweight terminal IDE), with ~10µs cold start, MCP/skills/subagent support, native + WASM builds, and Agent Client Protocol (ACP) support for editor integration.
**Why I should care** — Most coding-agent CLIs are shipped as end-user TUI products; fx is explicitly built to be embedded into other systems, which is the shape that matters if the goal is building agent capability *into a product* rather than using a terminal app personally.
**What it could replace** — A multi-week build-from-scratch of a minimal, permission-controlled, multi-provider agent harness with MCP/ACP support and session management.
**Ways I could use it** — Scriptable/pipeable agent calls from CI without a heavy TUI; embed the WASM SDK into a custom internal dev tool; prototype an agent-orchestration layer using fx as the lightweight execution engine.
**Agent opportunity** — Native MCP client/server support and a subagent model make it directly composable into a larger agent-orchestration setup.
**Integration effort** — Low — single curl install script; embedding via WASM SDK is more involved but still self-contained.
**Maturity** — Experimental — explicitly labeled "Experimental. Use at your own risk" by the maintainers, v0.0.7, created 2026-08-11 (3 weeks old), 2,679 stars, Apache-2.0.
**License** — Apache-2.0, no restrictions.
**Alternatives** — OpenCode, Aider, Claude Code, Codex CLI (all heavier TUIs, not designed for embedding); VT Code (below) trades minimalism for governance.
**Why this one** — The WASM SDK + ACP + tiny-binary combination is a genuinely different design point than every other coding-agent CLI in the space — optimized for embedding, not standalone use.
**Recommendation** — Prototype the CLI first; treat the WASM embedding path as experimental until it passes 1.0.

### 3. VT Code — 7.9/10
**Decision:** PROTOTYPE

**What it is** — An open-source Rust terminal coding agent built safety-first: restricted shell sandbox, tool guardrails, subprocess isolation, audit logging, and a provider whitelist to stop accidental data leakage to unapproved LLM endpoints. Modular crates (`vtcode-battery-pack`) allow embedding individual components.
**Why I should care** — Most terminal coding agents optimize purely for capability; VT Code's differentiator — explicit governance controls — is exactly the concern that surfaces once agent tooling moves from personal use toward anything security-sensitive, which is directly relevant given the MSSP admin-portal context.
**What it could replace** — Custom sandboxing/audit-logging wrapper work that would otherwise be needed to make agent tooling safe for security-conscious use.
**Ways I could use it** — Local/offline terminal coding agent via Ollama/LM Studio/llama.cpp; corporate-safe agent usage where a provider whitelist and audit trail are required; study the propose/verify sub-agent split as a pattern.
**Agent opportunity** — MCP + Agent Plugin support, plus WebMCP for attaching a browser editor to a live terminal session.
**Integration effort** — Medium — Rust binary via curl/Homebrew/Cargo install, some config required; foreign ecosystem relative to the MERN stack.
**Maturity** — Emerging, but comparatively mature for this space — created 2025-08-29 (over a year old), 827 stars, actively pushed as of 2026-09-01, v0.151.2, Apache-2.0.
**License** — Apache-2.0, no restrictions.
**Alternatives** — fx (above, minimal/embeddable rather than governance-focused); Aider, OpenCode, Claude Code, Codex CLI (none emphasize provider whitelisting/audit logging to this degree).
**Why this one** — The audit-logging and provider-governance design is a concrete, working example of "agent tooling done safely enough to hand to security-conscious customers."
**Recommendation** — Prototype for personal use first; the governance features are the part worth studying even without full adoption.

### 4. mcp-ts-core — 7.8/10
**Decision:** PROTOTYPE

**What it is** — An agent-native TypeScript framework for building MCP servers: declarative tool/resource definitions, built-in auth, multi-backend storage, OpenTelemetry instrumentation, and first-class support for Bun/Node/Cloudflare Workers.
**Why I should care** — This is infrastructure for *building* MCP servers in the exact Node/TypeScript stack already in daily use, replacing the boilerplate (auth, storage, telemetry) that otherwise gets rebuilt from scratch on every new MCP server.
**What it could replace** — A week or more of hand-wired auth, pluggable storage, and OpenTelemetry setup for any new MCP server.
**Ways I could use it** — Scaffold an MCP server for an internal tool without hand-rolling plumbing; expose a future SaaS product as an MCP server for customers' agents as a shippable feature; standardize how future MCP servers handle auth/observability.
**Agent opportunity** — Not an MCP server itself — it's the framework for building one, directly supporting primary relevance axis 1 ("expose as an MCP server").
**Integration effort** — Low — npm install, TypeScript-native, declarative config.
**Maturity** — Emerging — created 2025-03-20 (over a year old, actively maintained), 148 stars, Apache-2.0, npm `latest` 0.12.3 published 2026-08-21 (matches GitHub tag).
**License** — Apache-2.0, no restrictions.
**Alternatives** — Official `@modelcontextprotocol/sdk` (lower-level, no built-in auth/storage/telemetry conveniences); Miragon/mcp-toolkit (similar goal, newer/thinner).
**Why this one** — It's the only one of today's finds that directly accelerates *building* an MCP server rather than consuming one — the more durable kind of leverage for someone shipping products.
**Recommendation** — Prototype on the next internal MCP server build; verify it tracks MCP spec changes promptly before depending on it for a shipped product.

### 5. Autoprompt Skill — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A coding-agent skill replacing step-by-step prompting with a single clear goal, running a plan → build → review → test → sign-off → sweep loop where separate sub-agents plan, execute, and independently verify the work. Supports 9 coding agents (Claude Code, Codex, OpenCode, and others).
**Why I should care** — Backed by a real benchmark (Terminal-Bench 2.1: OpenCode alone solved 60/89 tasks, OpenCode+Autoprompt solved 73/89 — a 45% reduction in failures), and the plan/execute/verify separation is a pattern worth studying even independent of adopting this specific skill.
**What it could replace** — Manual step-by-step prompting and hand-built plan/execute/verify prompt scaffolding on larger agentic tasks.
**Ways I could use it** — Hand an agent a single high-level goal on a larger multi-file feature instead of micromanaging steps; use selectively on higher-stakes tasks given the cost tradeoff below.
**Agent opportunity** — Drop-in skill for any of the 9 supported agent CLIs — no infrastructure to stand up.
**Integration effort** — Low — skill file injection, Node 20+/Python 3.11+/Git required.
**Maturity** — Emerging — created 2026-08-17 (2 weeks old), fast growth to 961 stars, MIT, pushed 2026-08-30.
**License** — MIT, no restrictions.
**Alternatives** — Benjamin-Plus Skill (above — optimizes cost, not failure rate; complementary, not competing); manual plan/verify prompting done by hand.
**Why this one** — Real benchmark evidence for the failure-rate claim, not a marketing number.
**Recommendation** — Prototype selectively on higher-stakes tasks — the maintainer's own estimate is ~3x execution time and ~2x token usage for the failure-rate improvement, so it's not a blanket replacement for normal prompting.

### 6. Tela — 7.3/10
**Decision:** STUDY

**What it is** — A self-hostable, markdown-native team wiki with AI agents as first-class collaborators via a built-in MCP server. Go + pgx (no ORM) + PostgreSQL/pgvector backend, React 19 + Milkdown + Yjs frontend for real-time multiplayer editing.
**Why I should care** — Most self-hosted wiki alternatives bolt AI on as a chatbot; Tela's MCP-first design (agents get scoped read/write tools, not just chat) is a more honest architectural answer to "how should a product expose itself to agents," worth studying even without adopting the whole app.
**What it could replace** — Notion/Confluence/Outline for a self-hosted knowledge base, if the AGPL terms are acceptable for the use case.
**Ways I could use it** — Self-hosted Notion alternative that's directly agent-queryable/writable; reference architecture for building any "AI-native" collaborative product.
**Agent opportunity** — MCP endpoint (`/api/mcp`) with per-tool write restrictions and PAT/OAuth auth — a concrete pattern for exposing product data to agents safely.
**Integration effort** — Medium — Docker Compose stack (Postgres+pgvector, Gotenberg, a Slidev sidecar), heavier than a single binary.
**Maturity** — Emerging — created 2026-05-18 (~3.5 months old), 57 stars, v0.8.0, AGPL-3.0.
**License** — **AGPL-3.0 — flagged loudly.** Fine for internal self-hosted use; modifying and re-offering it as a hosted service triggers AGPL's source-disclosure requirement. A separate commercial/Enterprise license exists for production use beyond that.
**Alternatives** — Docmost, AFFiNE, Outline (self-hosted wikis without native MCP integration); Notion/Confluence (SaaS, no self-hosting, no agent write access).
**Why this one** — The permission-scoped MCP write layer, not the wiki itself, is the interesting part — a working reference for agent-safe product data exposure.
**Recommendation** — Study the architecture and MCP permission model; don't adopt the full app without checking AGPL implications for any commercial use.

## Small but High-Leverage Utility
**Markdown Vault MCP** ([pvliesdonk/markdown-vault-mcp](https://github.com/pvliesdonk/markdown-vault-mcp), MIT, 32 stars) turns a personal markdown notes vault into a hybrid keyword+semantic search and write surface for an LLM — SQLite FTS5 (BM25) fused with optional embeddings via reciprocal rank fusion, 34 LLM-visible tools, and production-grade packaging (CI/CD, codecov, semantic versioning, edge/pre-release/stable channels) that's unusually polished for what's normally a weekend-project category. Point it at any Obsidian-style vault and Claude can search and write notes immediately, no vector DB to stand up. Only genuinely useful if a markdown notes habit already exists — otherwise it's a nice-to-know pattern rather than an immediate install.

## Worth Watching
- **SenteLabsAI/extensible-mcp** (Apache-2.0, 5 stars) — an MCP proxy solving a real and growing pain point (token bloat from injecting every tool from every configured MCP server) via on-demand semantic tool discovery and a deterministic access-control filter pipeline. Architecture is sound (three meta-tools: `search_tools`, `call_tool`, `load_mcp_server`), but it's v1 with only 5 stars and the maintainer's own docs flag that LLM-supplied confirmation strings are unsafe against prompt injection until signed claims land. Worth another look once it has more traction and the security gap is closed.
- **Spielewoy autoprompt-skill and JetBrains benjamin-plus-skill both launched the same week** — worth watching whether either author keeps shipping (JetBrains backing gives benjamin-plus somewhat more confidence) versus being a one-off benchmark post.
- **t8y2/dbx** (Apache-2.0, 17,736 stars) — a 20MB lightweight cross-platform DB client (90+ databases including MongoDB/Postgres) with built-in AI, MCP server, CLI, desktop, and Docker. Not deep-reviewed today given the very fast, somewhat unusual star growth (17.7k stars in ~4 months) — worth a closer look next time to separate genuine traction from any anomaly before recommending it as a MongoDB/Postgres tooling upgrade.
