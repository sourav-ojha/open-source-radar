# Open Source Radar — 2026-10-26
_Rotation slot 6 — infrastructure, observability, deployment_

## Executive Summary
Today's best find wasn't another observability dashboard — it was formae, a genuinely different take on infrastructure-as-code that discovers what's actually running instead of trusting a state file, with a native MCP server for AI agents. Nora showed up as a credibly lighter-weight second entrant next to the already-catalogued Artifact Keeper in the self-hosted artifact-registry niche, and Dopbase is a promising but very young single-file secrets manager positioned explicitly against Vault/OpenBao's operational weight. Two previously catalogued tools also earned real updates: Pipewright embedded an approval-gated MCP server plus automated post-deploy health verification, and TokenTimer extended into enterprise Windows PKI via Vault and AD CS. Generic single-word category searches (distributed tracing, metrics pipeline, service mesh) mostly returned megalist "awesome-*" repos or nothing useful when sorted by stars; narrower phrase-plus-stars-range queries sorted by recency were the pattern that actually worked.

## Today's Best Discoveries

### 1. formae — 8.2/10
**Decision:** PROTOTYPE

**What it is** — A stateless infrastructure-as-code tool: an agent periodically discovers what's actually running across AWS, Azure, GCP, Kubernetes, and roughly a dozen other providers, versions every change and who made it, and lets you reconcile drift resource-by-resource — no Terraform-style state file. Works through Pkl code, a CLI, or a native MCP server for AI agents.
**Why I should care** — Every real AWS account accumulates resources nobody captured in Terraform state. formae treats those as read-only "unmanaged" until explicitly adopted, removing the brittle `terraform import` dance, and the MCP server means a coding agent can answer "what's running here and what changed" through an audited schema instead of raw CLI exploration.
**What it could replace** — Manual `terraform import` scripting; ad hoc shell scripts for cloud-account inventory during a new engagement; driftctl (discontinued).
**Ways I could use it** — Fast read-only inventory of an unfamiliar client AWS account ahead of a PTaaS engagement; continuous drift detection with a who-changed-what ledger; bootstrapping Pkl IaC from a legacy account via `formae extract`; wiring the MCP server into Claude Code for audited infra Q&A and changes.
**Agent opportunity** — Native MCP server ships with the project; Claude Code has a marketplace install, with Codex/Cursor/OpenCode documented separately.
**Integration effort** — Medium — install is a one-line shell script, but the Pkl DSL and plugin model take some ramp-up.
**Maturity** — Emerging. 775 stars, 44 forks, 9 contributors, ~1 year old, active biweekly releases (v0.90.5).
**License** — FSL-1.1-ALv2 (Functional Source License) — **not OSI open source**. Confirmed via the LICENSE file directly: internal use and embedding in a commercial product are explicitly permitted; only a "Competing Use" (reselling formae itself or a substitute for it/formae Cloud) is barred. Converts to Apache-2.0 two years after each release.
**Alternatives** — Terraform/Pulumi (state-file model, manual import needed), driftctl (discontinued), Steampipe/CloudQuery (read-only, no reconciliation).
**Why this one** — It's the only IaC tool found that treats discovery as the default source of truth instead of state, and the only one with a first-class MCP surface rather than a bolted-on wrapper.
**Recommendation** — Prototype against one real, ideally non-production, AWS account before trusting it with anything critical.

### 2. Nora — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted artifact registry and pull-through cache in a single ~20MB binary with no database, covering 17 package formats (Docker/OCI, Maven, npm, PyPI, Cargo, Go, RubyGems, NuGet, Terraform, and more), with supply-chain curation (allowlist/blocklist/quarantine via a companion OSV-feed tool) and cosign-signed releases.
**Why I should care** — Most projects eventually need a private mirror in front of npm/PyPI/Docker Hub for CI reliability and supply-chain hygiene; Nora does it with a far lighter operating footprint than Artifactory, Nexus, or even the already-catalogued Artifact Keeper.
**What it could replace** — Direct CI traffic to public registries (rate-limit/outage exposure); manual Artifactory/Nexus migration scripting (`nora import` handles it); a from-scratch air-gapped mirror setup (`nora mirror`).
**Ways I could use it** — Pull-through cache in front of a CI pipeline; air-gapped package mirroring for a client environment; enforcing a minimum release age/quarantine window on new package versions; OIDC-based artifact publishing instead of long-lived registry credentials.
**Agent opportunity** — None documented beyond standard REST/API-token scripting.
**Integration effort** — Low — Docker image, Helm chart, binary, or deb/rpm; no database to provision.
**Maturity** — Emerging. 350 stars, 44 forks, 16 contributors, ~9 months old, frequent releases (v1.4.2, pushed the day of this review). 40 open issues against 350 stars suggests active churn.
**License** — MIT, unrestricted commercial use.
**Alternatives** — Artifact Keeper (already catalogued — broader 40+ format coverage plus built-in Trivy/Grype scanning, heavier); JFrog Artifactory, Sonatype Nexus (commercial); Harbor (OCI-only).
**Why this one** — Different operating-footprint tradeoff than Artifact Keeper: no database, cache-first design, for teams that want a lightweight mirror rather than a full registry-plus-scanner.
**Recommendation** — Stand up as a pull-through cache in front of one real CI pipeline before considering it a permanent registry replacement.

### 3. Dopbase — 7.3/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted secrets manager bundling server, admin UI, REST API, and CLI into one single-file executable with a SQLite backend and a local master key, organizing secrets by project and environment.
**Why I should care** — Vault and OpenBao need their own HA storage backend and auth-method setup before they're useful — a lot of ceremony for a solo developer or small team that just wants to stop scattering `.env` files. Dopbase's explicit design goal is working "without requiring a large supporting infrastructure stack."
**What it could replace** — Scattered per-repo `.env` files; handing a human credential to a CI runner or agent instead of a scoped token.
**Ways I could use it** — Centralizing project/environment secrets; `dopbase run <env> -- <command>` to inject secrets into a process without writing a shared `.env`; issuing a `DOPBASE_TOKEN` scoped to a CI runner or agent; import/export across dotenv/JSON/YAML/TOML/Docker-env formats.
**Agent opportunity** — `DOPBASE_TOKEN` is explicitly documented as supporting AI agents as well as CI runners; no MCP server.
**Integration effort** — Low — install script or release binary; no official Docker image yet.
**Maturity** — Experimental. ~2 months old, 165 stars (fast climb from 0), 11 forks, 4 contributors, 19 open issues (high ratio typical of a very young project).
**License** — Apache-2.0, unrestricted commercial use.
**Alternatives** — HashiCorp Vault/OpenBao (full-featured, heavier), Infisical (mainstream, excluded by policy), Doppler (hosted SaaS), plain `.env` files (status quo).
**Why this one** — The only self-hosted secrets manager found this run designed from the ground up to avoid Vault-class operational overhead.
**Recommendation** — Trial for a low-stakes side project's secrets; hold off on anything production-critical until encryption/key-management details are independently verified.

## Meaningful Updates
**Pipewright** (huangchengsir/pipewright) — PROTOTYPE 7.5 → PROTOTYPE 7.9. v1.9.0–v1.9.5 added an MCP server embedded directly in the Pipewright binary (shares its port, no separate deployment) exposing project/pipeline queries, pipeline triggering, and run/deployment history, with read-only-by-default project-scoped tokens; v1.9.2 extended this to agent-proposed configuration changes gated behind manual web approval. v1.9.3+ added "release safeguarding" — a manual 5/10/15-minute read-only post-deploy health check (image version, container liveness, restarts, Docker health) with an optional evidence-cited AI explanation generated only on explicit per-use consent. Why it matters: this is a real step toward giving a coding agent write access to CI/CD safely rather than just read access. Catalog updated: Yes.

**TokenTimer** (tokentimerch/tokentimer-core) — PROTOTYPE 7.5 → PROTOTYPE 7.6. v0.18.0 added guided Vault-backed certificate distribution and Active Directory Certificate Services (AD CS) enrollment for Windows/IIS, extending CertOps beyond ACME/DNS-01 into enterprise Windows PKI environments an MSSP client might actually run. Why it matters: broadens the realistic client base for the MSSP-service-line use case already noted for this project. Catalog updated: Yes.

**Cynative** (cynative/cynative) — checked v1.12.1 → v1.14.1; release notes show only connector tweaks and bug fixes (GCP/GitLab connector hints, classification fixes). Not meaningful per the catalog's own update criteria. Catalog updated: No.

## Small but High-Leverage Utility
**vps_pilot** (sanda0/vps_pilot) — a single Go binary (dashboard + hub) plus a tiny Rust agent per server, purpose-built for "the handful of Linux servers you run" rather than a full Prometheus/Grafana stack. CPU/memory/network/disk metrics with live WebSocket updates, threshold alerts to Discord/Email/Slack, and a scoped project-command runner that only executes commands declared in a per-project config file, with every run logged. For 2-10 servers, this is a lot less to operate than standing up a full metrics stack just to know when something's on fire.

## Worth Watching
- **Consize** (consize-oss/consize) — An automated cloud-cost-optimization control plane with a genuinely interesting architecture (Discover → Recommend → Policy check → Plan → Apply → Verify → Recover, with automatic rollback on a regressed health signal). Apache-2.0, but very early (v0.2.0, alpha) and currently only works end-to-end for Kubernetes Deployments + Prometheus; needs broader cloud/resource coverage and real (not just estimated) savings numbers before it's worth a deeper look.
- **Talus** (Hartwell-Labs/talus-process-monitor) — An eBPF Linux ransomware-detection agent (behavioral syscall scoring, optional neural classifier) with a confirmed-real MIT license. Held back because the README contradicts itself: the main text describes `--auto-kill` sending SIGKILL on a verdict, but the licensing section says the MIT build contains no `kill(2)` call at all and that path is commercial-only. That gap, plus self-assessed maturity claims and a single visible author, needs resolving before trusting it as a security tool.
- **openctemio/openctem** — The most feature-complete entrant (asset discovery, risk-based prioritization, validation, remediation) in a same-week wave of ~5 near-identical self-hosted attack-surface-management/CTEM platforms, but still only 8 stars and thin independent traction. Worth another look if it pulls ahead of the pack it's currently indistinguishable from.
