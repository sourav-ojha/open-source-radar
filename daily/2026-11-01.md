# Open Source Radar — 2026-11-01
_Rotation slot 5 — self-hosted SaaS alternatives, productivity_

## Executive Summary
Today's slot surfaced a small but genuinely useful cluster of self-hosted "sell a digital thing" infrastructure: two different takes on a Gumroad alternative (one radically serverless, one a more complete multi-gateway Go app) and a self-hostable affiliate/referral tracker in a stack that matches tooling already in use. The more notable story of the day, though, is a maintenance update: Velox — the AI-token-native billing engine catalogued three weeks ago — renamed itself to Hardcount and, in the process, shipped ten releases that fixed a real correctness bug in its flagship LiteLLM integration and hardened it for actual partner installs. A same-day affiliate-marketing "traffic distribution system" was found but held back on dual-use grounds rather than recommended.

## Today's Best Discoveries

### 1. HonorBox — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A Gumroad/Lemon Squeezy alternative that needs no server and no database: a static storefront on GitHub Pages, checkout via Stripe Payment Links on your own Stripe account, and fulfillment via a scheduled GitHub Action that invites each buyer as a collaborator on a private product repo, re-issuing the invite before GitHub's 7-day expiry.
**Why I should care** — Every other self-hosted Gumroad alternative in the catalog needs a running service. This needs nothing but a GitHub repo and Stripe account, which is the right trade-off for selling one thing occasionally.
**What it could replace** — A storefront + backend you'd otherwise stand up (and pay for) to sell a single digital product, or a manual "take payment, then add buyer as collaborator by hand" process.
**Ways I could use it** — Sell internal scripts/templates as a paid product; package a one-off paid add-on for the MSSP admin-portal SaaS (a report template, a hardening checklist); adopt just the fulfillment script (`scripts/fulfill.js`) onto an existing Stripe + private-repo setup via its "bring your own store" mode; use the live demo as a reference implementation.
**Agent opportunity** — The fulfillment script is a small, config-driven building block an agent could wire into any payment-link-to-repo-access workflow independent of the rest of the suite.
**Integration effort** — Low: no server to run, just GitHub Pages + a GitHub Action + Stripe Payment Links.
**Maturity** — Experimental: created July 2026, 21 stars, 1 fork, effectively single-maintainer. The live demo sells a real paid add-on, independently corroborated by third-party SaaS-directory listings rather than purely self-asserted.
**License** — MIT, no restrictions.
**Alternatives** — Gumroad, Lemon Squeezy, Polar (all proprietary — Polar is the closest comparison, also offering instant private-GitHub-repo access as a built-in benefit).
**Why this one** — Genuinely different architecture (zero infrastructure) rather than another server-based clone, and it handles the one fiddly edge case (GitHub invite expiry) that would otherwise bite in production.
**Recommendation** — Prototype it for a small, infrequent digital-product sale; there's essentially no operational risk since there's no service to run.

### 2. Open Payment Host — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted Go web app for selling digital products, subscriptions, and newsletters via Stripe, PayPal, Razorpay, or Square, with automatic per-country gateway routing and Listmonk/Mailchimp audience sync.
**Why I should care** — Four years of continuous single-maintainer development, used in production by its own author, with genuinely differentiated features (country-based gateway routing, newsletter sync) not found elsewhere in this niche.
**What it could replace** — Platform percentage fees on top of processing fees (Gumroad/Ko-fi/Buy-Me-a-Coffee); a hand-built multi-gateway checkout integration; a presigned-URL file-delivery pipeline.
**Ways I could use it** — Sell digital files/subscriptions without a platform take rate; route Indian customers to Razorpay and everyone else to Stripe for parity pricing; deliver paid downloads via S3/R2 presigned URLs; sync buyers into a newsletter automatically.
**Agent opportunity** — Experimental REST API/webhook surface — not yet stable enough to lean on.
**Integration effort** — Medium: Docker or one-click Railway deploy, but several payment-gateway credentials to wire up.
**Maturity** — Emerging: 243 stars, 12 forks, 4 subscribers, created 2022, pushed 2026-09-29. Maintainer explicitly flags "possible unknown bugs" while using it for his own production payments.
**License** — AGPL-3.0, flagged loudly: fine to self-host and sell through, but modifying and offering it as a hosted platform to third parties triggers source-disclosure.
**Alternatives** — Gumroad, Buy Me a Coffee, Ko-fi, Lemon Squeezy, Polar (all proprietary); HonorBox (today's other find — zero-server vs. this one's full multi-gateway server).
**Why this one** — The country-based payment router and newsletter sync are real, not cosmetic, differentiators versus every other self-hosted Gumroad clone reviewed to date.
**Recommendation** — Prototype for a real digital-product sales need, keeping the AGPL implications and the maintainer's own "WIP" admission in mind.

### 3. RefearnApp — 7.1/10
**Decision:** PROTOTYPE

**What it is** — A self-hostable affiliate/referral tracking platform (open-source alternative to Rewardful, FirstPromoter, Tolt): edge click/conversion tracking on Cloudflare Workers, Stripe/Paddle/PayPal payouts, coupon-code tracking, affiliate portal. Next.js + Postgres (Drizzle) + Upstash Redis.
**Why I should care** — Referral programs are a cheap growth channel, and every proprietary alternative charges a fee that scales with referral volume. This is the first self-hostable entrant in this specific niche, in a stack that's already in daily use (Next.js, Cloudflare).
**What it could replace** — Rewardful/FirstPromoter/Tolt subscription fees; hand-built click/conversion attribution and payout logic.
**Ways I could use it** — Run a referral program for a future micro-SaaS product; pay affiliates via PayPal mass payouts instead of manual transfers; attribute a launch campaign via coupon codes.
**Agent opportunity** — None identified at review time.
**Integration effort** — Medium: Docker for the main app, but the tracking layer needs a Cloudflare Workers account — more moving parts than a single-container deploy.
**Maturity** — Emerging: 47 stars, 17 forks (healthy engagement signal), created March 2025, pushed 2026-10-29. Latest GitHub tag is 5 months stale relative to `main` — don't take the tagged version as the true state of the project.
**License** — AGPL-3.0 on the self-hosted edition (all features unlocked); a separately-sold "Managed Cloud" tier is the vendor's own hosted offering, not a feature gate.
**Alternatives** — Rewardful, FirstPromoter, Tolt (all proprietary).
**Why this one** — Only self-hostable option found in this exact niche, and the stack fit (Next.js/Cloudflare/Postgres) is better than building or adapting something foreign.
**Recommendation** — Prototype, but verify the current state of `main` directly rather than trusting the stale release tag.

## Meaningful Updates

**Velox → Hardcount (gethardcount/hardcount)** — PROTOTYPE, 8.2 → 8.3/10. Previous state: v0.3.2, 4 stars, pre-1.0 billing engine with rigorous but unvalidated benchmarks. Current state: renamed to Hardcount at v0.9.0 (2026-10-28; `getvelox/velox` now 301-redirects to the new repo), v0.9.1, 6 stars. What changed: ten tagged releases fixed a real correctness gap — LiteLLM proxy usage was silently not recorded at all prior to v0.5.0 — and added mandatory idempotency keys, required multi-replica rollout support, a security-review-driven `METRICS_TOKEN` requirement, a migration-repair command, private-IP webhook rejection, and a one-command Docker install with a full API reference. Why it matters: this moved the project from "rigorous-looking but had a real gap in its flagship integration" to "gap fixed, hardened for actual partner installs" in three weeks — a genuine maturity jump, not cosmetic churn. Does this change the recommendation: still PROTOTYPE (pre-1.0, still effectively single-maintainer, still tiny community), but worth re-testing if it was tried and found lacking around the LiteLLM path specifically. Catalog updated: Yes.

**Keygate (tabloy/keygate)** — PROTOTYPE, 8.0 → 8.1/10. Previous state: v0.1.16, 135 stars. Current state: v0.1.19, 188 stars, 64 forks. What changed: added per-seat licensing (buyers pick seat count at checkout, change it later in the portal) and per-member license keys with per-device revocation; fixed Stripe refund/dispute handling to correctly scope what it revokes, and fixed a webhook-reliability bug where failed license updates answered Stripe 200 instead of 500 (so Stripe never retried a failed update). Why it matters: per-seat licensing is genuinely new functionality for team-sold tools, and the refund/webhook fixes close real correctness gaps in the billing path rather than being cosmetic. Does this change the recommendation: still PROTOTYPE — still pre-1.0 and thinly staffed, but the fixes raise confidence in the billing correctness claims specifically. Catalog updated: Yes.
