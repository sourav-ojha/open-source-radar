# Open Source Radar — 2026-11-03
_Rotation slot 7 — experimental projects and hidden gems_

## Executive Summary
Today's strongest thread is small, single-binary tools that treat an AI coding agent as a first-class peer of a human user rather than bolting an API onto a human-first tool — kanzo (a 4.5 MB kanban board that's equally an MCP server) and veil (a local proxy that keeps an agent's real production data away from the model provider) both do this cleanly. Alongside them, kensaku shows the same "do the obvious thing nobody else bothered to do" pattern applied to local search: full-text and OCR indexing over MCP, where Everything/Listary/PowerToys Run still only index filenames. A fourth find, pngdeer, is a straightforward but well-measured TinyPNG replacement. The pentest/PTaaS-adjacent searches today (secondary context only) surfaced a genuinely well-built local agentic-pentesting workspace (executioner) sitting in an already-saturated niche, and a marketing-heavy CTF-competition artifact (sapper-v2) that doesn't generalize beyond its competition. Two fresh suspicious-engagement cases are flagged below for future tracking rather than outright rejection, since both are too new to call definitively.

## Today's Best Discoveries

### 1. veil — 7.9/10
**Decision:** PROTOTYPE

**What it is** — A local privacy proxy (Python, PyPI `veil-proxy`) that sits between a coding agent CLI (Claude Code, Codex, Aider, or any Anthropic/OpenAI-compatible client) and the model provider, deterministically pseudonymizing names, emails, phone numbers, addresses, IDs and secrets before a request leaves the machine, then swapping the real values back into the agent's local output.
**Why I should care** — This is exactly the risk created by letting a coding agent run shell commands or DB queries against anything resembling production data, and it's directly relevant to the MSSP/PTaaS context where the data at hand is a client's, not just mine.
**What it could replace** — Manual data scrubbing before giving an agent access to anything production-shaped; trusting a model provider's data-handling terms by default.
**Ways I could use it** — point Claude Code/Codex at a real prod DB dump or real logs without the model seeing real PII; force-route a team through it via `managed-settings`; investigate an MSSP client incident locally without sending client PII to a third-party model; verify redaction by diffing the "what was on disk" vs "what the model got" log lines it ships with.
**Agent opportunity** — No agent-side code changes needed — just swap a base URL or env var; it implements the wire protocol for Anthropic Messages, Bedrock, Vertex, Microsoft Foundry, and OpenAI Chat Completions/Responses.
**Integration effort** — Low: `pip install veil-proxy`, runs on 127.0.0.1:8787.
**Maturity** — Experimental, explicitly alpha. 13 days old, single maintainer, unusually candid Limitations section (own disclosure that an agent with shell access could discover an unanticipated bypass).
**License** — Apache-2.0, no restrictions.
**Alternatives** — Microsoft Presidio (general redaction library, no agent-session pseudonym consistency or wire adapters); manual scrubbing (status quo).
**Why this one** — It's the first tool found doing *reversible*, deterministic pseudonymization specifically for coding-agent sessions, rather than one-way redaction that would break the agent's ability to act on the data.
**Recommendation** — Trial it on any session where an agent needs to touch data resembling real customer/client records; not yet a guaranteed compliance control given its alpha status.

### 2. Kanzo — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A kanban board and an MCP server in one 4.5 MB Rust binary: a human works the board in a browser, coding agents take tasks/move cards/comment over MCP, and a CLI is a third equal interface onto the same data. No account, no server process, no database.
**Why I should care** — Every self-hosted PM tool already in this catalog (Taskosaur, Kaneo, It's a Plan) is human-first with an API bolted on; kanzo is built the other way around, so an agent's task-taking and a human's watching are the same operation.
**What it could replace** — A hand-rolled "give my agent a task queue" setup, or a bespoke MCP wrapper around Linear/Trello/Jira.
**Ways I could use it** — a shared backlog a coding agent pulls from while I watch cards move in the browser; a Raspberry Pi as the always-on shared board for multiple laptops; marking tasks "Human" so agents leave them alone; a zero-setup personal kanban independent of the agent feature.
**Agent opportunity** — Native MCP server (`kanzo mcp`) with task-take/move/comment, auto-detecting the right project from a repo's git remote.
**Integration effort** — Low: one install command, published on crates.io, starts in ~2ms.
**Maturity** — Experimental. 9 days old, v0.3.0, 922 stars/58 forks/6 subscribers — a healthy ~16:1 stars:forks ratio for a repo this new, unlike the inflated-engagement cases flagged elsewhere.
**License** — AGPL-3.0, flagged loudly. Fine for personal/internal self-hosted use; a blocker only if ever offered as a hosted multi-tenant service to third parties.
**Alternatives** — Taskosaur, Kaneo, It's a Plan (human-first self-hosted PM tools already catalogued); Linear/Trello/Jira (proprietary).
**Why this one** — The MCP server, CLI and browser board are three equal clients of the same store from day one, not an afterthought.
**Recommendation** — Run it as a real task queue for one active coding-agent project for a week before trusting it further.

### 3. Kensaku — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A cross-platform local file-search launcher (Rust) indexing filenames, full text inside documents, OCR'd text inside images/screenshots, and semantic/natural-language queries. Nothing leaves the machine; ships a desktop app, a CLI, and an MCP server.
**Why I should care** — Everything, Listary and PowerToys Run only index filenames. Kensaku indexes content, OCRs images, and answers "the PDF about database indexing" — directly useful for an agent trying to locate a referenced file without being told the exact path.
**What it could replace** — The "which folder did I put that in" problem, and a from-scratch local-search MCP tool for an agent.
**Ways I could use it** — find a file by what was in it, not its name; search screenshots by OCR'd error text; give an agent MCP access to the filesystem by content; natural-language time filters on search.
**Agent opportunity** — MCP server over stdio or loopback-only HTTP; responses are size-budgeted and file content is returned as data, never as instructions.
**Integration effort** — Low once installed; unsigned builds mean an expected first-run security warning.
**Maturity** — Experimental. 10 days old, v1.0.12 (already several releases), 613 stars/44 forks/3 subscribers, 6 contributors with one dominant author.
**License** — MIT, no restrictions.
**Alternatives** — Everything (Windows, filenames only); Listary, PowerToys Run (filename/launcher only); Spotlight/mdfind (no OCR, no MCP).
**Why this one** — Content + OCR + semantic search + MCP in one tool is a combination none of the filename-only incumbents offer.
**Recommendation** — Install it against a real machine's file set for a week to judge real-world OCR/semantic quality before relying on it.

### 4. pngdeer — 7.4/10
**Decision:** PROTOTYPE

**What it is** — A lossy PNG/JPEG/AVIF/animated-PNG compressor (Rust) with no quality slider: searches palette sizes, scores results with the SSIMULACRA2 perceptual metric, and keeps the smallest file that still looks right. Same code runs as a CLI and as a browser WASM app.
**Why I should care** — It directly replaces a recurring TinyPNG subscription with an open-source tool that claims — and structurally can demonstrate, since the same code runs in-browser — 8-12% smaller files at equal perceptual quality.
**What it could replace** — A TinyPNG subscription, or manual per-image quality-slider guessing in an asset pipeline.
**Ways I could use it** — a CI image-optimization step before deploy; one-off screenshot/asset compression; batch AVIF/WebP conversion for a marketing site.
**Agent opportunity** — Shell-scriptable from CI or an agent's tool-call surface; no MCP server or library package yet.
**Integration effort** — Low: Homebrew tap or `cargo install`; embedding in a Node build pipeline today means shelling out to the binary, since no npm package was found.
**Maturity** — Experimental. 9 days old, latest tag v0.2.1 (no GitHub Release notes), 427 stars/39 forks/2 subscribers, 2 contributors (a company account plus an AI coding-assistant commit co-author).
**License** — MIT, no restrictions.
**Alternatives** — TinyPNG (proprietary, the explicit benchmark target); pngquant/oxipng/ImageOptim (open-source, claimed to be beaten on its measured leaderboard); Squoosh (manual quality slider).
**Why this one** — Automatic quality selection plus a reproducible, identical CLI/browser code path makes the comparison at least checkable rather than purely vendor-asserted.
**Recommendation** — Low-risk to trial directly against a real asset set and compare output sizes before swapping an existing pipeline step.

## Meaningful Updates

**Paseo** (getpaseo/paseo) — v0.14.0-beta.1 → v0.15.0. Previous state: cross-machine agent delegation over SSH/relay, still beta. Current state: daemon restarts now keep terminal programs running (agents survive a daemon crash/update instead of being killed), plus an opt-in "agent recovery" setting that resumes interrupted agents in their existing conversations after a host restart. Why it matters: a real reliability improvement for anyone running multi-host agent fleets — a daemon restart no longer means losing in-flight agent work. Does this change the recommendation: no, held at PROTOTYPE, score nudged 7.8 → 7.9. Catalog updated: Yes.

## Small but High-Leverage Utility
**nomore** — a local CLI that finds the corrections you keep repeating to Claude Code and turns them into evidence-backed CLAUDE.md rules, each traceable to a specific GitHub issue and its reaction count. It ships a ready-made 20-rule starter pack mined from roughly 8,000 ranked `anthropics/claude-code` issues — importable into any project's CLAUDE.md with one line — and a local miner (no LLM call required) for a given project's own repeated corrections. It's the closest thing found to an automated version of exactly the "watch for corrections, write down the rule" process this radar itself depends on. Single contributor, 10 days old, 0 forks despite 101 stars and 4 subscribers — worth tracking for independent adoption, but the starter pack alone is a near-free thing to try today.
