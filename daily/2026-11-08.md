# Open Source Radar — 2026-11-08
_Rotation slot 5 — self-hosted SaaS alternatives, productivity_

## Executive Summary
Today's slot surfaced a genuinely crowded wave of self-hosted CRM/sales-OS projects, and the
interesting part wasn't any single one of them — it was picking apart which ones are real. The
best two differ on stack fit and use case rather than overlapping: NextCRM is a close match for
my own stack with real invoicing/audit/vector-search depth; DeskcommCRM is narrower (WhatsApp
sales funnels) but is the more interesting case study — a project held out of the catalog six
weeks ago over single-maintainer and affiliate-promotion concerns that has since genuinely grown
into a 170-contributor project. Outside the CRM wave, textbee (self-hosted SMS gateway) is the
strongest pure product-building-block find of the day: a real Twilio alternative with an official
MCP server and multi-year track record.

## Today's Best Discoveries

### 1. textbee — 8.3/10
**Decision:** USE NOW

**What it is** — An open-source SMS gateway that turns an Android phone into a REST/webhook/MCP
SMS API: NestJS API + Next.js dashboard + Kotlin Android app in one repo, with official JS/Python
SDKs. A drop-in Twilio alternative — cost is whatever the SIM plan already costs, no per-message
billing, no number-rental compliance process.
**Why I should care** — Directly removes a recurring SaaS line item (Twilio/Vonage/MessageBird)
for OTP, alerts, reminders, and two-way SMS at low-to-moderate volume, on a NestJS backend that's
already in my stack rather than a black box.
**What it could replace** — Twilio/Vonage/MessageBird account setup and per-message billing;
building a custom SMS microservice from scratch for a side project or client product.
**Ways I could use it** — OTP/2FA for an early-stage product; two-way SMS support flows; an n8n
automation step; a cheap SMS channel for MSSP/PTaaS client notifications; bulk CSV-paced
announcement SMS.
**Agent opportunity** — Official MCP server (`textbee/textbee-mcp`) exposes send/read SMS as agent
tools directly; npm/PyPI SDKs for scripting.
**Integration effort** — Medium: the software side (REST/webhooks/SDKs) is low-effort, but it
needs a dedicated Android phone online 24/7 as the physical gateway.
**Maturity** — Mature: created March 2022, v2.9.0 (2026-09-21), 3,295 stars, 504 forks, active CI
across all three subprojects.
**License** — AGPL-3.0 — flagged: safe to run unmodified internally; a modified fork offered to
third parties over a network would trigger source-disclosure obligations.
**Alternatives** — Twilio, Vonage, MessageBird, Plivo; other Android-SIM-gateway projects exist
but without textbee's multi-year, multi-SDK, MCP-integrated ecosystem.
**Why this one** — Three years of real multi-platform iteration (API + dashboard + Android app +
SDKs + MCP server) rather than a weekend demo of the same idea.
**Recommendation** — Install for any project that needs OTP/alert/low-volume SMS and can spare an
Android phone — the integration effort is genuinely low once that one physical dependency is met.

### 2. NextCRM — 8.4/10
**Decision:** PROTOTYPE

**What it is** — An open-source CRM on Next.js 16, React 19, PostgreSQL (Prisma 7), and
shadcn/ui, with a full invoicing module, per-entity audit logging, pgvector semantic search, an
E2B-sandboxed AI research/enrichment agent, and a built-in MCP server for direct AI-agent access
to CRM data.
**Why I should care** — A CRM + invoicing + audit-log + vector-search stack built on exactly my
own stack (Next.js/React/Postgres/Prisma) is a substantial chunk of what a B2B tool or vertical
SaaS seed would otherwise need built from scratch, and it's readable/forkable rather than opaque.
**What it could replace** — Building CRM/invoicing/audit-log modules from scratch; a paid hosted
CRM where the data model needs to be owned or extended.
**Ways I could use it** — Internal sales/CRM tool on existing Postgres infra; forkable seed for a
vertical CRM product; reference implementation for exposing a Next.js app's data over MCP; a
lift-out reference for the multi-currency invoicing module.
**Agent opportunity** — Built-in MCP server with per-user hashed Bearer tokens and a downloadable
Claude Code Skill; an E2B-sandboxed browser-driven research agent with confidence-scored writes.
**Integration effort** — Medium: straightforward for core CRM; more setup once AI/vector-
search/MCP (OpenAI/Anthropic/Firecrawl/E2B keys) are wanted.
**Maturity** — Mature: created July 2023, 739 stars, 287 forks, v0.37.20 released today, with a
visibly active feature roadmap in the README's own changelog.
**License** — MIT, no restrictions.
**Alternatives** — Twenty, Odoo CRM, SuiteCRM (none on this stack with built-in MCP); hosted CRMs
(HubSpot, Pipedrive, Kommo); the also-catalogued DeskcommCRM (WhatsApp-specific, see below).
**Why this one** — Best stack fit of today's CRM wave, plus the most feature-complete single
codebase (invoicing, audit trail, vector search, MCP) under the most permissive license (MIT).
**Recommendation** — Spin up the Docker/demo path and test the MCP server and invoicing module
against a real internal use case before deeper adoption.

### 3. DeskcommCRM — 7.5/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted "AI sales OS" for WhatsApp: AI agents qualify, answer, and sell
inside a CRM/funnel inbox (Next.js 16, Supabase), connecting to WhatsApp via WAHA rather than the
official Meta Business API. Positioned as an open alternative to Kommo, Octadesk, and Intercom.
**Why I should care** — This is a direct callback: first observed 2026-09-27 and deliberately
held out of the catalog because it was a single maintainer's repo riding an affiliate-hosting
partnership (HostGator) to 4,058 stars in 5 months. Six weeks later it has 170 recorded
contributors, 5,268 stars, 1,506 forks, and a release shipped the day before this review — the
concern it was held for has genuinely decoupled from technical merit.
**What it could replace** — Kommo/Octadesk/Intercom-style WhatsApp CRM SaaS; a from-scratch
WhatsApp sales-funnel + AI-qualification build.
**Ways I could use it** — Self-hosted WhatsApp sales funnel for a small business/agency client;
reference for WAHA integration into a Next.js/Supabase app without Meta Business API approval
overhead.
**Agent opportunity** — End-user-facing AI sales agents (not a coding-agent tool); separately,
install guides auto-load into Claude Code/Codex/Cursor/OpenCode/Antigravity for conversational
self-hosted setup.
**Integration effort** — Medium: a one-command installer provisions Docker/WAHA/Supabase, but
WhatsApp connection and LLM-key setup are real operational steps.
**Maturity** — Emerging-to-mature: created April 2026 (7 months), but with real multi-contributor
depth now (170-contributor badge) rather than one person's commit log.
**License** — MIT.
**Alternatives** — Kommo, Octadesk, Intercom; the also-catalogued NextCRM (general-purpose, no
WhatsApp/AI-sales focus); WAHA itself (the underlying dependency).
**Why this one** — The growth-pattern story is the point: a project that looked like promotion-
driven hype in September now shows the contributor/release-cadence signals of a real project.
**Recommendation** — Worth testing specifically for a WhatsApp-sales-funnel use case; use NextCRM
instead for general-purpose CRM needs.

## Small but High-Leverage Utility
**Beancount.io** (bex-co/beancount-io) — a polished product layer (native iOS/Android apps, a
one-install CLI, web reports, confirm-gated AI-agent "skills") on top of plain-text double-entry
accounting via Beancount + Fava. The pitch leans toward the hosted beancount.io product, but
self-hosting via `deploy/docker/` is real, and the CLI alone (`brew install bex-co/tap/bea`) runs
fully local with zero account needed — a genuine upgrade over a spreadsheet for personal or
freelance bookkeeping, while keeping the ledger as a Git-diffable text file. MIT-licensed.

  appointment booking; only 47 stars and too thin to assess yet, but the "AI receptionist"
