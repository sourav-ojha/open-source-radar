# Open Source Radar — 2026-09-09
_Rotation slot 1 — AI agents, MCP, coding productivity_

## Executive Summary
Today's discovery surface was dominated by two enormous, near-simultaneous waves —
"persistent memory for AI coding agents" and "MCP/AI gateway with budgets" — each
returning 20-30 same-day, near-identical repos on a single GitHub search query. Cutting
through that noise, the real finds this run cluster around operational infrastructure
*for* coding agents rather than agents themselves: a queue/spend-cap/sandbox layer for
running an agent unattended (pi-dispatch), a governance control plane for agent tool
access and cost (Preloop), a tamper-evident decision ledger (Edda), a deterministic
call-graph context tool (ripwire), and a broad self-hosted SaaS-replacement bundle
(Temps). None quite clear the USE NOW bar yet — all are early-stage — but each solves a
specific, real operational gap rather than repackaging an already-solved problem.

## Today's Best Discoveries

### 1. Temps — 8.1/10
**Decision:** PROTOTYPE

**What it is** — a self-hosted, AI-native alternative to Vercel + Sentry + PostHog +
Pingdom + Resend + E2B in one Rust binary, with 440+ CLI operations and agent skills.
**Why I should care** — it targets "replace paid SaaS with something self-hosted"
across seven categories at once instead of one.
**What it could replace** — separate paid subscriptions for hosting, error tracking,
analytics/session replay, uptime monitoring, transactional email, and code sandboxes.
**Ways I could use it** — self-host for a side/client project instead of Vercel+Sentry+
PostHog; let an agent deploy and inspect traces via its own skill files; front LLM calls
through the built-in AI gateway with per-model cost attribution; run Claude Code/Codex/
OpenCode workflow sandboxes from inside the platform.
**Agent opportunity** — ships `.claude/skills`-compatible skill files for its 440+ CLI
operations, and injects MCP servers automatically into workflow sandboxes.
**Integration effort** — Medium: single-binary curl install is simple, but real adoption
means migrating several existing integrations (deploy, error tracking, analytics) at once.
**Maturity** — Emerging. GitHub's own release tag (v0.0.8, March) is stale/misleading —
real cadence is daily nightly builds and an actively-published npm CLI (0.1.36).
**License** — Apache-2.0, no restrictions.
**Alternatives** — Vercel, Sentry, PostHog, Pingdom, Resend, E2B (the seven it targets).
**Why this one** — replaces seven SaaS categories from one binary with a shared CLI and
agent-skill surface, a materially different integration story than seven separate tools.
**Recommendation** — prototype on a low-stakes project to test the deploy + error-
tracking + analytics path before trusting it with anything production-critical.

### 2. ripwire — 7.9/10
**Decision:** PROTOTYPE

**What it is** — a zero-dependency, single-binary C++23 CLI and MCP server that builds
a ranked, deterministic call graph of a repo (blast radius, tests to run) for coding
agents.
**Why I should care** — "figure out the codebase first" is one of the biggest hidden
token/time costs of agent-driven development; a precomputed map an agent queries instead
of exploring by hand is a direct reduction in both.
**What it could replace** — an agent grepping and reading whole files to understand
call relationships, and manual "which tests are relevant" triage.
**Ways I could use it** — pre-flight context for an agent before a change; blast-radius/
test-impact check before merging an agent-authored change; run as an MCP server so any
MCP client queries the graph directly.
**Agent opportunity** — CLI + native MCP server, no wrapper needed.
**Integration effort** — Low: no API key, no embeddings, single binary, wide language
support.
**Maturity** — Emerging, unusually fast traction (1,780 stars in ~6 weeks). Hosted under
Red Hat's experimental `redhat-et` org but effectively single-author (1,944 commits from
one contributor vs. single digits from the next seven). README leans heavily on
self-reported, self-verified benchmark claims.
**License** — Apache-2.0, no restrictions.
**Alternatives** — embedding-based codebase-RAG tools; trace-mcp (already catalogued,
framework-aware graph, different approach).
**Why this one** — a deterministic, non-embedding call-graph approach is a meaningfully
cheaper architecture than the embedding-heavy context tools dominating this space.
**Recommendation** — worth testing the call-graph and blast-radius claims hands-on;
don't take the README's self-checked benchmarks at face value.

### 3. Preloop — 7.8/10
**Decision:** PROTOTYPE

**What it is** — a self-hostable AI agent control plane: MCP firewall for tool access, a
model gateway for cost/attribution, policy-as-code with human approvals, and runtime
session observability.
**Why I should care** — agent tool-call governance (what can it touch, who approved it,
what did it cost) is tedious to build in-house and directly relevant to the MSSP/
security-admin-portal side of the work.
**What it could replace** — a bespoke MCP proxy with tool-call policy enforcement and
per-agent spend tracking.
**Ways I could use it** — front local coding-agent MCP traffic through the firewall
requiring approval for risky calls; get real per-agent/per-model cost attribution; use
security-audit presets as a starting point for lightweight client evidence collection.
**Agent opportunity** — `preloop agents discover` auto-onboards Claude Code, Cursor,
Codex CLI, and any MCP-compatible agent with one command.
**Integration effort** — Medium: low-friction CLI onboarding, but real value requires
routing all agent traffic through it.
**Maturity** — Emerging (v0.15.0), 7 contributors, two clearly dominant, active CI and a
published PyPI package. Real demo recordings against a live stack, not slideware.
**License** — Apache-2.0, no restrictions.
**Alternatives** — a bespoke in-house MCP proxy; LiteLLM/Portkey (cost gateway only, no
MCP firewall or approvals).
**Why this one** — combines an MCP firewall and a model-cost gateway with a policy/
approval layer in one platform, a narrower governance-focused pitch than the general MCP
gateway wave seen elsewhere today.
**Recommendation** — test `preloop agents discover` against a real local agent setup
before routing anything security-sensitive through it.

### 4. pi-dispatch — 7.6/10
**Decision:** PROTOTYPE

**What it is** — a self-hosted service that runs the `pi` coding agent on a schedule or
forge event, inside a locked-down ephemeral container, behind a durable queue and hard
spend caps, with a live admin panel.
**Why I should care** — "let a coding agent work unattended without surprise bills or
full machine access" is a real, unsolved gap in most agent CLIs, including `pi` itself
by its own README.
**What it could replace** — a custom-built job queue + container sandbox + spend-cap
layer around a coding agent.
**Ways I could use it** — run pi against GitHub issue/PR events with per-repo spend
caps; bake a project's toolchain into the job image for build-and-screenshot flows; use
the insights page to compare subscription vs. metered agent cost per flow/model.
**Agent opportunity** — this *is* the automation layer: any forge event or cron becomes
a bounded, sandboxed, cost-recorded agent run.
**Integration effort** — Medium: requires running a background service and maintaining
Docker job images, though the trigger/queue/budget model is well documented.
**Maturity** — Emerging (~2 months old), 173 stars, effectively solo-authored (427
commits from one author vs. 1 from a second contributor).
**License** — MIT, no restrictions.
**Alternatives** — building the same layer by hand; repurposed CI runners lacking
native spend caps and cost attribution.
**Why this one** — explicitly scoped to the queue/budget/sandbox problem around an
agent you already trust, rather than being yet another agent to evaluate.
**Recommendation** — wire it up against a low-stakes repo with a hard spend cap to
validate the claims before trusting it with anything unattended and consequential.

### 5. Edda — 7.2/10
**Decision:** PROTOTYPE

**What it is** — a local, tamper-evident, append-only ledger for coding agents:
decisions and cross-agent/session coordination state persisted in `.edda/`, plus a
cross-provider agent-review workflow.
**Why I should care** — two specific, recurring pains — re-litigating a decision after
the transcript compacts, and losing track of what a crashed parallel agent session
finished — get a durable, inspectable record instead of "ask the agent again."
**What it could replace** — re-explaining the same tradeoff across sessions; manually
reconstructing a crashed session's progress; a custom cross-provider review workflow.
**Ways I could use it** — keep a durable "why we chose X" record; run parallel agent
sessions with crash recovery; `edda review --agent pi --model ...` for a second-provider
review of a branch with recorded findings and cost.
**Agent opportunity** — works with Claude Code, Cursor, Codex, OpenClaw, and any MCP
client; the cross-provider review command is itself an orchestration primitive.
**Integration effort** — Low: local CLI via `cargo install edda`, no server required.
**Maturity** — Emerging but disciplined. Solo-authored (705 commits) but the issue
tracker shows real engineering rigor — the project dogfoods its own "fleet" coordination
tooling and tracks its own test flakiness as first-class bugs.
**License** — Dual MIT/Apache-2.0 (GitHub API detects only Apache-2.0; repo ships both).
**Alternatives** — ad-hoc CLAUDE.md/AGENTS.md notes (no tamper-evidence); mex (already
catalogued — codebase knowledge, not a decision/coordination ledger).
**Why this one** — the agent-memory space is extremely crowded right now; Edda is
differentiated by scope — a decision/coordination ledger, not generic semantic recall.
**Recommendation** — try it on a project with heavy parallel-agent use to see if the
decision-ledger and crash-recovery claims hold up.

## Small but High-Leverage Utility
**DeckProbe** (deckflow/deckprobe) — "ffprobe for documents": a Rust CLI + browser WASM
SDK that probes PDF, Microsoft Office, and Apple iWork files for structural facts (page
count, slide count, etc.) without opening them, returning deterministic JSON with
confidence and evidence. Apache-2.0, ships an agent skill and an MCP server out of the
box, and reads as unusually polished for a repo that's only 5 weeks old — clean CI, 0
open issues, a real target vocabulary and budget-enforcement model instead of an ad hoc
wrapper around a parsing library. Filed as a utility rather than a full catalog entry
because it's still young and narrow, but worth knowing about as a fast preflight check
before handing a document to a heavier parser, OCR pipeline, or model.

## Worth Watching
- **amux** (mixpeek/amux) — an open-source control plane for running parallel Claude
  Code/Codex/Gemini coding-agent workers with a shared task board, 425 stars, real
  multi-contributor activity. Held back this run because its license is MIT *plus
  Commons Clause*, which bars reselling amux itself as a hosted service (internal or
  embedded use is unrestricted) — and because its "orchestrate multiple coding agents"
  scope overlaps enough with pi-dispatch (above) that a full side-by-side review didn't
  fit this run's budget. Worth a direct comparison against pi-dispatch next time either
  resurfaces.
- **inite-brain-service** (inite-ai/inite-brain-service) — a bitemporal knowledge-graph
  memory server for AI agents with GDPR "forget" support, REST + native MCP. The
  bitemporal-graph approach is architecturally distinct from the vector-store memory
  tools flooding this space, but it's AGPL-3.0 and surfaced in the middle of a massive
  same-day "agent memory" duplicate wave (see Rejected below) — would need to clearly
  outperform the vector-based options to justify a full review given the AGPL flag.

## Run Notes

agent," "agent memory," "mcp gateway"), GitHub REST API for repo/release/contributor/
license metadata on 8 deep-reviewed candidates plus an 18-repo existing-catalog release
spot-check, `raw.githubusercontent.com` for README and LICENSE file verification

Algolia (`search_by_date` on "MCP agent" and the `show_hn` tag). GitHub rate limit
headroom: comfortable throughout (8,350/hr, well under 150 requests used). HN Algolia
again returned mostly low-point toy/hobby posts by raw score, but one low-point post
("ripwire: ripgrep of AI context") led to a legitimate 1,780-star repo — a reminder to
keep cross-checking low-point HN posts against the GitHub API rather than filtering on
points alone. GitHub search sorted by "updated" on broad terms continues to return
20-30 same-day, near-identical repos per query (see Rejected) — this is a persistent
signal-to-noise problem for broad terms specifically that narrower/qualified queries
don't have. No sources were unreachable this run. No "Still Worth Trying" section —
oldest catalog entries are 11 days old, short of the 14-day threshold.
