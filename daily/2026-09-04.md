# Open Source Radar — 2026-09-04
_Rotation slot 3 — developer utilities, debugging, testing_

## Executive Summary
Today's finds cluster tightly around one specific pain point: the friction of relying on AI coding agents at real scale. Four new catalog entries each attack a different piece of it — losing session history across agent runs (**ctx**), losing execution-tree visibility into a custom TS agent (**AgentInspect**), re-explaining a codebase to an agent every single session (**mex**), and not being able to independently verify an agent's own claim that a security fix worked (**DvalinCode**). None of these are "AI wrapper" noise; each is infrastructure for people who already use coding agents heavily, which fits this slot's developer-tooling focus squarely. Separately, **Bernstein** (catalogued 2026-08-30) shipped a release that reframes it from a deterministic agent orchestrator into a full governance/audit framework for AI agents — directly strengthening its MSSP/PTaaS relevance.

## Today's Best Discoveries

### 1. ctx — 8.4/10
**Decision:** USE NOW

**What it is** — A local-first CLI that indexes past coding-agent session transcripts (Claude Code, Codex, etc.) already on disk, so agents can search prior decisions and failed approaches instead of repeating investigation from scratch. A paid "ctx pro" add-on layers "git blame, but for agent sessions" on top.
**Why I should care** — Directly solves the "agent repeats work every session because its history is buried in unreadable log files" problem that comes with heavy daily coding-agent use.
**What it could replace** — grepping raw `~/.claude` JSONL logs by hand or via a script (the project's own benchmark claims ~50x more tokens for the same recall via raw search).
**Ways I could use it** — recover why code exists when picking up a stale branch; hand a fresh session the real prior investigation instead of a re-discovery loop; search across parent/subagent/forked sessions when orchestrating multiple agents; audit what an agent did across weeks of history.
**Agent opportunity** — built for agent-to-agent handoff — `ctx search`/`ctx blame` are meant to be called by the agent itself, not just a human.
**Integration effort** — Low. One install script, fully local, no account for the core CLI.
**Maturity** — Emerging (1,062 stars, created Feb 2026, 19 contributors, 3,500+ commits, versioned releases).
**License** — Apache-2.0 for the core CLI. **"ctx pro" (the actual blame feature) is a separate closed-source paid companion, $20/mo** — flagged loudly since it's easy to assume the whole tool is free.
**Alternatives** — raw log grepping (status quo); ad hoc transcript-dump scripts.
**Why this one** — it's the first tool seen here that treats agent session history as a first-class, locally-indexed, agent-searchable asset rather than a log to be discarded.
**Recommendation** — install and run `ctx setup` on the current machine; evaluate the paid blame tier only after the free tier proves useful.

### 2. mex — 8.1/10
**Decision:** PROTOTYPE

**What it is** — A repo-local "living wiki" for a codebase, maintained by AI coding agents. Builds a deterministic Tree-sitter + SQLite code graph across TS/JS/Python/Rust (with Express route-to-handler awareness) and routes only relevant context into an agent's session, with drift checks when a refactor invalidates a wiki claim.
**Why I should care** — Directly fits a MERN/TS stack, including explicit Express awareness, and targets the exact failure mode of a bloated CLAUDE.md/AGENTS.md file that floods context and goes stale.
**What it could replace** — a single giant instruction file; agents re-scanning an entire repo every session.
**Ways I could use it** — pilot on one active MERN/TS repo; let it maintain architecture/decisions/conventions as reviewable Markdown; rely on `mex check`/`mex sync` to catch stale docs after a refactor; use it as an internal-tool pattern for keeping agents grounded on a larger MSSP admin-portal codebase.
**Agent opportunity** — installs first-class Claude Code and Codex skills on setup; the whole context-routing design targets agent consumption.
**Integration effort** — Low (`npx mex-agent setup`), though the MCP server package is not yet published — build from source if that surface specifically is needed.
**Maturity** — Emerging (1,541 stars, created March 2026, 16 contributors, 493 commits, active Discord, i18n).
**License** — MIT, no restrictions.
**Alternatives** — one giant instruction file (status quo); mainstream agent-memory tools that compact facts into lossy summaries rather than grounding claims in a deterministic code graph (different niche from catalogued LightAgent/LightMem, which target conversational/task memory).
**Why this one** — the deterministic code-graph grounding plus drift detection is a materially different approach from "agent memory" as usually pitched.
**Recommendation** — pilot on one repo across a few real refactors to see if drift detection actually holds up before rolling out broadly.

### 3. DvalinCode — 7.9/10
**Decision:** PROTOTYPE

**What it is** — Independent security verification for code written by humans or AI agents. Re-scans and re-runs a project's own tests/checks itself, reading exit codes rather than asking the model that made a fix whether it worked, and issues an offline-verifiable "Verified Fix Record."
**Why I should care** — Heavy coding-agent use means fixes — including security fixes — often get accepted on the agent's own say-so. This is directly relevant to the MSSP/PTaaS side of the business, where "prove it" evidence matters more than a confident claim.
**What it could replace** — manually re-running scans/tests after every agent-authored security fix; trusting an agent's self-report.
**Ways I could use it** — gate PRs containing AI-agent-authored fixes on an independently re-run check; run the zero-config baseline scan (injection/secrets/XSS/eval/unsafe shell) before wiring in semgrep; attach a Verified Fix Record to a PR or incident as client-facing evidence; use `diff: true` in CI to gate only what a PR newly introduces.
**Agent opportunity** — has a built-in remediation executor that can call Claude Code/Codex/Copilot, but deliberately never consults the agent that wrote a fix when verifying it; interoperates with other systems via portable SARIF.
**Integration effort** — Low. `npx dvalincode security scan .` runs with no install, no API key, no network calls for the built-in ruleset; drop-in GitHub Action for PRs.
**Maturity** — Emerging (113 stars, created May 2026, 12 contributors, 298 commits, 442/442 tests badge, OpenSSF Scorecard badge). Polished for its age but still an early, single-dominant-author project.
**License** — MIT, no restrictions.
**Alternatives** — trusting the agent's own claim (status quo); Semgrep/CodeQL alone (find findings, don't verify a remediation); Codex Security (Dvalin interoperates via SARIF rather than competing).
**Why this one** — the "never ask the model that wrote the fix" design is exactly right for a world where agents both introduce and "fix" findings, and the record format is genuinely re-verifiable offline.
**Recommendation** — try it on one repo's PR pipeline specifically for AI-agent-authored fixes.

### 4. AgentInspect — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A local-first evidence and trajectory-testing toolkit for TypeScript AI agents: readable execution trees, deterministic CI trajectory checks, and redacted evidence bundles, all from one captured local trace.
**Why I should care** — Relevant if/when building a custom agent product on the AI SDK, LangGraph, or OpenAI Agents JS, rather than only using off-the-shelf coding agents.
**What it could replace** — eyeballing raw console logs to debug a custom agent; a hosted tracing account just to see what an agent did.
**Ways I could use it** — debug a failing custom TS agent locally; gate CI on deterministic trajectory checks instead of manual log review; produce a redacted, hash-verified evidence bundle for a PR or incident; adopt a framework adapter if building on LangGraph/AI SDK/OpenAI Agents JS.
**Agent opportunity** — exposes a `TraceContract` API for programmatic trajectory analysis an orchestrator could call in its own CI gate.
**Integration effort** — Medium — useful only once an agent is actually instrumented, unlike a drop-in CLI.
**Maturity** — Emerging (499 stars, created May 2026, 16 contributors, 958 commits, extensive docs with explicit Stable/Beta/Experimental surface labeling).
**License** — MIT, no restrictions.
**Alternatives** — hosted tracing platforms like LangSmith/LangFuse (catalogued Laminar is a similar hosted-adjacent alternative); `console.log` and eyeballing (status quo).
**Why this one** — local-first, no-account debugging plus deterministic CI trajectory gating is a real gap for anyone shipping a custom agent, not just observing one.
**Recommendation** — adopt the moment a custom TS agent product moves from prototype to something with a CI pipeline.

## Small but High-Leverage Utility
**mcpwatch** ([Sreelal727/mcpwatch](https://github.com/Sreelal727/mcpwatch)) — `npx @sreelal727/mcpwatch audit` starts every MCP server already configured, measures the actual token cost of its tool definitions, and prints an itemised bill: which server is eating the most context before a word gets typed, and which of its tools have never been called. In one command it turned up a github MCP integration burning ~10,700 tokens *every session* on tool definitions that were never invoked in the observed window — a config-file deletion's worth of savings that would otherwise be invisible. Genuinely novel niche (no other catalogued tool measures MCP token overhead), MIT licensed, npm-published at v0.3.0 with CI and tests. Not catalogued yet — the GitHub repo is one day old with 0 stars and no tagged release, which is too thin to fully vouch for per the "be cautious with very new repositories" rule, but worth running once given how cheap the check is (`npx`, no config, no account).

## Worth Watching
- **stackradar-cli** ([lockdep/stackradar-cli](https://github.com/lockdep/stackradar-cli)) — a single static binary that answers "which of my running Kubernetes pods have a known CVE" against OSV and CISA's Known Exploited Vulnerabilities catalogue, with no cluster-side agent. Well-engineered for its age (cosign-signed releases, careful docs on exactly what leaves the laptop) and a direct fit for AWS EKS plus the MSSP/PTaaS context, but only 5 commits and 3 stars — needs a few more weeks of real-world use and at least one more tagged release before it's worth a full review.
- **QAMap** ([IvoryCanvas/QAMap](https://github.com/IvoryCanvas/QAMap)) — reads a PR diff and repo structure to propose an evidence-backed QA plan (affected flows, boundary/failure scenarios, cited to exact changed lines) without making its own LLM call. 22 stars, 212 commits, npm-published, ChatGPT/Codex plugin integration — reasonably built out, but the project's own docs call it "early and pre-1.0," and static-analysis-driven test-scenario suggestions have a real risk of confident-but-wrong output. Would need a track record of catching real gaps (not just plausible-sounding ones) to justify adoption.
- **noisefloor** ([ahmed-hashim-pro/noisefloor](https://github.com/ahmed-hashim-pro/noisefloor)) — a regression harness for non-deterministic systems (LLM/RAG agents): runs a target N times, measures the run-to-run spread, and only calls a delta a "regression" once it clears the measured noise floor. Directly useful for anyone building AI agent evals, but two days old, 0 stars, one worked example (a RAG agent against claude-sonnet-4-6). Would need broader real-world validation beyond the single example to be worth adopting.
