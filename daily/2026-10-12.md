# Open Source Radar — 2026-10-12
_Rotation slot 6 — infrastructure, observability, deployment_

## Executive Summary
The strongest find today sits one category over from the slot's core (product infrastructure): Artifact Keeper, a 45-format artifact registry that credibly competes with Artifactory under MIT. Within the slot itself, two self-hosted orchestration tools stood out for directly replacing paid SaaS he'd otherwise pay for — Terraducktel (a self-hosted Terraform Cloud/Spacelift) and redStackPRO (a topology-to-Terraform compiler for authorized red-team/cyber-range infrastructure, directly relevant to the PTaaS side). A fourth, Stashbase, is outside the slot but too good to skip: a request-level proxy that keeps real secrets out of a coding agent's reach entirely. Also noted a short-lived two-entrant "Vector fleet control plane" wave (Vectory, VortexFLOW) that hasn't produced a clear winner yet, and a genuinely novel but very early dual-wire-protocol (Elasticsearch + Loki) log search engine (rSearch) worth re-checking once it has more than one contributor.

## Today's Best Discoveries

### 1. Artifact Keeper — 8.5/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted, Rust-built universal artifact registry speaking the native wire protocol of 45+ package formats (Maven, npm, PyPI, Docker/OCI, Cargo, Go, Helm, NuGet, RPM/Deb, HuggingFace, and more), with Trivy/Grype security scanning built into every upload and a stated JFrog Artifactory migration path.
**Why I should care** — Artifactory/Nexus are the realistic options once a team needs more than one package-format registry, and both get expensive at scale. Artifact Keeper covers almost the same format surface under MIT, with scanning inline rather than bolted on.
**What it could replace** — A paid Artifactory/Nexus Pro license; separate single-purpose registries (private npm, Docker registry, PyPI mirror) run as independent services.
**Ways I could use it** — Private npm/PyPI/Maven registry for internal packages; self-hosted Docker/OCI registry with scan-on-push as an ECR+scanner alternative; migrating an existing Artifactory instance off its license; writing a custom WASM handler for an in-house package format.
**Agent opportunity** — No MCP server; a coding agent could drive the REST API for publish automation like any registry.
**Integration effort** — Medium: Docker Compose with Postgres (+ optional OpenSearch), no Kubernetes/Helm packaging yet.
**Maturity** — Emerging but substantial: 74 contributors, 154 forks, 1,123 stars, created January 2026, active weekly releases (v1.10.2). 6,400+ backend unit tests claimed, but no explicit production-readiness statement.
**License** — MIT. No restrictions on commercial or embedded use.
**Alternatives** — JFrog Artifactory, Sonatype Nexus (proprietary), Harbor (OCI-only, no multi-format coverage).
**Why this one** — Real contributor base and format breadth, not a thin single-format clone; direct Artifactory-migration tooling makes the SaaS-replacement case concrete rather than theoretical.
**Recommendation** — Prototype against one real internal package feed (e.g., a private npm registry) before trusting it with release-critical artifacts.

### 2. Terraducktel — 7.9/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted Terraform and Helm orchestrator (FastAPI + React + Postgres + ephemeral Docker executors) that reproduces Terraform Cloud/Spacelift's plan → approval gate → apply → drift-detection workflow.
**Why I should care** — Terraform Cloud/Spacelift/env0 charge per-seat for exactly this workflow, on infrastructure (AWS + Terraform) he already runs. This is the same workflow self-hosted under MIT.
**What it could replace** — A Terraform Cloud/Spacelift subscription; ad hoc "approve in a Slack thread before applying" processes; cron scripts that `terraform plan` on a schedule and post drift to Slack.
**Ways I could use it** — Gated plan/apply pipeline for AWS + Kubernetes infra; scheduled drift detection with chat alerts; Helm diffs through the same approval flow; GitHub-webhook-triggered plans on PR open.
**Agent opportunity** — No MCP server, but the REST API is a plausible target for an agent that proposes infra changes and files them as gated runs instead of applying directly.
**Integration effort** — Medium: Docker Compose only, and the API needs `/var/run/docker.sock` access to spawn executors — a real privilege tradeoff to weigh, not a minor detail.
**Maturity** — Pre-1.0 (v1.4.0, four releases in one week). 4 contributors, 19 stars, 11 open issues. The maintainers themselves flag real-AWS apply as "in flight," and ship a dev admin credential that must be rotated.
**License** — MIT.
**Alternatives** — Terraform Cloud, Spacelift, env0 (proprietary targets); Atlantis (open-source, PR-comment-driven, but no built-in UI/RBAC/drift worker).
**Why this one** — Nothing else in the catalog currently covers this specific "self-hosted Terraform Cloud" niche, and the feature list (approval gates, drift detection, OIDC SSO, audit log) is a direct, line-item match for what the SaaS alternatives charge for.
**Recommendation** — Run it against a sandboxed, non-production AWS account first — the docker.sock privilege and unproven real-AWS apply path are real, not cosmetic, caveats.

### 3. redStackPRO — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A visual canvas for composing red-team/cyber-range infrastructure as a topology, compiling to a self-contained Terraform+Ansible export (~200 files) deployed by the operator; covers offensive C2 labs (Sliver/Mythic) and defensive AD ranges (including GOAD), with the tool itself never holding cloud credentials.
**Why I should care** — Standing up a cyber range or authorized C2 lab by hand means writing and maintaining Terraform/Ansible for networking, jumpboxes, and per-tool provisioning every time — exactly the kind of prep work that eats a day before a PTaaS engagement or AD-lab training session starts.
**What it could replace** — Hand-written Terraform/Ansible per engagement; ad hoc tracking of what credentials/implants are planted where.
**Ways I could use it** — Authorized internal red-team practice lab; GOAD-based AD range for defensive training; agent-driven topology validation/compile via the REST API.
**Agent opportunity** — The `serve`/`validate`/`compile` API is explicitly designed for an automated agent to drive independent of the GUI.
**Integration effort** — Medium: single Docker container, but the generated export needs to actually be read (credentials, VPN setup) before running `deploy.sh`.
**Maturity** — Pre-1.0 beta (v0.9.1). Solo maintainer, org created 2026-09-25 — 141 stars/16 forks in about two weeks is fast enough traction for a brand-new security tool that it's worth re-checking in a few weeks rather than treating as settled.
**License** — MIT core; bundled GOAD lab templates remain GPLv3 with attribution (relevant only when redistributing those specific templates).
**Alternatives** — Hand-rolled Terraform/Ansible per engagement (status quo), Ludus, direct use of GOAD/Detection Lab templates without a compiling layer on top.
**Why this one** — The "export is the boundary" design (no credentials held by the tool, schema-validated compile, scrubbed deploy logs) is a genuinely careful approach to a dual-use problem, not just a convenience wrapper.
**Recommendation** — Strictly for authorized lab/engagement use; treat the README's authorized-use-only scoping as load-bearing. Try it in a throwaway lab account before a client engagement, given the solo-maintainer status and two-week age.

### 4. Stashbase CLI — 7.5/10
**Decision:** PROTOTYPE

**What it is** — A local access-control layer for coding agents (Claude Code, Codex, Cursor): a localhost proxy substitutes placeholders for real secrets only on approved hosts/methods/paths, denies reads of sensitive files and writes to `.git`, strips disallowed MCP tools from discovery entirely, and can monitor/revoke remote agent sessions mid-run.
**Why I should care** — Outside today's slot, but directly on the AI-agent-leverage axis: a coding agent session today typically has unrestricted access to whatever secrets sit in its environment, with enforcement only at the prompt level. Stashbase makes that an actual policy boundary.
**What it could replace** — Pasting real API keys into an agent's `.env`/environment during a session; the absence of any audit trail for what hosts an agent actually called.
**Ways I could use it** — Run an agent against a project touching a payment or internal-admin API with only placeholders visible to it; scope a session's `egress_hosts` tightly; scan agent-triggered package installs for compromised packages; hand off a long session to a teammate with revoke power.
**Agent opportunity** — This is itself agent-security infrastructure; the MCP-tool-denial-at-discovery detail is worth copying in any custom MCP server exposed to third parties.
**Integration effort** — Low for basic proxying; Medium if relying on the sandboxing backends across a mixed-platform team (Intel Mac unsupported, Windows needs WSL2).
**Maturity** — Early-stage and unusually candid about its own limits: the docs state the native backend is "not a security boundary against a malicious process running as the same user." Open-core — some features need a paid plan. 12 stars, actively committed.
**License** — Apache-2.0 for the CLI; open-core beyond that.
**Alternatives** — Generic secrets managers (Infisical, Vault, 1Password CLI) that deliver real values rather than policing requests; Cynative (already catalogued — a different control point, pre-checking planned IAM actions rather than live-proxying requests).
**Why this one** — Request-level scoping by host/method/path plus MCP-tool-discovery filtering is a more complete model than "don't paste secrets into the prompt," and the maintainers are honest about where the boundary currently is and isn't.
**Recommendation** — Try it on one real session that touches a sensitive API; take the native-backend caveat at face value rather than assuming Docker-level isolation by default.

## Small but High-Leverage Utility
**loki-vl-proxy** (ReliablyObserve/loki-vl-proxy, Apache-2.0, 46 stars) is a 14MB Go binary that sits between Grafana and VictoriaLogs, translating LogQL into LogsQL so Explore, Logs Drilldown, dashboards, and live tail all work against a VictoriaLogs backend through an existing Loki datasource with zero plugin changes. VictoriaLogs is dramatically cheaper to run than Loki at the same ingest volume, and this proxy is the piece that lets a team actually migrate without touching every dashboard and alert rule that currently points at a Loki datasource. It's unusually well-tested for its size — 8,561 passing tests, 87.6% coverage, a multi-tier cache, circuit breakers, and documented compatibility gaps rather than a blanket "100% compatible" claim — which is the kind of honesty that's rare in a self-reported-benchmark README.

## Worth Watching
- **rSearch** (ZerosAndOnesLLC/rSearch) — A Rust log search engine that speaks both the Elasticsearch/OpenSearch *and* Loki wire protocols simultaneously (Tantivy-backed, single static binary, no JVM). Genuinely novel positioning — a drop-in replacement regardless of whether a team's tooling expects Kibana-style or Grafana-Loki-style queries — but only 2 stars, 1 fork, GPL-3.0, and no sign of more than one contributor. Would need real-world usage reports and a second contributor before it's more than an interesting architecture note.
- **cloudflare-sts** (cf-contrib/cloudflare-sts) — A Security Token Service for Cloudflare: trades a CI job's OIDC token for a short-lived, least-privilege Cloudflare API token or R2 credential instead of a long-lived `CLOUDFLARE_API_TOKEN` sitting in CI secrets. Cloudflare has no native equivalent to AWS STS, so this fills a real gap — but it's 0 stars, created two weeks ago, and needs a track record before trusting it with CI credentials.
- **Vector fleet control planes (Vectory, VortexFLOW)** — Two independent, same-month attempts at a self-hosted control plane for managing a fleet of Vector (vector.dev) instances — pipeline design, versioned releases, fleet-wide deployment. Neither has more than 6 stars yet, and neither is differentiated enough from the other to pick a winner. Worth checking back once one of them has actual users.
