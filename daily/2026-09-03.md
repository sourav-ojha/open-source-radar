# Open Source Radar — 2026-09-03
_Rotation slot 2 — product infrastructure, APIs, backend components_

## Executive Summary
Today's GitHub search firehose for "webhook"/"admin panel"/"feature flags"/"job queue"
was almost entirely same-day noise — dozens of 0-star scaffolds and tutorial repos with
near-identical descriptions, several clearly AI-generated in bulk. Underneath it, three
things held up to inspection: a mature TypeScript/Vue admin-panel CLI (AdminForth), a
modular Postgres-native BaaS with a built-in MCP server (Rebase), and — outside the usual
MERN/AI-agent axis but directly relevant to the MSSP side of the business — a self-hosted
MSP documentation/PSA platform positioned as an IT Glue/Hudu replacement. Also confirmed a
real, security-relevant release: Kingfisher (already catalogued) shipped GitHub App auth
and expanded cloud blast-radius analysis.

## Today's Best Discoveries

### 1. AdminForth — 8.3/10
**Decision:** USE NOW

**What it is** — A TypeScript + Vue admin-panel framework: `npx adminforth create-app --db <url>`
against an existing Postgres/MySQL/Mongo/SQLite/ClickHouse database scaffolds a full CRUD
back-office in minutes, extended with Vue components, custom Express routes, and plugins
(audit log, file/image upload, TOTP 2FA, i18n, Copilot-style AI writing).
**Why I should care** — Every SaaS product needs an internal admin UI and it's almost
always hand-built and then neglected; this generates one from the schema already in use
(Postgres/Mongo) instead.
**What it could replace** — The recurring "build another internal CRUD admin" task, and
possibly a Retool subscription for internal tooling.
**Ways I could use it** — Scaffold a back-office for the MSSP admin-portal or a new
micro-SaaS MVP; give support/ops staff a safe CRUD UI instead of DB access; use the
built-in audit-log/2FA plugins instead of building access control from scratch; prototype
an AI-assisted back-office via the writing/image-generation plugin.
**Agent opportunity** — CLI (`adminforth resource`/`component`) is scriptable by a coding
agent; no dedicated MCP server found despite "agentic" framing in the README — treat that
claim as unverified.
**Integration effort** — Low. CLI-driven scaffolding against an existing schema; deploys
as a normal Node/Express app anywhere Node runs.
**Maturity** — Mature. Created 2024-05-20, 391 stars, 26 forks, active release cadence
(v3.17.1, 2026-08-31).
**License** — MIT. No cloud-subscription gate.
**Alternatives** — React-admin, Retool, Directus, Payload CMS, AdminJS, Refine.
**Why this one** — CLI-first scaffolding directly against an existing schema, plus a
first-party plugin set, rather than composing several separate packages.
**Recommendation** — Install and scaffold against a real project's schema as a first test.

### 2. Rebase — 7.7/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted, Postgres-native backend-as-a-service: REST, typed SDK,
auth, S3-compatible storage, realtime, backups, and row-level security over your own
Postgres, with an opt-in schema-driven admin panel and a built-in MCP server. Three
modular adoption modes: BaaS, CMS, Full.
**Why I should care** — Targets the same job as Supabase but stays modular and
Postgres-only — no forced control plane, no dozen containers just to get REST + auth +
storage.
**What it could replace** — Hand-written REST/auth/storage/realtime glue for a new
product, and the operational overhead of running a full Supabase self-hosted stack when
only a subset is needed.
**Ways I could use it** — Stand up a Postgres-backed REST+auth+storage layer for a new
micro-SaaS MVP; use typed SDK codegen to keep frontend/backend types in sync; run the
static RLS audit before trusting row-level security on a customer-facing table; point a
coding agent at a live schema through the MCP server.
**Agent opportunity** — First-party MCP server (`@rebasepro/mcp`) exposes schema
discovery, entity management, and migrations to AI coding agents directly.
**Integration effort** — Medium. Modular adoption keeps footprint small, but it's still
new infrastructure to run (`docker compose up -d db` + CLI).
**Maturity** — Emerging. Created 2026-03-30 (~5 months), 8 stars, pre-1.0 (v0.17.3), but
active weekly-ish releases, CI/npm-downloads badges, and a Discord.
**License** — MIT.
**Alternatives** — Supabase self-hosted (heavier stack), PocketBase (SQLite, not
Postgres), Directus, Payload CMS, NHost.
**Why this one** — Postgres-only, modular by default, MCP-native out of the box — none of
the mainstream alternatives combine all three.
**Recommendation** — Stand up in BaaS mode for a small side project to evaluate the
REST/auth/storage layer and the MCP server hands-on before trusting it with anything
production-critical.

### 3. Client St0r — 7.0/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted MSP/IT documentation and PSA platform (Django 6 +
MariaDB): asset management, encrypted password vault, knowledge base, tickets, projects,
contracts, quotes, invoices, and a customer portal. Positioned as an open-source IT
Glue/Hudu alternative.
**Why I should care** — This is a secondary-context find (MSSP admin-portal side of the
business, not the core MERN/AI-agent axis) but a directly applicable one: it's a working
replacement for the per-seat SaaS category (IT Glue, Hudu) an MSSP practice would
otherwise pay for.
**What it could replace** — A recurring IT-documentation/PSA SaaS subscription, or the gap
of not having that tooling at all.
**Ways I could use it** — Self-host as the documentation/PSA layer for the MSSP practice;
use the encrypted vault + asset management as a lighter alternative to a general secrets
manager for client credentials; study the ticket-to-invoice PSA workflow and
customer-portal pattern as a reference architecture for the MSSP admin-portal SaaS's own
client-facing surface.
**Agent opportunity** — README lists an "AI assist" feature with no implementation detail
— unclear based on available documentation.
**Integration effort** — Medium. Different stack (Django/MariaDB) from the primary
MERN/Node stack, but it runs as a standalone app rather than an embedded library, so the
mismatch matters less.
**Maturity** — Emerging. Created 2026-01-10 (~8 months), 71 stars, 19 forks, marked
"production ready" by its own README; note a version-tag drift worth checking before
deploying (README badge 3.17.444 vs. latest tag v3.17.495).
**License** — MIT.
**Alternatives** — IT Glue and Hudu (proprietary, per-seat, the incumbents it targets);
ITFlow (another open-source option, not directly compared here).
**Why this one** — Bundles PSA (tickets/projects/contracts/quotes/invoices) alongside
documentation in one self-hosted app rather than documentation alone.
**Recommendation** — Trial-deploy to evaluate against whatever the MSSP practice currently
uses (or lacks) for client documentation and PSA.

## Small but High-Leverage Utility
**Liteque** — a small, typesafe, SQLite-backed job queue for Node.js/TypeScript, extracted
from the Karakeep self-hosted bookmarking app (MIT, 78 stars, actively released). Most
Node job-queue options assume Redis or Postgres is already running; Liteque needs neither
— just a SQLite file, a typed queue, and a runner with retries and Zod-validated payloads.
For a small service or micro-SaaS side project that doesn't otherwise need a database
beyond SQLite, this removes an entire piece of infrastructure (and its ongoing cost) just
to get background jobs with retries. Not a replacement for Sidequest (already catalogued,
USE NOW) where multi-node coordination or a web dashboard is actually needed — but for
the smallest-footprint version of a project, it's the right size tool.

## Worth Watching
- **javimosch/bkn** — a single-binary backend core (document store, KV, auth, files,
  events, cron, webhooks, sandboxed JS runtime over embedded SQLite) explicitly pitched as
  "agent-first, no admin UI." The concept is directly on-thesis, but the repo is literally
  hours old (created 2026-09-03), 0 stars, no README yet. Needs a real README, at least one
  tagged release, and some usage evidence before it's worth a second look.
- **powabase-ai/powabase** — packages the standard self-hosted Supabase stack plus an AI
  service layer (sources, knowledge bases, agents) behind one `docker compose up`. The data
  plane is the unmodified upstream Supabase self-hosted stack, so the only real
  differentiator right now is the single-project deployment convenience and an early,
  unproven AI layer. Would become interesting if the AI service layer matures into
  something clearly differentiated from just running Supabase directly.
- **stablemates/workhorse** — a Postgres-native durable job queue with TypeScript, Python,
  and Go workers sharing one queue via versioned SQL functions, with transactional
  enqueue guaranteed by the same Postgres transaction as the triggering write. The
  cross-language angle is genuinely differentiated from Sidequest (already catalogued,
  Node-focused), but it's public beta, 7 stars, ~6 weeks old, and has no tagged release
  yet. Worth another look once it ships a 1.0 or at least a first tagged release.
