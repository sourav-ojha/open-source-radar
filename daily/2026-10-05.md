# Open Source Radar — 2026-10-05
_Rotation slot 6 — infrastructure, observability, deployment_

## Executive Summary
The headline finding this run wasn't a new project — it was a status change on an existing one. `localstack/localstack` now shows `archived: true` via the GitHub API (no commits since 2026-03-23), closing out the de facto standard for local AWS development. That single fact reopened an entire category: three credible drop-in replacements have emerged in its place (Floci, MiniStack, kumo), each taking a different technical bet on how to emulate AWS locally. Beyond that wave, today's research also surfaced a very new but unusually complete self-hosted MongoDB backup/DR tool, an AGPL-licensed RMM+PSA platform relevant to the MSSP side of the business, and a zero-config entity-resolution library whose marketing-heavy README is worth treating with some skepticism despite genuinely useful design.

## Today's Best Discoveries

### 1. Floci — 8.5/10
**Decision:** USE NOW

**What it is** — A free, open-source local AWS emulator (MIT) built as a direct, same-port drop-in replacement for LocalStack.
**Why I should care** — LocalStack is archived; Floci covers the exact AWS surface used day to day (S3, EC2, ECR, Lambda, SQS, IAM, EB, ALB, EKS) with an explicit migration guide and zero code changes.
**What it could replace** — LocalStack itself, or any hand-rolled "mock the AWS SDK" test setup.
**Ways I could use it** — Local dev/test against S3/DynamoDB/SNS/SQS; CI integration tests without a real AWS bill; Terraform/CDK dry runs; EKS/ECS/ALB architecture prototyping; same vendor also ships Azure/GCP/OCI emulators if infra work expands.
**Agent opportunity** — No MCP server, but trivially scriptable into an agent-driven CI/test loop (spin up, run tests, tear down).
**Integration effort** — Low — swap the Docker image, same API surface.
**Maturity** — Emerging-to-mature: ~7 months old, 100 contributors, continuous commit activity, v2.1.0 tagged, Docker Hub image.
**License** — MIT, no feature gates found anywhere in the docs.
**Alternatives** — MiniStack (different architecture, see below), kumo (Go-native, smaller scope).
**Why this one** — Highest adoption (26.3k★, 2.8k forks — fork ratio supports organic growth) and most direct migration path of the three alternatives found.
**Recommendation** — Install it wherever a LocalStack-based Docker Compose file currently exists.

### 2. MiniStack — 8.0/10
**Decision:** PROTOTYPE

**What it is** — A second free local AWS emulator (MIT, Python), architecturally distinct from Floci: RDS/ElastiCache/ECS run against *real* Postgres/MySQL/Redis/Docker containers instead of in-process mocks.
**Why I should care** — Same LocalStack-archival trigger, but a genuinely different trade-off — pick this one when test fidelity for a specific stateful AWS service matters more than raw footprint.
**What it could replace** — LocalStack, specifically for workloads that need real database/cache behavior under the hood.
**Ways I could use it** — RDS-backed integration tests needing genuine Postgres semantics; local Bedrock prototyping proxied to a local model server; multi-account/multi-region local testing.
**Agent opportunity** — Internal `/_ministack/*` API (health, reset, inspect SES/SQS messages) is useful for agent-driven test automation.
**Integration effort** — Low-medium — real-infra services need the Docker socket mounted.
**Maturity** — Emerging: ~7 months old, 100 contributors, frequent releases (v1.5.21).
**License** — MIT.
**Alternatives** — Floci (broader adoption, lighter), kumo (Go-native).
**Why this one** — The only one of the three backing stateful services with real engines rather than mocks.
**Recommendation** — Prototype specifically where RDS/ElastiCache/ECS fidelity is the deciding factor; otherwise default to Floci.

### 3. GoldenMatch — 7.5/10
**Decision:** PROTOTYPE

**What it is** — A zero-config entity-resolution library (MIT; Python, with TS/WASM and native SQL support) that merges duplicate/messy records into "golden records" without hand-written rules or a trained model.
**Why I should care** — Merging duplicate customer/contact records from multiple sources is a recurring, genuinely hard problem; this packages auto-tuned matching behind a one-line call and exposes the chosen config for reuse.
**What it could replace** — Hand-rolled fuzzy-matching dedup logic, or the need to learn/tune Splink before getting usable results.
**Ways I could use it** — Dedup a CRM export before migration; power a "possible duplicate" review queue in an admin panel; clean multi-source data before analytics.
**Agent opportunity** — Claims an MCP server and 70+ MCP tools (not independently verified this review).
**Integration effort** — Low for the Python/CSV path.
**Maturity** — Emerging: v3.22.0 on PyPI, active CI, published benchmarks — but small community (132★, 1 watcher) and a sprawling family of same-maintainer sibling packages.
**License** — MIT.
**Alternatives** — Splink (far more production track record, requires manual tuning).
**Why this one** — Zero-config operation with an inspectable, reusable matching config is the real differentiator from Splink.
**Recommendation** — Try it directly on one real messy dataset before trusting the headline "beats Splink" claim — the README leans hard on marketing language and unverified benchmarks.

### 4. MongoRescue — 7.4/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted MongoDB backup/DR tool (MIT, single Go binary): streaming `mongodump`/`mongorestore`, checksum-verified and automated-restore-tested backups, safe-clone restores by default, encryption, a dashboard, CLI, REST API, and an MCP server.
**Why I should care** — MongoDB is core to the MERN stack; this replaces fragile hand-rolled `mongodump` cron scripts with something that actually proves backups restore, and lets an agent check backup health directly via MCP.
**What it could replace** — Hand-rolled backup/cron scripts; a case for not needing MongoDB Atlas just to get managed backups.
**Ways I could use it** — Scheduled encrypted backups to S3-compatible storage; automated restore-tests; CI backup/restore scripting with stable exit codes.
**Agent opportunity** — Native MCP server (Streamable HTTP and stdio) with scoped API keys and its own audit log — one of the more complete "MCP as a first-class interface" designs seen recently.
**Integration effort** — Low — one Docker container or binary.
**Maturity** — **Very new** — created 10 days before this review, 6 stars, 0 forks, 0 watchers, but with daily tagged releases (v0.1.0 → v0.18.0) and a feature set well beyond typical for its age.
**License** — MIT.
**Alternatives** — Hand-rolled scripts, MongoDB Atlas backup (Atlas-only), Percona Backup for MongoDB.
**Why this one** — The only MongoDB-specific, self-hosted backup tool found with a dashboard, verified restores, and an MCP server in one package.
**Recommendation** — Worth experimenting with, but treat as pre-production — no independent community validation exists yet for a project this young.

### 5. Breeze — 7.0/10
**Decision:** PROTOTYPE

**What it is** — An open-source RMM + PSA platform (AGPL-3.0) for MSPs/internal IT with an AI operator built into every page: monitoring, patching, remote access, scripting, ticketing, quoting, and billing in one system.
**Why I should care** — Secondary-context fit via the MSSP security admin-portal SaaS and PTaaS partnership: unifies RMM and PSA (no separate billing-sync step) with a risk-classified AI-operator design worth studying regardless of adoption.
**What it could replace** — Running separate RMM + PSA tools with a sync job between them; commercial incumbents (Atera, NinjaOne, ConnectWise).
**Ways I could use it** — Device fleet monitoring/patching for managed endpoints; unified ticket-to-invoice billing; branded client portal; AI-assisted alert triage with human approval gating.
**Agent opportunity** — Internal AI-operator design (per-page agent, risk-classified tool access, dangerous actions gated behind human approval) is a reusable pattern for adding safe agentic actions to any admin product.
**Integration effort** — Medium — full platform deploy (Postgres, Redis, Go agent distribution).
**Maturity** — ~9 months old, 126 stars, 43 forks, active release cadence, published security whitepaper mapped to SOC 2.
**License** — **AGPL-3.0 — flagged.** Self-hosting for internal use is fine; reselling a modified instance to clients would trigger the network-use source-disclosure clause.
**Alternatives** — Atera, NinjaOne, ConnectWise (closed-source, per-seat); Tactical RMM (open, GPL, RMM-only).
**Why this one** — RMM+PSA unification and AI-operator-as-first-class-citizen design, not a bolted-on chatbot.
**Recommendation** — Worth a closer look through the MSSP lens; resolve the AGPL hosting question before any commercial redistribution.
