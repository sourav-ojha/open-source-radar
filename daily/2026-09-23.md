# Open Source Radar — 2026-09-23
_Rotation slot 1 — AI agents, MCP, coding productivity_

## Executive Summary
Today's slot-1 pass surfaced a cluster of genuinely differentiated agent-orchestration tooling rather than another wave of near-identical "coding agent CLI" repos: two takes on "manage many coding agents across machines" (Imbue's `mngr`, CLI-first and infra-light; Paseo, a polished self-hosted desktop/web/mobile product), one that extends agent verification to mobile/cross-platform UI (Callstack's `agent-device`), and one that hands agents general infrastructure operation across hosts (AgentDock). The coding-agent-CLI niche itself (Kimi Code, pi_agent_rust) stayed crowded with no standout differentiation strong enough to clear the bar against already-catalogued VTCode.

## Today's Best Discoveries

### 1. agent-device — 8.5/10
**Decision:** PROTOTYPE

**What it is** — Callstack's CLI + MCP server + typed Node.js API that lets AI coding agents drive and verify iOS/Android/HarmonyOS/tvOS/web/macOS/Linux apps via accessibility-tree snapshots and ref-based actions.
**Why I should care** — Coding agents currently have no reliable way to verify UI changes beyond reading source; this closes that loop for mobile/cross-platform work specifically, with real production usage at Expensify and a public Shopify mention.
**What it could replace** — Manual "build, tap through, eyeball it" verification after agent-generated UI changes; one-off Appium/Detox scripts written just to let an agent check its own work.
**Ways I could use it** — Verify React Native UI changes against a real simulator before opening a PR; automated screenshot/video evidence on agent-authored PRs; drive cross-platform QA flows from one CLI; coordinate parallel agent workstreams against a device pool.
**Agent opportunity** — CLI, bundled stdio MCP server, and a Node.js client for custom orchestration; works out of the box with Claude Code, Codex, Cursor, Cline, and other MCP clients.
**Integration effort** — Medium: the CLI installs in minutes, but real use needs simulators/emulators or device access already set up.
**Maturity** — Emerging (created Jan 2026) but with confirmed production usage, active daily commits, real CI, v0.21.12.
**License** — MIT, no commercial-use restrictions.
**Alternatives** — Appium, Detox, XCUITest/Espresso directly — none purpose-built for token-efficient AI-agent consumption.
**Why this one** — Backed by a credible React Native consultancy with public evidence of real-world use, not a demo.
**Recommendation** — Prototype it against a React Native/cross-platform project's next agent-authored UI change.

### 2. mngr — 8.1/10
**Decision:** PROTOTYPE

**What it is** — Imbue's Unix-style CLI for running many coding agents (Claude Code, Codex, any CLI agent) in parallel across local machines, Docker containers, remote hosts via SSH, or Modal — "git for agents" lifecycle (`create`/`list`/`connect`/`message`/`push`/`pull`/`clone`/`destroy`).
**Why I should care** — Running more than one or two agents at once quickly turns into ad hoc SSH tabs and tmux panes; this gives that a real, vendor-agnostic interface without adopting a managed platform.
**What it could replace** — Hand-rolled SSH/tmux juggling across EC2 boxes or containers; vendor lock-in to a single coding-agent's own orchestration UI.
**Ways I could use it** — Fan out agents across EC2 boxes for parallel, independent tasks on a MERN monorepo; keep a long-running agent working in the background and check in periodically; standardize agent lifecycle across a team regardless of which CLI agent each person prefers.
**Agent opportunity** — This is the orchestration layer itself — CLI-first, plugin-extensible, no managed service required.
**Integration effort** — Low-Medium: trivial install (pip/curl script), but value requires already having remote hosts/containers to fan out to.
**Maturity** — Emerging (created Jan 2026, active daily). No tagged GitHub release; PyPI package lags `main` by several months — track `main` directly.
**License** — MIT (confirmed via raw LICENSE file; GitHub API shows NOASSERTION only due to a subfolder-override preamble, not a licensing difference).
**Alternatives** — tmux/SSH scripts (status quo), Paseo (below), previously-catalogued Preloop.
**Why this one** — Stays a thin CLI over primitives (SSH, git, tmux, Docker) already trusted and debuggable, rather than a new platform.
**Recommendation** — Prototype fanning out 2-3 agents across local Docker containers before trusting it with remote fleets.

### 3. Paseo — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted control plane for running coding agents (Claude Code, Codex, Copilot, OpenCode, Pi) in parallel, with desktop, web, mobile (iOS/Android), and CLI clients all talking to a local daemon, plus voice control and an E2E-encrypted relay for phone pairing.
**Why I should care** — This is a working example of exactly the "manage agents from my phone" product this radar's mission explicitly flags as a product-opportunity signal — not a mockup, a shipping self-hosted product with real community traction.
**What it could replace** — Staying tied to a desk to monitor long-running agent tasks; vendor-specific orchestration UIs.
**Ways I could use it** — Start a task at a desk, steer it from a phone; voice-dictate tasks; self-host on a home server or AWS box over Tailscale for a persistent dev environment; compare multiple agent providers on the same task through one interface.
**Agent opportunity** — Full multi-provider agent-orchestration product; plugin system adds new providers/commands/panels without forking.
**Integration effort** — Low: one Docker command or a downloaded desktop app; needs at least one agent CLI already installed and credentialed.
**Maturity** — Emerging (created Oct 2025) but fast-moving: 18k+ stars, weekly release cadence, multi-contributor activity consistent with genuine maintenance rather than star-farming.
**License** — Apache-2.0, confirmed via LICENSE file. GitHub's API misreports this as NOASSERTION due to a non-standard file preamble — the actual terms are unrestricted Apache-2.0.
**Alternatives** — mngr (above, CLI-only), stagewise-io/stagewise and RunMaestro/Maestro (AGPL agent-orchestration IDEs, seen this run, not deep-reviewed).
**Why this one** — Genuinely cross-device (native mobile, not just responsive web) in a space where most competitors are desktop/CLI-only.
**Recommendation** — Self-host the Docker daemon against a low-stakes project and try the mobile-pairing flow directly.

### 4. AgentDock — 7.6/10
**Decision:** PROTOTYPE (with caution)

**What it is** — An MCP-based tool runtime (no chat UI, no model inference) giving AI agents controlled file, shell, Git, Skill, MCP, and browser-automation access across local computers, remote servers, and containers, with multiple instances coordinating cross-device workflows in one conversation.
**Why I should care** — Directly targets the AWS/EC2 multi-host operational context in this profile — inspect logs, run Git ops, and coordinate multi-host deploys from a chat interface instead of switching SSH sessions.
**What it could replace** — Manual SSH-session switching between dev/staging/prod-adjacent boxes; one-off scripts exposing a VPS's Docker/reverse-proxy state to an LLM session.
**Ways I could use it** — Inspect remote logs/processes/ports from a chat interface; run Git operations directly in the environment the app actually runs in; coordinate multi-host deploys from one conversation.
**Agent opportunity** — Pure MCP tool-runtime infrastructure, extensible via Skills and dynamic MCP servers.
**Integration effort** — Medium-High: installs easily, but safe deployment requires deliberately scoping permission boundaries before pointing a chat interface at real infrastructure.
**Maturity** — Emerging: Docker Hub pulls, a Trendshift trending badge, v0.8.3, active international community (English + Chinese-language channels).
**License** — Apache-2.0, no commercial-use restrictions.
**Alternatives** — Direct SSH + a coding agent's own shell tool, mngr/Paseo (coding-agent-lifecycle focused rather than general infra operation).
**Why this one** — Purpose-built for general infra operation (files/shell/Git/Docker/reverse-proxy/deploy) rather than agent-lifecycle management specifically.
**Recommendation** — Trial against a disposable sandbox/VM first — this grants real command/file/Git execution on real machines, which is a materially larger blast radius than typical dev tooling, and worth extra caution given the MSSP/PTaaS secondary context.

## Worth Watching

Genuinely well-engineered (1,773 stars, active daily, v0.5.1) but functionally overlaps with already-catalogued VTCode in the coding-agent-CLI niche; would need a clearer differentiator than "faster startup, no unsafe code" to clear the bar over an existing catalog entry.

Apache-2.0, 937 stars, actively maintained (v1.4.1). Architecturally interesting but macOS-only limits fit for this profile; worth another look if a cross-platform build appears.
