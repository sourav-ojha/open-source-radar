# Open Source Radar — 2026-09-18
_Rotation slot 3 — developer utilities, debugging, testing_

## Executive Summary
Today's discovery run leaned into agent-debugging infrastructure: two independent, mature MCP servers now expose *real* step-through debuggers (breakpoints, stepping, variable inspection) to coding agents, one headless enough to run inside a Kubernetes pod. Alongside that, a genuinely novel "time-travel" recorder/replayer for whole agent runs turns "why did the agent do that" into a reproducible artifact instead of a re-run-and-guess exercise. The most immediately useful find, though, is unglamorous: a battle-tested hook that blocks the exact class of destructive-command mistakes (`git reset --hard`, `rm -rf`, `DROP TABLE`) this operating spec itself warns about, across every major coding-agent CLI. Rounding it out, a codebase-intelligence platform consolidates docs generation, dead-code detection, and agent-context retrieval behind one local index, with a disclosed benchmark rather than a marketing number. The GitHub Search API surfaced heavy noise today — dozens of near-identical "coding agent CLI," "agent memory," and "codebase understanding" repos pushed within the same 24-hour window — none of which cleared the bar over what's already catalogued or rejected.

## Today's Best Discoveries

### 1. Destructive Command Guard (dcg) — 8.6/10
**Decision:** USE NOW

**What it is** — A high-performance hook that blocks destructive commands (`git reset --hard`, `rm -rf`, `DROP TABLE`, `kubectl delete namespace`, `aws ec2 terminate-instances`, `docker system prune`, and more) before an AI coding agent can execute them.
**Why I should care** — This is precisely the failure mode this radar's own operating rules exist to prevent, and it's a near-zero-effort install.
**What it could replace** — Manual vigilance reviewing every agent-proposed command for the catastrophic, hard-to-reverse subset.
**Ways I could use it** — Install against Claude Code/Codex/Copilot/Cursor today; use per-agent trust profiles to tune allowlists; run its CI scan mode on PRs; use `dcg explain` before running an uncertain command by hand.
**Agent opportunity** — Itself a `PreToolUse`-style hook across ~13 coding-agent harnesses — agent-safety infrastructure, not just a tool for agents to call.
**Integration effort** — Low: one signed installer script wires up whichever agents are detected.
**Maturity** — Mature for its age: ~6,000 stars, created January 2026, very active, 50+ rule packs.
**License** — MIT License with an OpenAI/Anthropic Rider (custom). Voids the license only for OpenAI, Anthropic, and their affiliates — no effect on ordinary individual or commercial use.
**Alternatives** — Dicklesworthstone/slb (same author, "two-person rule" peer-approval CLI) is complementary rather than competing; otherwise the status quo is trusting the agent.
**Why this one** — Broadest agent-harness coverage of anything in this space, signed cross-platform releases, and sub-millisecond SIMD-accelerated classification rather than a naive regex blocklist.
**Recommendation** — Install it today against whatever coding agent is the daily driver.

### 2. mcp-debugger — 8.3/10
**Decision:** USE NOW

**What it is** — A headless MCP server exposing real step-through debugging (breakpoints, stepping, variable inspection, expression evaluation) across eight languages via the Debug Adapter Protocol, with no IDE required.
**Why I should care** — Runs wherever the bug actually lives — a Docker container, a Kubernetes pod, a CI runner — which matches how backend services on an AWS/EKS-heavy stack actually get debugged, unlike IDE-bound alternatives.
**What it could replace** — The print-statement debugging loop agents default to; and, for remote/headless targets, the human need to reproduce a bug locally just to attach a real debugger.
**Ways I could use it** — Attach to a misbehaving EKS pod and hand the live session to an agent; auto-debug a failing CI test via the provided GitHub Action; set logpoints on a hot path without pausing a live process; debug a containerized Node/Python service with no VS Code involved.
**Agent opportunity** — Purpose-built MCP tool surface with secret redaction on by default, plus a companion Agent Skill teaching root-cause debugging discipline.
**Integration effort** — Low — `npx @debugmcp/mcp-debugger`; per-language toolchains needed for full coverage.
**Maturity** — Emerging — pre-1.0 (v0.24.2), created June 2025, CI + OpenSSF Scorecard/Best Practices badges.
**License** — MIT, no restrictions.
**Alternatives** — microsoft/DebugMCP (510 stars, MIT) does the same thing but requires a running VS Code instance and cannot attach to CI/K8s/remote processes.
**Why this one** — The only one of the two that works in a container, a Kubernetes pod, or a CI runner rather than only inside a live VS Code window.
**Recommendation** — Install and try against a real containerized service the next time something needs stepping through remotely.

### 3. Repowise — 8.0/10
**Decision:** PROTOTYPE

**What it is** — Indexes a codebase's dependency graph, git history, tests, docs, and architectural decisions once, then answers cited questions, computes diff blast-radius, scores code health, flags dead code, and generates always-current docs via CLI, MCP, editor views, PR analysis, and a local dashboard.
**Why I should care** — Consolidates a docs generator, a change-impact tool, manual architecture-decision records, and an agent-context layer into one local index, with a published benchmark methodology rather than a bare claim.
**What it could replace** — A bespoke combination of separate docs, dead-code, and impact-analysis tooling most teams maintain by hand.
**Ways I could use it** — Feed an agent cited context instead of letting it re-derive architecture every session; compute blast radius and run only the tests a diff exercises; find dead code and defect-prone files before a refactor; auto-generate documentation from the same index.
**Agent opportunity** — MCP tools specifically built to cut agent "rediscovery" overhead — its disclosed benchmark claims 3.8 vs. 7.2 tool calls and 393 vs. 13,984 tokens for an equivalent task (n=43, method published).
**Integration effort** — Medium — `pip install repowise`, more moving parts than a single CLI (dashboard, MCP server, PR analysis), though all local.
**Maturity** — Emerging — 6 months old, 6,696 stars with a real multi-contributor team, 217 open issues (active, not fully settled).
**License** — AGPL-3.0 for the self-hosted core, or a commercial license. **Flagged loudly**: hosting a modified version as a network service requires releasing source under AGPL unless the commercial license is purchased.
**Alternatives** — mex (catalogued) is a narrower drift-checked living wiki without the code-health/dead-code/PR-analysis layer; ripwire (catalogued) is deterministic code-graph context without the git-history/decision-tracking layer.
**Why this one** — Broader scope than either catalogued alternative, plus a disclosed benchmark rather than a marketing number.
**Recommendation** — Index a real repo with it to evaluate the agent-context and code-health claims firsthand before deciding self-host-under-AGPL vs. commercial license for anything customer-facing.

### 4. coding-agent-search (cass) — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A unified TUI/CLI that indexes and searches local session history across 20+ coding-agent harnesses (Codex, Claude Code, Gemini CLI, Cursor, Aider, Copilot, and more) into one searchable timeline.
**Why I should care** — Working across multiple coding-agent CLIs scatters "what was tried and why" across incompatible log formats; this normalizes all of them.
**What it could replace** — Manually scrolling terminal scrollback or exporting each tool's own siloed history.
**Ways I could use it** — Search "what did I ask Claude Code to do about that regression last week"; point an agent at cass in robot mode so it can search prior session history for context; audit which harness produced a specific past change.
**Agent opportunity** — Explicit "robot mode" (`--robot --json`, `capabilities --json`) designed from the start to be queried by another agent.
**Integration effort** — Low — prebuilt binary via installer script, Homebrew, or Scoop.
**Maturity** — Experimental — explicitly labeled alpha.
**License** — MIT License with an OpenAI/Anthropic Rider (same clause and author as Destructive Command Guard).
**Alternatives** — Grepping raw session logs by hand, or each agent's own non-cross-searchable built-in history.
**Why this one** — Broadest harness coverage (20+) of anything addressing this specific gap.
**Recommendation** — Worth trying if regularly switching between more than one or two coding-agent CLIs; treat as a convenience layer given alpha status.

### 5. OrcaReplay — 7.6/10
**Decision:** PROTOTYPE

**What it is** — Records a coding agent's full execution at the process/socket boundary and replays it byte-for-byte offline with no model called, or forks the run from any step onto a different model to compare outcomes.
**Why I should care** — Turns "why did the agent do that" from re-running and guessing into a deterministic, inspectable artifact — nothing else catalogued does step-level model forking.
**What it could replace** — Re-running the same prompt and hoping for the same failure; SDK-wrapper-based observability tools that require code changes and still can't reproduce byte-for-byte.
**Ways I could use it** — Reproduce exactly what an overnight agent session did without burning tokens; fork a run at the step it went wrong onto a cheaper model to see if the mistake was model-specific; capture and diff the actual system prompt a harness assembles across models.
**Agent opportunity** — Captures below the agent, at the process/socket boundary, so it works even for agents that hold their own API credentials and can't be modified.
**Integration effort** — Low — `npm i -g orcareplay`, no server required.
**Maturity** — Experimental — three weeks old, but built by a team with an existing commercial product (OrcaRouter) behind it.
**License** — Apache-2.0 for code; trace spec under CC BY 4.0.
**Alternatives** — Catalogued LLM observability tools (Langfuse-style, Opik, Laminar) report cost/tokens but not deterministic replay or model forking.
**Why this one** — The only entrant with deterministic byte-for-byte replay and mid-run model forking rather than post-hoc cost/token observability.
**Recommendation** — Trial it the next time a coding-agent session does something inexplicable; too new for USE NOW given no track record yet.
