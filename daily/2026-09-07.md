## Today's Best Discoveries

### 1. Dagu — 8.5/10
**Decision:** USE NOW

**What it is** — A local-first workflow/DAG engine: single self-hostable binary, built-in Web UI, no external database or message broker. Define DAGs in declarative YAML that wrap existing shell commands, Docker containers, Kubernetes Jobs, or SSH commands unmodified.
**Why I should care** — Cron gives no dependencies/retries/history. Airflow gives that but forces you to operate a second platform and rewrite jobs into its task model. Dagu keeps orchestration as config next to scripts that already work.
**What it could replace** — Ad hoc cron jobs, a from-scratch Airflow deployment, hand-rolled retry/logging wrappers around scripts.
**Ways I could use it** — ETL/dbt pipeline scheduling with observability; multi-step SSH maintenance/deploy scripts across a small fleet; self-service diagnostics UI for non-engineers; GitHub-event-triggered private automation; ffmpeg batch jobs with parallel fan-out.
**Agent opportunity** — Ships a built-in MCP server for inspecting/controlling workflows and runs — usable directly as an agent tool.
**Integration effort** — Low. Single binary or Docker, no external DBMS/broker required.
**Maturity** — Mature. Created 2022, 3,841 stars, 88 contributors, v2.16.2 released 2026-09-02.
**License** — GPL-3.0. Not AGPL/SSPL, but still copyleft — fine for internal ops use, needs review before embedding/redistributing in a shipped product.
**Alternatives** — Apache Airflow, Temporal, n8n, plain cron.
**Why this one** — Zero external infrastructure and zero rewrite of existing scripts; the architecture explicitly optimizes for "orchestration is not your main job."
**Recommendation** — Install and trial as a cron/Airflow replacement for internal automation.

### 2. Duckle — 7.6/10
**Decision:** PROTOTYPE

**What it is** — Open-source ETL/ELT platform: author pipelines visually or in Python/SQL on a desktop canvas, ship the same file to run headless on your own server (`duckle-runner serve`). Compiles to SQL executed by DuckDB.
**Why I should care** — No vendor cloud, no per-row billing, no lock-in; pipelines are single git-tracked files. Claims 96M rows Postgres→Parquet in 39.9s (unverified independently, but plausible given DuckDB's known performance).
**What it could replace** — Hand-rolled Node/Python ETL scripts; a paid managed-ETL SaaS for routine data movement.
**Ways I could use it** — Scheduled data-sync/export jobs with an audit trail; reverse-ETL to a CRM; feeding a RAG pipeline via its 190 built-in connectors; giving non-engineers a visual pipeline canvas for recurring reports.
**Agent opportunity** — Built-in MCP server for Claude/Cursor to inspect or modify pipelines directly; also ships a sandboxed local AI assistant with no fs/net/tool access.
**Integration effort** — Medium. Authoring requires a Tauri desktop app; execution is a separate headless runner/Docker image — more moving parts than a pure CLI tool.
**Maturity** — Emerging/beta. Created 2026-05, 1,271 stars, 10 contributors, explicitly labeled beta.
**License** — Dual MIT OR Apache-2.0 (confirmed via LICENSE-MIT/LICENSE-APACHE files). No restrictions.
**Alternatives** — Airbyte, dlt, Meltano, n8n (not ETL-optimized).
**Why this one** — Git-based pipeline files plus DuckDB compilation is a genuinely different shape than warehouse-metered competitors.
**Recommendation** — Prototype on a real recurring export/reverse-ETL task before anything production-critical.

### 3. Pipewright — 7.5/10
**Decision:** PROTOTYPE

**What it is** — A single static Go binary combining CI, multi-server deployment (agentless SSH), and container/server ops — a one-tool alternative to Jenkins or the Drone+Ansible+Portainer trio. Includes a visual DAG pipeline canvas, auto-HTTPS reverse proxy, per-PR preview environments, and DORA metrics.
**Why I should care** — The self-hosted deploy-platform space is crowded (a ~15-repo Coolify-alternative wave was rejected here on 2026-08-31), but Pipewright also does CI rather than assuming it exists elsewhere, and the auto-HTTPS/per-PR-preview pieces remove real recurring setup work.
**What it could replace** — A manual GitHub Actions + SSH-deploy-script + Caddy/nginx stitched-together setup; hand-configured ephemeral PR environments.
**Ways I could use it** — Multi-server zero-downtime deploys with rollback; environment promotion chains with approval gates; container/host ops from one dashboard; optional AI-assisted failure diagnosis (BYO key, fully degradable).
**Agent opportunity** — Optional AI assist for root-cause diagnosis and natural-language-to-shell in the ops terminal; core CI/CD path doesn't depend on it.
**Integration effort** — Low. Single static binary; Docker only needed for isolated builds/container deploys.
**Maturity** — Emerging. Created 2026-05-30 (~3 months old), 34 stars, 2 contributors — unusually complete feature set for the age, actively committed as recently as 2026-08-29.
**License** — MIT (confirmed via LICENSE file). No restrictions.
**Alternatives** — Jenkins, Drone+Ansible+Portainer, Coolify, Dokploy.
**Why this one** — Broader scope (CI + deploy + ops + HTTPS in one binary) than the already-rejected Coolify-alternative wave, which only did deployment.
**Recommendation** — Trial on a non-critical project given the low contributor count and short track record.

### 4. Shelve — 7.4/10
**Decision:** PROTOTYPE

**What it is** — Centralized secrets/environment-variable management: encrypted vault, CLI (`shelve run`) that injects secrets without `.env` files, GitHub Actions/repo-secrets sync via a GitHub App, RBAC, self-hostable server.
**Why I should care** — Solves the universal multi-environment-Node-project problem (scattered `.env` files) with decent CLI DX and native GitHub Actions sync, and — unlike Doppler/1Password — is self-hostable.
**What it could replace** — Manually passed `.env` files; per-repo manual GitHub secrets updates; a paid Doppler/Infisical Cloud subscription.
**Ways I could use it** — Centralize secrets across dev/staging/prod for MERN projects; `shelve pull`/`push` in CI instead of manually maintained secret files; time-limited secure secret sharing instead of DMs.
**Agent opportunity** — None built-in — contrast with Sigillo (below), which is purpose-built around agent-safe secret redaction.
**Integration effort** — Low. npm CLI install, self-hosted server or hosted shelve.cloud.
**Maturity** — Emerging-to-mature. Created Feb 2024, 453 stars, 15 contributors, "Production Ready" per own status table; CLI v5.3.0 released 2026-08-17, repo pushed 2026-09-03.
**License** — Apache-2.0. No restrictions.
**Alternatives** — Doppler, Infisical, 1Password for Developers, platform-native env management (Vercel/Netlify), Sigillo.
**Why this one** — Self-hostability plus native GitHub Actions sync is the differentiator against the hosted-only incumbents.
**Recommendation** — Prototype for centralizing secrets across personal/small-team projects; verify self-hosting friction hands-on first.

## Small but High-Leverage Utility
**RunWisp** — a single Go binary replacing `crond` and `supervisord`. Define scheduled jobs and long-running services in one `runwisp.toml`; it captures exit code, duration, and full stdout/stderr for every run, browsable in a web dashboard, TUI, or REST API, with live log streaming. GPL-3.0, 43 stars, zero runtime dependencies, Docker image available. The specific pain it removes — SSH-ing into a server at 3am to figure out why a cron job silently failed — is exactly the kind of recurring 20-minute-per-incident cost this radar exists to catch. Not catalogued (overlaps conceptually with Dagu, which is the fuller-featured pick when dependencies/DAGs are needed) but worth knowing about for the narrower "just tell me what my cron jobs are doing" case.

## Worth Watching
- **Sigillo** (self-hostable secrets manager, remorses/sigillo) — genuinely novel angle: redacts secrets from process stdout/stderr so they never leak into an AI agent's context window (`sigillo run -- next dev` instead of sourcing `.env`). MIT claimed in the README but **no LICENSE file exists in the repo** — needs the maintainer to fix this before it's trustworthy to adopt. Also self-hosting is specifically tied to Cloudflare Workers + D1, not a generic Docker self-host. Revisit if a LICENSE file lands and/or a non-Cloudflare-specific self-host path appears.
- **rk8s** (rk8s-dev/rk8s) — a lightweight, Kubernetes-compatible container orchestrator written in Rust implementing the actual CRI, with Docker Compose-style multi-container support. Architecturally interesting (559 stars, Apache-2.0) but pushed_at is drifting toward 6+ weeks stale at review time — watch for renewed activity before treating it as more than a study item.
- **Regen** (FluidifyAI/Regen) — self-hosted PagerDuty/incident.io alternative with AI-generated postmortems and 1-click migration from Grafana OnCall (now archived) — directly relevant to the MSSP/PTaaS secondary context. **AGPLv3** — flagged loudly since any customer-facing hosted use would trigger AGPL's network-copyleft clause. Only 3 contributors and 77 stars; revisit if the contributor base grows or a non-AGPL dual-license option appears.
