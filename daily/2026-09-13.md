# Open Source Radar — 2026-09-13
_Rotation slot 5 — self-hosted SaaS alternatives, productivity_

## Executive Summary
Today's discovery pass sat squarely in an unusually crowded niche: self-hosted CRM,
project-management, and billing tools that build AI-agent access (MCP, REST, webhooks)
into the product itself rather than bolting a chatbot onto the UI. Three entrants cleared
the bar — a CRM, an issue tracker, and a billing engine — all AGPL-3.0 and all worth
knowing for different reasons: one is production-ready enough to actually run a client
pipeline on, one is pre-stable but architecturally interesting for agent-as-teammate
workflows, and one is a "study the architecture, don't switch yet" case against a more
mature incumbent. A parallel theme was licensing sleight-of-hand: a second AI-PM tool
(Taskosaur) markets itself as "open source" while actually shipping under a Business
Source License — the same pattern flagged in Notifuse two weeks ago.

## Today's Best Discoveries

### 1. It's a Plan (itsaplan) — 7.7/10
**Decision:** PROTOTYPE

**What it is** — Self-hosted project-management/issue tracker (TypeScript, Bun, Turbo
monorepo, Docker Compose with Postgres + MinIO) positioned as an open alternative to
Linear/Jira/Trello/Plane.
**Why I should care** — AI agents get a real board assignee slot, role, and permissions —
not a sidebar chatbot — and the whole thing is exposed over REST, webhooks, and MCP. It's
also built on infrastructure already in daily use (TS, Docker, S3-compatible storage,
OIDC SSO), so evaluating it costs almost nothing.
**What it could replace** — A paid Linear/Jira seat for personal or client engineering
work, plus the custom glue that would otherwise be needed to let a coding agent read/
update tickets.
**Ways I could use it** — Self-host as the primary tracker for client work; give Claude
Code a real assignee slot via MCP and measure whether "agent as teammate" beats "agent as
invoked tool"; sync issues elsewhere via webhooks; borrow the OIDC SSO design (creds in
DB, no `.env` restart) for another product.
**Agent opportunity** — First-party MCP server, REST API, and webhooks, documented as
core to the product rather than an add-on.
**Integration effort** — Low. `docker compose up -d` after filling 8 env values; matches
existing infra (Postgres, S3-compatible object storage).
**Maturity** — Emerging. Created 2026-07-14 (~2 months old), 494 stars, v0.17.0
(2026-09-06), README explicitly warns of breaking changes before a stable release.
**License** — AGPL-3.0-only. Flagged per policy: modified forks offered as a service must
release source. No issue for plain self-hosted use.
**Alternatives** — Linear (proprietary), Plane (AGPL-3.0, already mainstream), Taskosaur
(reviewed today, rejected for BSL licensing), Huly.
**Why this one** — Agent participation is modeled as board citizenship (role +
permissions + assignee), not a chat feature, and it needs zero new infrastructure to try.
**Recommendation** — Prototype it against a real coding-agent task queue before treating
it as a daily-driver tracker; pre-stable status means it isn't a same-day production swap.

### 2. Relaticle — 7.5/10
**Decision:** PROTOTYPE

**What it is** — Self-hosted CRM (Laravel 13 + Filament 5, PostgreSQL) with a
production-grade MCP server (37 tools) and full REST API for agent-operable customer/
deal management.
**Why I should care** — Most self-hosted CRMs treat API/agent access as an afterthought.
Relaticle documents the MCP server and REST API as primary product surface, with a
working example of team-scoped, per-field-encrypted authorization — directly useful both
as an actual CRM for the MSSP/PTaaS side of the business and as a reference for exposing
any data-heavy product to an agent safely.
**What it could replace** — A spreadsheet or paid CRM SaaS for tracking MSSP/PTaaS
clients and leads.
**Ways I could use it** — Run it as the real client/lead CRM; point an ops agent at the
MCP server to auto-log notes and update deal stages; study the 22-field flexible/
encrypted data model; use the REST API as a backend without touching the PHP UI.
**Agent opportunity** — 37-tool MCP server (CRUD, schema introspection, activity history,
pipeline analysis), documented at relaticle.com/docs/mcp.
**Integration effort** — Medium. Laravel/PHP is outside the current daily stack, though
Docker self-hosting and REST/MCP consumption avoid touching PHP directly.
**Maturity** — Emerging-to-mature. Created 2024-09-25 (~2 years old), 1,648 stars, v3.5.8
(2026-09-12), 2,000+ automated tests — but effectively single-maintainer by commit volume
(1,428 of ~1,445 commits from one contributor).
**License** — AGPL-3.0. Flagged per policy — same network-use copyleft consideration as
above.
**Alternatives** — Twenty (mainstream, no native MCP server), EspoCRM, SuiteCRM,
Django-CRM.
**Why this one** — MCP-as-primary-feature plus a genuinely flexible, encrypted data model,
not just "CRM with an API."
**Recommendation** — Stand it up via Docker to evaluate the MCP server against a real
lead-tracking workflow.

### 3. Meteroid — 7.2/10
**Decision:** STUDY

**What it is** — Open-source pricing-and-billing platform: Rust-based real-time usage
metering (no pre-aggregation required), flexible/versioned pricing plans, subscription
lifecycle, invoicing.
**Why I should care** — Billing/metering is exactly the infrastructure that's expensive
to get right and recurs as a blocker between "idea" and "shippable paid product" — this
is a serious, actively developed entrant with a specific edge (high-throughput metering)
for any usage-billed product idea.
**What it could replace** — Hand-built subscription/invoicing/metering logic, or a paid
billing SaaS, for a usage-priced product.
**Ways I could use it** — Back a usage-billed API product; model hybrid flat+usage
pricing before committing to a vendor; study the metering architecture regardless of
which billing engine ends up adopted.
**Agent opportunity** — None found — integration is via its own API, not MCP. Treat any
agent-tool claim beyond that as unclear based on available documentation.
**Integration effort** — Medium. Self-hostable via Docker or usable as Meteroid Cloud,
but billing wiring (webhooks, plan migrations, payment-provider integration) always
warrants care regardless of deploy simplicity.
**Maturity** — Self-declared "status: experimental" despite being created 2023-07-13
(~3 years old), 1,231 stars, v1.0.0-rc7 (2026-08-24) — take that self-assessment at face
value rather than reading "years old and active" as mature.
**License** — AGPL-3.0, flagged loudly: billing infrastructure is a prime candidate for
embedding into a commercial product, and AGPL's network-use clause requires a modified,
hosted version to release its source.
**Alternatives** — Lago (AGPL-3.0, already mainstream and more established at 10k+
stars — the safer immediate adopt), Kill Bill, Stripe Billing (proprietary).
**Why this one** — The real-time, no-pre-aggregation metering engine is a specific
architectural bet Lago doesn't make the same way.
**Recommendation** — Study the metering architecture; Lago remains the safer choice to
actually adopt today if billing infrastructure is needed now.

## Worth Watching
- **DeskcommCRM** (melgarafael/DeskcommCRM) — Next.js/TypeScript/Supabase, MIT-licensed
  WhatsApp-first "AI sales OS" CRM, 1,907 stars, real CI and multiple secondary
  contributors. What would make it worth catalouging: less affiliate-marketing pressure
  in the primary install flow (a HostGator VPS partnership link is embedded directly in
  the "one command" self-host instructions) and an explanation for its unusually high
  fork-to-star ratio (561 forks against 1,907 stars, roughly 5x a typical repo's ratio) —
  neither is disqualifying alone, but together they're worth resolving before
  recommending it as an install-and-trust CRM.
- **Taskosaur** (Taskosaur/Taskosaur) — Conversational-AI project management, 556 stars,
  legitimate multi-contributor codebase (TypeScript/NestJS/Next.js). What would make it
  worth reconsidering: dropping the "open source" framing for its actual Business Source
  License, or relicensing to something OSI-approved — as-is, itsaplan covers the same
  niche without the licensing ambiguity.
- **aglyn** (aglyn/aglyn) — Apache-2.0 self-hosted website builder + CMS + commerce +
  forms + workflows, active since 2020 but only 5 stars. What would make it worth a
  deeper look: any sign of real external adoption or a written self-hosting guide — right
  now there's nothing to differentiate a 5-year, near-zero-traction project from
  abandonware without one.
