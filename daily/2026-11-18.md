# Open Source Radar — 2026-11-18
_Rotation slot 1 — AI agents, MCP, coding productivity_

## Executive Summary
Today's slot-1 sweep surfaced a genuine theme: infrastructure vendors and research teams building the plumbing *around* coding agents rather than another coding agent itself — a self-hosted agent-memory layer from ClickHouse built on its own database, a harness-abstraction layer (HarnessRouter) letting a product switch Claude Code/Codex/Hermes/etc. without rewriting integration code, and a unified "antivirus" for agent runtime safety (HOL Guard) that consolidates several niches this catalog already tracks as separate point tools. NVIDIA's SkillEvaluator got promoted off Worth Watching after v1.0.1 finally shipped the standalone compatibility checker that was missing in September. Broad GitHub keyword sweeps on MCP/agent-memory/coding-agent/gateway terms were overwhelmingly noise today — several results showed clearly inflated star counts (one repo reported 467,084 stars with no corresponding engagement signal), reconfirming the star-inflation pattern flagged repeatedly in past runs; real signal came from a handful of credible-org or well-documented entrants rather than the broad sweep itself.

## Today's Best Discoveries

### 1. ClickHouse Loom — 8.3/10
**Decision:** PROTOTYPE

**What it is** — Self-hosted shared memory, document search, and code intelligence for AI agents, built by ClickHouse Inc. on ClickHouse itself. Memories link to the code they describe and are flagged when that code changes; includes a multi-language code index, document search with citations, multi-user namespaces, an MCP server, and Python/TypeScript SDKs with native Claude Code and Codex plugins.
**Why I should care** — The agent-memory niche is already crowded in this catalog (CortexDB, rostam, mnemosyne, cognee), but this is the first entrant from a credible infrastructure vendor self-hosting its own product on its own engine, with memory tied to *code* specifically rather than plain semantic recall — a materially different and more useful guarantee for a coding-agent workflow.
**What it could replace** — A separate RAG/document-search stack plus hand-rolled "remind the agent what we decided last time" context-stuffing.
**Ways I could use it** — persistent team-shared memory per repo; code-index queries for blast-radius/caller questions; document search with citations over specs/PDFs; shared task inboxes across multiple agents on the same codebase; session briefs to resume work from a prior run's goal and cost.
**Agent opportunity** — MCP server, Python/TypeScript SDKs, native Claude Code and Codex plugins.
**Integration effort** — Low: one Docker install script starts Loom + ClickHouse together, switchable between personal and multi-user mode without losing data.
**Maturity** — Emerging (created 2026-10-08, ~6 weeks old), unusually polished for its age (CI, OpenSSF Scorecard, published benchmark protocols, i18n in six languages).
**License** — Apache-2.0, no commercial-use restrictions.
**Alternatives** — CortexDB, rostam, mnemosyne, cognee.
**Why this one** — Published benchmarks with explicit caveats ("not statistically established," "results are specific to the tested workloads") are rare honesty in this niche; 159 stars with no inflation red flags is a better trust signal here than a bigger number would be.
**Recommendation** — Stand it up against a real repo to test whether code-linked memory holds up in practice.

### 2. HarnessRouter (Community Edition) — 8.0/10
**Decision:** PROTOTYPE

**What it is** — Self-hosted infrastructure implementing the Unified Harness Protocol (UHP): turns 31+ coding-agent harness bases (Claude Code, Codex, Hermes, Pi, OpenCode, Cline, goose, Aider, and more) into interchangeable backends behind one OpenAI Responses-compatible API, with sessions, streaming, files, cancellation, and structured failure handling.
**Why I should care** — Directly hits the micro-SaaS/product-building axis: building anything on top of "a coding agent" today means picking one harness and eating its integration surface, or rebuilding session/streaming/artifact plumbing per harness. This removes that cost.
**What it could replace** — Hand-rolled per-harness integration code for any product that wraps a coding-agent harness.
**Ways I could use it** — backend for a product that lets a customer pick their own harness/model; cost/latency arbitrage across harness x model pairings (the project's own benchmark shows up to 99.8% cost difference and 3.2x latency difference between best/worst configuration for one task); a stable API to build internal tooling against instead of coupling to one CLI's flags.
**Agent opportunity** — The entire project is agent orchestration infrastructure — one API, any harness.
**Integration effort** — Low to stand up (`docker run`, ~4GB disk, your own provider key, no HarnessRouter account needed); medium to build a real product against the UHP surface.
**Maturity** — Emerging (created 2026-08-09, ~3 months old), near-daily release cadence, 488 forks against 30 subscribers.
**License** — Apache-2.0 for the Community Edition, confirmed via LICENSE file; a separate managed Cloud edition exists alongside it.
**Alternatives** — Hand-rolling integrations (status quo); LiteLLM/Bifrost solve a lower-level problem (model API normalization, not harness/session abstraction).
**Why this one** — No direct open-source competitor at the harness-abstraction layer was found in this catalog; the UHP open standard is worth tracking independent of this specific implementation.
**Recommendation** — Worth a trial for anything currently hard-coding a single coding-agent harness; too new to depend on in production yet.

### 3. HOL Guard — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A unified runtime policy-enforcement layer ("open-source antivirus for AI agents") covering destructive shell commands, package-install supply-chain scanning, plugin/skill/MCP review, and prompt-injection screening in one approval workflow and audit trail, with native hooks across 16 coding-agent harnesses.
**Why I should care** — This catalog already tracks point solutions for several of these surfaces individually (Destructive Command Guard for commands, SkillSpector/cisco-mcp-scanner for skills and MCP servers). HOL Guard's distinction is unifying them behind one approval flow and audit trail, which matters for the MSSP/PTaaS context specifically: "what did the agent try to do, and who approved it" becomes one answerable question instead of three.
**What it could replace** — Running and reconciling several separate safety tools with separate approval flows.
**Ways I could use it** — single install protecting whichever harnesses are actually in use; `hol-guard command test/explain` before running an ambiguous command manually; `hol-guard supply-chain scan` and `hol-guard abom --format json` for an AI bill-of-materials view; `hol-guard receipts` as a cross-harness audit trail — plausibly reusable as a client-facing report in the MSSP security-portal product.
**Agent opportunity** — Native pre-tool hooks for most harnesses, managed MCP proxies where native hooks aren't available.
**Integration effort** — Medium: `pipx install hol-guard && hol-guard init` is simple, but enforcement depth varies per harness — check the support matrix.
**Maturity** — Emerging-to-mature (created 2026-03-28, ~8 months old), active CI/publish pipeline, OpenSSF Scorecard badge, named sponsors.
**License** — Apache-2.0.
**Alternatives** — Destructive Command Guard, SkillSpector, NVIDIA SkillEvaluator, cisco-mcp-scanner — HOL Guard's pitch is breadth across all of these, not a new individual capability.
**Why this one** — The ABOM export and unified receipt/audit trail are the pieces none of the narrower point tools provide.
**Recommendation** — Test alongside, not necessarily instead of, the already-catalogued point tools — specifically for the audit trail and ABOM export. Note: 1,110 stars against only 2 subscribers (555:1) is an elevated ratio per this catalog's recurring engagement pattern; the 278 forks is a real-usage counter-signal, but worth keeping in mind.

### 4. NVIDIA SkillEvaluator — 7.9/10 (promoted from Worth Watching)
**Decision:** PROTOTYPE

**What it is** — A multi-tier framework for evaluating AI agent skills/plugins: static compatibility checks, quality gates, overlap detection, and live agent evaluation. v1.0.1 (shipped today) made the static tier, HarnessCheck, fully standalone — no model key, no NVIDIA pipeline — checking a skill against versioned compatibility profiles for Claude Code, Codex, Copilot CLI, Hermes, OpenClaw, and OpenCode.
**Why I should care** — This was held out of the catalog on 2026-09-30 for needing NVIDIA's own Verified Skills/Harbor pipeline to be useful. That objection is now resolved: `skillevaluator harness-check ./my-skill` is a zero-dependency check anyone authoring a Claude Code skill can run.
**What it could replace** — Trial-and-error discovery that a skill is silently truncated or rejected by a specific harness after shipping it.
**Ways I could use it** — run HarnessCheck before publishing any Claude Code skill; use the full Tier 1-3 pipeline if building a skill registry/marketplace; NeMo Gym backend for teams already in that ecosystem.
**Agent opportunity** — Installable as an agent-assisted evaluation skill itself (`npx skills add NVIDIA/SkillEvaluator`); usable directly in repository CI.
**Integration effort** — Low for the HarnessCheck subset (PyPI install, standalone CLI); medium-high for the full live-evaluation tier (model-key spend, NeMo Gym setup).
**Maturity** — v1.0.1 is explicitly "our first complete release in the 1.0 series," backed by NVIDIA with a published arXiv paper.
**License** — Apache-2.0.
**Alternatives** — SkillSpector (security, adjacent problem); today's Small but High-Leverage Utility, AsItIs agent tools, checks a related but narrower question worth comparing directly in a future review.
**Why this one** — The specific objection that kept it out of the catalog for seven weeks is now gone.
**Recommendation** — Run HarnessCheck against any Claude Code skill before publishing it.

## Small but High-Leverage Utility
**AsItIs agent tools** (Katta041/asitis-agent-tools) is a read-only linter for CLAUDE.md, AGENTS.md, and SKILL.md that shows exactly what a coding agent actually loads at session start, what loads later and under what trigger, and what's silently shadowed — with a token-budget estimate per file. It directly answers a question this very radar project depends on: does an agent load AGENT.md the way the spec assumes, or does a conflicting local override or harness-specific fallback rule silently win? Thin traction (4 stars, 7 weeks old) but the idea is narrow enough to verify in one run — worth trying against this repo's own AGENT.md/CLAUDE.md setup.
