# Open Source Radar — 2026-10-16
_Rotation slot 3 — developer utilities, debugging, testing_

## Executive Summary
Today's slot surfaced a cluster of tools treating verification itself as the unit of
work rather than an afterthought: a coverage CLI explicitly structured around "agent
closes one gap, gets one verdict" instead of a raw percentage, and a fault-injection
testbed for MCP clients/gateways — a niche nothing else in the catalog covers, since
the generic API-mocking tools (mockd, Pikopod) don't model MCP's own protocol semantics.
Broad GitHub keyword search (visual regression, mutation testing, flaky-test detection,
local CI runners) was mostly noise today; the signal came from narrower, more specific
angles, consistent with the pattern noted in recent product-infrastructure runs.

## Today's Best Discoveries

### 1. Supercov — 8.0/10
**Decision:** PROTOTYPE

**What it is** — A coverage CLI built around a one-gap-at-a-time loop: run your existing
test command unmodified, get line/branch/function/MC-DC coverage with per-test
attribution, and a single most-useful uncovered path to target next.
**Why I should care** — Most coverage tools stop at a percentage; this turns "coverage is
low" into a bounded, concrete task an agent (or a human on autopilot) can execute without
drifting into unrelated changes.
**What it could replace** — A hand-rolled coverage CI check, or a CodeCov/Coveralls
subscription for teams that just want PR-level gap visibility.
**Ways I could use it** — Wire into CI for PR comments on untested changed lines; hand an
agent `supercov gaps` and let it close one path per iteration; run unattended overnight
restricted to test-only changes; use `supercov diff` to confirm a new test covers what it
was written for.
**Agent opportunity** — Ships as a Claude Code / Codex / Gemini CLI agent skill
(`/supercov:coverage`) plus a GitHub Action.
**Integration effort** — Low: single `npx`/`pip`/`cargo`/Homebrew install, no server, no
account for the core coverage path.
**Maturity** — Emerging — created 2026-08-23, already at npm v4.12.2 via GitHub Actions
OIDC trusted publishing (credible supply-chain signal, but fast version churn).
**License** — MIT core. Optional quality/security scoring calls a separate paid
"TypeSafe AI" API (~$0.01/MB, cached) — not required for coverage itself.
**Alternatives** — Istanbul/nyc/c8/Jest coverage (no agent loop), CodeCov/Coveralls
(hosted, no agent loop), SonarQube (heavier, server-based).
**Why this one** — Cross-language parity (JS/TS/Python/Ruby/Rust/Go/Java/Kotlin) in one
CLI surface, with the gap-at-a-time framing built in rather than left to the user.
**Recommendation** — Prototype the free core CLI in one repo's CI before touching the
paid scoring feature.

### 2. Cakewalk MCP Test Kitchen — 7.2/10
**Decision:** PROTOTYPE

**What it is** — A configurable MCP server testbed that injects faults (HTTP error
sequences, JSON-RPC errors, tool failures, elicitation/approval flows, SDK-compatibility
scenarios) at MCP clients and gateways, with a live request log in a React admin UI.
**Why I should care** — Nothing else in the catalog tests the MCP protocol itself; mockd
and Pikopod cover generic REST/gRPC/WS fault injection but don't model JSON-RPC errors or
MCP elicitation flows.
**What it could replace** — A hand-written throwaway broken MCP server used to test
retry/backoff logic in an MCP client or gateway under development.
**Ways I could use it** — Verify retry/backoff against a 503-then-200 sequence; check a
client survives a JSON-RPC error or `isError: true` tool result; test
elicitation/approval UX; check MCP C# SDK 2.0 compatibility.
**Agent opportunity** — Directly useful when building or hardening MCP servers/gateways
that will sit in front of real agent sessions.
**Integration effort** — Medium: Docker Compose is the fast path; local dev needs .NET 10
+ Node 22 + Docker/Postgres.
**Maturity** — Experimental — created 2026-10-07 (9 days old), 4 stars, single visible
contributor.
**License** — MIT.
**Alternatives** — mockd, Pikopod (both catalogued, neither MCP-protocol-specific).
**Why this one** — It's the only entrant found in this niche at all, not the best of
several.
**Recommendation** — Trial against any MCP client/gateway currently in development, with
the expectation the project may need patching given its age.

### 3. vayu — 6.8/10
**Decision:** PROTOTYPE

**What it is** — A desktop API client (Postman-style) with a bundled native C++
load-testing engine, combining request design and k6-level load testing in one local
app.
**Why I should care** — Pure workflow consolidation: removes the Postman→k6
context-switch if that's a real daily friction point.
**What it could replace** — Running Postman/Insomnia/Bruno and k6/Locust/goose as two
separate tools for the same API.
**Ways I could use it** — Design a request collection and immediately load-test the same
endpoints at concurrency; quick smoke-level load test of a staging endpoint pre-launch.
**Agent opportunity** — None identified — no CLI/API/MCP surface documented.
**Integration effort** — Medium: desktop installer per OS, no scripting surface for CI.
**Maturity** — Emerging — created January 2026, active releases (v0.43.0, 2026-10-14).
**License** — AGPL-3.0 — flagged loudly; fine locally, do not embed in a hosted product
without a separate license.
**Alternatives** — Postman/Insomnia/Bruno (design only); k6/Locust/goose (load testing
only, more permissive licenses).
**Why this one** — The native-engine-in-one-app bundling is the only real
differentiator; worth it only if tool-switching is the actual pain point.
**Recommendation** — Only worth trying if the two-tool context switch is a recurring
annoyance; otherwise use k6 and a request client separately.

## Small but High-Leverage Utility
**commit-check** — a single config file that checks commit messages, branch names,
sign-offs, and now AI-attribution trailers against team policy, enforced in CI or a
pre-commit hook. As AI-agent-authored commits become routine, knowing which commits were
agent-generated is worth tracking as policy rather than convention — and this replaces
the ad hoc git-hook script most teams write once per repo and never maintain again.
