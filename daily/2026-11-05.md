# Open Source Radar — 2026-11-05
_Rotation slot 2 — product infrastructure, APIs, backend components_

## Executive Summary
Three separate, independent projects surfaced today pivoting existing infrastructure (SSO/IAM, zero-trust networking, and a dedicated LLM/MCP proxy) specifically toward governing AI-agent access — a stronger-than-usual theme for slot 2. Casdoor is a mature six-year-old SSO/IAM server that just rebranded itself "agent-first," Octelium is an 18-month-old zero-trust access platform (VPN/ZTNA/ngrok-alternative/PaaS) that added an AI/MCP gateway on top of its existing identity model, and ThinkWatch is a purpose-built AI API + MCP governance gateway with cost accounting and PII redaction. A fourth, unrelated find — docs.plus, a collaborative document editor with a distinctive per-heading chatroom UX — rounds out today's discoveries as a product-building-block rather than a gateway. Generic "MCP gateway" GitHub search otherwise surfaced a now-familiar saturated wave with no further standouts.

## Today's Best Discoveries

### 1. Casdoor — 8.2/10
**Decision:** USE NOW

**What it is** — A mature, six-year-old self-hosted IAM/SSO server (OAuth2, OIDC, SAML, CAS, LDAP, SCIM, WebAuthn, MFA) that now bills itself as "Agent-first IAM / LLM MCP & agent gateway," with a built-in MCP and agent gateway sitting on top of the same identity/policy engine used for human SSO.
**Why I should care** — Any product sold to a second enterprise customer eventually needs real SSO/SAML support, and Casdoor removes that build from scratch while also letting the same RBAC govern what an AI agent is allowed to touch.
**What it could replace** — A hand-rolled Passport.js/OAuth server, or building SAML/LDAP/SCIM support from scratch.
**Ways I could use it** — Central SSO/IdP for the MSSP admin-portal SaaS; RBAC/multi-tenant user management for a new product; one OIDC provider for both humans and agents; LDAP/SAML bridge for enterprise customers.
**Agent opportunity** — Built-in MCP & agent gateway; an agent authenticates through the same OIDC flow as a human instead of a static API key.
**Integration effort** — Low. Single Docker container + Postgres/MySQL, one YAML config, documented quick start.
**Maturity** — Mature (created 2020, 14,762 stars, weekly releases, v4.25.0 on 2026-10-30).
**License** — Apache-2.0. No commercial-use restrictions.
**Alternatives** — Keycloak (household-name, excluded by policy), Logto (lighter, narrower protocol coverage), Issuerd/Authup (catalogued, narrower agent-specific IAM).
**Why this one** — Broadest protocol coverage (CAS/LDAP/SCIM included) of the group, plus six years of production hardening the newer agent-only IAM tools don't have.
**Recommendation** — Install and point one internal tool's auth at it as a first test.

### 2. Octelium — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted, unified zero-trust secure access platform on Kubernetes: zero-config VPN, ZTNA/BeyondCorp platform, ngrok/Cloudflare-Tunnel alternative, API gateway, AI/LLM gateway, MCP-gateway infrastructure for agents, and a lightweight PaaS, all under one identity-based policy engine.
**Why I should care** — Combines zero-trust VPN, API/AI gateway, and secretless cloud-API access under one identity model — directly relevant to AWS/EKS infrastructure and to safely exposing internal services to AI agents without static credentials.
**What it could replace** — Tailscale/Twingate/Cloudflare Access subscriptions, an ngrok subscription, and manually distributed AWS API keys.
**Ways I could use it** — Zero-trust access into AWS/EKS infra; secretless S3/Lambda access; self-hosted ngrok replacement for dev/demos; MCP-gateway for agent access control; a self-hosted PaaS for Next.js/Node apps.
**Agent opportunity** — Native MCP-gateway and A2A support with OAuth2 client-credentials auth and per-request policy-as-code (CEL/OPA) access control.
**Integration effort** — Medium. Genuinely self-hostable with a documented single-node install path, but requires running on Kubernetes and learning its policy model.
**Maturity** — Emerging (18 months old, 4,154 stars, 159 forks, 20 subscribers, v0.49.0 weekly cadence).
**License** — AGPL-3.0 (flagged — fine for internal self-hosting, revisit before any hosted commercial offering; README also shows an Apache-2.0 badge for what's likely a client-library subcomponent, worth verifying per-directory before redistribution).
**Alternatives** — Teleport, Cloudflare Access, Tailscale (all SaaS-dependent); Issuerd/Midplane (catalogued, narrower single-purpose gateways).
**Why this one** — Breadth: network + API + AI gateway in one identity model, at the cost of a Kubernetes dependency.
**Recommendation** — Stand up a single-node instance to test the zero-trust-access and secretless-AWS-API angles.

### 3. ThinkWatch — 7.5/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted AI API and MCP gateway for organizations: every LLM request and MCP tool call is authenticated against the org's OIDC IdP, rate-limited and budgeted per user/role, scanned by PII/secrets and prompt-injection guards, and logged to a ClickHouse audit trail — a bastion host for AI access.
**Why I should care** — Puts cost visibility, access control and a content/PII safety net in front of every agent's model and tool calls, directly relevant before giving agents broader write access to real infra or MSSP/PTaaS client data.
**What it could replace** — A hand-built LLM-provider format-conversion layer, per-user MCP OAuth plumbing, rate-limit/budget tracking, and a manual PII-redaction pass.
**Ways I could use it** — Single governed entry point for Claude Code/Cursor/CI calls to any model provider with per-user budgets; per-user MCP OAuth so tool calls show the real user upstream; PII/secrets redaction before data leaves the network; prompt-injection/dangerous-tool-call filtering.
**Agent opportunity** — Fills the governance-layer gap this catalog has only found in pieces before (Issuerd for IAM, Midplane for SQL, keypaste for secrets), bundled for the AI-request/MCP-call path with cost accounting.
**Integration effort** — Low. One-command Docker Compose deploy with auto-generated secrets; a Helm chart for Kubernetes.
**Maturity** — Emerging (7 months old, 814 stars, 23 forks, 4 subscribers, v3.11.0).
**License** — Business Source License 1.1 (flagged — free up to 10M billable tokens / 10K MCP calls per month, converts to GPL-2.0-or-later in 2030; GitHub API reports NOASSERTION, confirmed BSL-1.1 by reading the LICENSE file directly).
**Alternatives** — Issuerd (catalogued, general-purpose not LLM-specific); mcpspan/Pare (catalogued, observability/compression not governance); commercial LLM gateways (Portkey, LiteLLM proxy).
**Why this one** — The only one of the three with cost accounting, PII redaction, and prompt-injection filtering built specifically around the AI-request/MCP-call path.
**Recommendation** — Run it as the personal/small-team gateway for Claude Code and MCP usage given the generous free tier.

### 4. docs.plus — 6.8/10
**Decision:** PROTOTYPE

**What it is** — A self-hostable real-time collaborative document editor (Etherpad-descended, Tiptap/ProseMirror/Yjs) with a chatroom on every heading, per-section unread counts, and an MCP integration for Claude/ChatGPT/Cursor to edit documents directly.
**Why I should care** — A 6-year-old, MIT, actively maintained editor with a genuinely distinct UX (section-scoped comment threads, not whole-page) removes a multi-week realtime-editor build and is a plausible embeddable feature or standalone micro-SaaS seed.
**What it could replace** — A Notion/Confluence subscription for straightforward team docs with discussion; a from-scratch CRDT-based realtime editor build.
**Ways I could use it** — Embeddable collaborative-editing feature inside the MSSP admin portal; internal team wiki/spec tool; self-hosted Google Docs alternative; a micro-SaaS seed around the chatroom-per-heading UX.
**Agent opportunity** — Ships an MCP server letting agents read/write directly inside a shared document.
**Integration effort** — Medium. 8-service Docker Compose stack plus externally-provided Postgres, Supabase, and S3-compatible storage (local disk unsupported).
**Maturity** — Mature core, modest community (created 2020, 98 stars, 6 subscribers, v2.2.0).
**License** — MIT. No restrictions.
**Alternatives** — Liveblocks/raw Yjs (lower-level primitives); Outline/HackMD (other self-hosted doc tools).
**Why this one** — The per-heading-chatroom UX and MCP integration are distinct enough to be worth a trial versus generic collaborative editors.
**Recommendation** — Run `make dev-local` to evaluate the editor UX and MCP integration before committing to the full self-hosting stack.

## Small but High-Leverage Utility
**hookdeck/hookdeck-cli** (Apache-2.0, 369 stars) — a CLI that forwards webhooks to localhost with free, permanent event URLs (an ngrok alternative purpose-built for webhooks), plus a bundled MCP server exposing webhook-gateway resource management as tools for AI/agent clients. The tunneling/listen feature needs no self-hosting and no paid tier for local development use, which makes it a genuine time-saver for anyone debugging webhook integrations repeatedly. Worth noting clearly: the broader "Event Gateway" resource-management commands depend on Hookdeck's own hosted backend, so this is a dev-utility recommendation, not a self-hostable infrastructure one — Hookdeck "monetizes the platform with its production offering," per its own README.
