## Today's Best Discoveries

### 1. NestLens — 8.6/10
**Decision:** USE NOW

**What it is** — Laravel Telescope-inspired debugging and monitoring dashboard for
NestJS: 16 watchers (request, query, exception, job, cache, Redis, schedule, event,
batch, mail, HTTP client, notification, gate, command, view, dump, GraphQL) with a
real-time web dashboard, most auto-detected with zero config.
**Why I should care** — NestJS is explicitly named in Sourav's stack. This is a
one-line-import replacement for the request/query/exception debugging tooling he'd
otherwise hand-build per project.
**What it could replace** — Custom request-logging middleware, a hand-rolled query
interceptor, an exception tracker, and a debug dashboard UI — several days of glue
code across watchers.
**Ways I could use it** — Drop into any NestJS service for local dev visibility; leave
gated behind IP whitelist + RBAC in staging; use automatic data masking to keep
sensitive fields out of the dashboard; monitor Bull queue/job health without a separate
observability stack; reuse the same setup across a microservice fleet.
**Agent opportunity** — None; this is a human-facing debugging dashboard.
**Integration effort** — Low: `npm install nestlens`, one module import, visit
`/nestlens`.
**Maturity** — Emerging (v0.14.2, pre-1.0, documented breaking changes across
0.4.0/0.6.0/0.8.0; single primary maintainer).
**License** — MIT, no restrictions.
**Alternatives** — Laravel Telescope (PHP-only), hand-rolled logging + dashboard,
Sentry/Datadog APM (paid, heavier, not query-level out of the box).
**Why this one** — Directly matches the named stack, not a generic "might be useful"
find.
**Recommendation** — Install into a current NestJS project this week.

### 2. Codanna — 8.3/10
**Decision:** PROTOTYPE

**What it is** — Local code intelligence MCP server and CLI for AI coding agents. One
MCP call returns a symbol's signature, docstring, call graph (callers/callees), and
blast-radius impact fused together, instead of an agent chaining several tool calls.
**Why I should care** — Directly hits the AI-agent-leverage axis: fewer round-trips per
agent session on a large repo, fully local by default (no source code leaves the
machine unless remote embeddings are explicitly opted into).
**What it could replace** — The grep-and-read loop an agent runs today to understand
unfamiliar code; LSP-based navigation, which is accurate but slow to spin up per
session.
**Ways I could use it** — Persistent MCP server for session-long agent work on a large
repo; one-shot CLI mode in slash-commands/bash hooks/CI without a daemon; document RAG
mode to index docs alongside code; `analyze_impact` before a refactor.
**Agent opportunity** — This *is* the agent integration — MCP server plus a Claude
Code plugin with visual x-ray/graph skills.
**Integration effort** — Medium: build from source needs Rust, or use a prebuilt
binary; requires an indexing step and a ~150MB embedding-model download on first use.
**Maturity** — Emerging but active (v0.16.0, 71 forks, multiple contributors, CI in
place).
**License** — Apache-2.0, attribution required per NOTICE.
**Alternatives** — Already-catalogued Semble and Repowise occupy adjacent niches; a
wave of smaller near-duplicates surfaced this run too (see Rejected/Duplicate
Candidates) — this is a genuinely saturated category.
**Why this one** — Breadth (15 languages), claimed speed (76k–249k symbols/sec parse,
sub-10ms warm lookups), and the fused single-call response shape are real
differentiators on paper, but need a hands-on trial before treating the claim as
settled.
**Recommendation** — Trial on an active large repo to see if it measurably reduces
agent tool-call overhead before standardizing on one code-intelligence tool.

### 3. Resterm — 8.0/10
**Decision:** PROTOTYPE

**What it is** — Terminal-native "API-as-code" workbench. Requests live as plain,
git-diffable `.http`/`.rest` files with directives for conditionals, loops, multi-step
workflows, mock servers, and inline SSH-bastion / Kubernetes port-forward tunnels.
Covers HTTP, GraphQL, gRPC, WebSocket, and SSE.
**Why I should care** — The `@ssh` and `@k8s` tunnel directives remove a manual
`kubectl port-forward` or SSH-tunnel step from testing an internal service behind a
bastion or inside a private EKS cluster — a direct fit given the AWS/EKS background.
**What it could replace** — Exported/shared Postman collections that drift from the
codebase; a separate mock-server tool for frontend/backend decoupling; manual tunnel
setup before hitting an internal endpoint.
**Ways I could use it** — Version-controlled request collections reviewed in normal
`git diff`; `resterm record` to reverse-engineer an existing API's traffic into request
or mock files; `resterm run` in CI with JSON/JUnit output; OpenAPI import for fast
onboarding onto an existing API surface.
**Agent opportunity** — None — explicitly "No AI integration" by design. `resterm run`
and the headless Go API are automation-friendly regardless.
**Integration effort** — Low: single binary via Homebrew or an install script, no
account or server needed.
**Maturity** — Emerging but active (v1.9.0, 1,949 stars, pushed same day as review;
single dominant contributor).
**License** — Apache-2.0, no restrictions.
**Alternatives** — Postman/Insomnia/Hoppscotch/Bruno (GUI-first, heavier), Hurl
(plain-text but no TUI/mocks/tunnels), VS Code REST Client (similar file format, no
tunnels or CLI runner).
**Why this one** — The SSH/Kubernetes tunnel directives are a genuinely uncommon
feature among API clients.
**Recommendation** — Worth a trial specifically for any work that regularly touches
bastion- or EKS-fronted internal services.

### 4. Sourcebot — 7.8/10
**Decision:** PROTOTYPE

**What it is** — Self-hosted, multi-repo code search and natural-language codebase
Q&A ("Ask Sourcebot") with IDE-level goto-definition/find-references across every
configured repo and branch regardless of host, deployed via Docker Compose.
**Why I should care** — Reveals a capability (self-hosted, org-wide, grounded code
Q&A) otherwise only available as an expensive enterprise product (Sourcegraph) or not
at all for a small spread of repos.
**What it could replace** — Per-repo, per-IDE search as the only way to find something
across a fleet of services (MERN backends, Next.js frontend, Terraform, NestJS admin
portal).
**Ways I could use it** — Index every active repo into one searchable instance; ask
natural-language questions about unfamiliar/legacy code with citations instead of a
hallucination-prone summary; cross-repo goto-definition without cloning each one
locally.
**Agent opportunity** — "Ask Sourcebot" is itself agent-shaped (a reasoning model
driving Sourcebot's own search/nav tools); no standalone MCP server is advertised in
the README as of this review.
**Integration effort** — Medium: Docker Compose stack, JSON config for repo
connections, an LLM provider to enable the Q&A feature.
**Maturity** — Mature relative to today's other picks (v5.1.14, 375 forks, 121 open
issues — active backlog, not neglect).
**License** — **FSL-1.1-ALv2 (Functional Source License) — flagged loudly.**
Source-available, not OSI-approved; converts to Apache-2.0 two years after each
release. Self-hosting/internal use/embedding is unrestricted; building a directly
competing hosted product from it during the window is not. A separate license applies
to the `ee/` enterprise directory, not fully inspected this run.
**Alternatives** — Sourcegraph (much heavier/enterprise-priced), grep/ripgrep across
cloned repos (no cross-repo Q&A or nav), GitHub's own code search (cloud-only, no
self-hosted index).
**Why this one** — No comparably mature self-hosted org-wide code-search-plus-Q&A tool
surfaced this run.
**Recommendation** — Worth standing up once managing more than one or two active
repos at a time; confirm comfort with the FSL terms first.

### 5. assaio — 7.4/10
**Decision:** PROTOTYPE

**What it is** — Offline-first Go CLI with embedded SQLite that reads local Claude
Code, Codex CLI, Gemini CLI, GitHub Copilot CLI, Cline, and Antigravity CLI logs to
report token usage, cost, and accepted-edit activity per project/vendor — without
extracting or storing prompt text, response text, or code.
**Why I should care** — This radar's own README notes that a daily agent run draws
from the same Claude Max plan usage window as everyday coding work; assaio is a
concrete way to actually see that spend locally rather than guess from the account
usage page.
**What it could replace** — Checking five separate vendor dashboards to understand
AI-coding spend and output.
**Ways I could use it** — `assaio-agent dashboard --since 30d` for an offline HTML
cost/activity report; `assaio-agent evidence --repo .` to correlate local sessions with
local commits (labeled matched/ambiguous/unmatched, never asserted as causal);
`assaio-agent doctor --strict` to catch vendor log-format drift; point it at this very
repo's history to see what the radar run itself has cost over time.
**Agent opportunity** — A tool *about* agent usage rather than an agent tool itself; an
extension protocol allows adding new log-format parsers.
**Integration effort** — Low: single Go binary, `assaio-agent demo`/`init` to try it
with zero network calls on the default path.
**Maturity** — Experimental/pre-1.0 — the project says so directly ("suitable for
evaluation and design-partner pilots"). 86% statement-coverage snapshot, published
corrections log, single primary maintainer.
**License** — Apache-2.0, no restrictions. Embedded LiteLLM pricing snapshot is
separately MIT-licensed.
**Alternatives** — Individual vendor usage dashboards — accurate for quota, siloed per
vendor, no local commit correlation. No self-hosted cross-vendor equivalent found.
**Why this one** — Privacy-conscious design (no prompt/code content ever leaves the
machine on the default path) and a direct answer to a cost question this repo's own
README already raises.
**Recommendation** — Low-risk to try immediately; treat conclusions as directional
given its pre-1.0, single-maintainer status.

## Small but High-Leverage Utility
**lgtm** (`kunkka19xx/lgtm`, Apache-2.0, 58 stars) is a terminal diff reviewer purpose-
built for reviewing AI-agent-written changes rather than human PRs: it runs in a pane
beside a coding agent, re-renders the diff live as the agent writes, and lets you point
at exact lines with vim motions instead of retyping a file path back into the chat.
`lgtm risk` specifically flags when an agent quietly deleted or skipped a test — a
narrow, concrete problem (reviewing fast, high-volume agent output without losing track
of what changed) that a five-minute install fixes. Not catalogued — pre-1.0 (v0.1.5,
created 2026-08-26, single primary maintainer, Zig-based) and worth watching rather
than committing to yet, but worth trying in any active Claude Code/Codex session today.
