# Open Source Radar — 2026-09-26
_Rotation slot 4 — data, search, documents, RAG_

## Executive Summary
Today's slot-4 sweep (12 parallel GitHub Search API queries across RAG, vector databases,
document processing, full-text search, knowledge graphs, embeddings, ETL, data pipelines,
semantic search, rerankers, change data capture, and text-to-SQL) hit heavy noise — dozens
of same-day tutorial repos, "AdalFlow alternative" and rerank-benchmark spam, and several
already-rejected hype waves resurfacing (agent memory, AI/LLM gateways, universal
data-format converters). Underneath that noise, five genuinely differentiated picks
surfaced: Graft, a company-backed coding-agent context layer with unusually rigorous
SWE-bench evidence; CocoIndex, a declarative incremental-indexing framework that replaces
hand-rolled RAG re-embedding logic; seekdb, OceanBase's MySQL-protocol "state store for AI
agents" with a genuinely novel copy-on-write FORK/MERGE sandbox primitive; FrankenSearch, a
hidden-gem embeddable hybrid-search Rust CLI from the same author as the already-catalogued
Destructive Command Guard; and DatI, a small but conceptually direct "governed database as
an MCP tool" gateway. The "codebase context for AI coding agents" niche keeps growing —
today added Graft, sdsrss/code-graph-mcp, ScriptedAlchemy/tracedecay, and
wlsdks/ontology-atlas on top of already-catalogued Codanna, mex, and Repowise — and is
close to needing a head-to-head comparison rather than more individual entries.

## Today's Best Discoveries

### 1. Graft — 8.3/10
**Decision:** PROTOTYPE

**What it is** — A local coding-agent context layer that builds a codebase's architecture
into linked Markdown "nodes" (plain-English summaries plus the exact lines that matter)
instead of embeddings, wired into Claude Code/Cursor/Codex/Gemini via CLI and MCP server,
auto-refreshed against the working tree (including uncommitted edits) before every query.
**Why I should care** — The most rigorously benchmarked entry in an otherwise saturated
niche: a 50-task SWE-bench Verified run resolved 33/50 with Graft versus 27/50 cold, with
25% fewer tool calls and 23% fewer tokens, full harness and task list published.
**What it could replace** — The grep-and-read exploration loop an agent re-runs every
session on a repo it already mapped an hour before; no vector DB or embedding server to
stand up.
**Ways I could use it** — Wire into a large NestJS/React repo for session-persistent
context; `graft blast` as a PR-comment CI step showing blast radius with git-derived
owners; `graft map` for fast orientation on an unfamiliar service; structural-only mode
needs no API key at all; works across monorepos or a folder of separate repos.
**Agent opportunity** — This *is* the agent integration: 6 native MCP tools plus a deep
Claude Code integration (live statusline, post-edit blast-radius warnings, auto-resync).
**Integration effort** — Low: `npm install -g @nanonets/graft`, `graft init`, no daemon or
database — the graph is just files.
**Maturity** — Emerging (created July 2026, npm v0.20.0, no GitHub release tags yet) but
backed by NanoNets, a real funded document-AI company, under the Trail brand.
**License** — MIT, no restrictions.
**Alternatives** — Already-catalogued Codanna (MCP-only, embedding-based), mex, Repowise —
plus a wave of smaller near-duplicates rejected today (see below).
**Why this one** — Company-backed with published, reproducible-methodology benchmarks
rather than just headline claims, and a no-vector-DB, git-diffable design.
**Recommendation** — Trial for a week on an active repo and compare Claude Code's
tool-call/token usage with and without it before deciding whether it replaces or
complements Codanna.

### 2. CocoIndex — 8.2/10
**Decision:** PROTOTYPE

**What it is** — A declarative, incremental data-transformation framework (Rust core,
Python API) for RAG/agent-context indexes: declare a source-to-target flow once, and only
the changed delta re-processes on every subsequent run.
**Why I should care** — Incremental re-indexing (tracking what changed, invalidating only
affected downstream rows, retrying failures without reprocessing everything) is normally a
bespoke, easy-to-get-wrong subsystem in any RAG pipeline; this makes it a Python decorator.
**What it could replace** — A hand-rolled cron job diffing source files against a hash
table, plus the full-corpus re-embed bill that comes with batch-only pipelines.
**Ways I could use it** — Keep a docs/PDF RAG index continuously fresh; AST-aware code
embedding that only re-embeds files touched by the latest commit; structured extraction
from forms/invoices into Postgres with source-byte lineage; meeting-transcript-to-
knowledge-graph pipelines; watch-a-folder-to-Kafka publishing.
**Agent opportunity** — Ships a "CocoIndex skill" for coding agents plus a flagship
"CocoIndex-code" MCP server for AST-aware, incremental, semantic code indexing.
**Integration effort** — Medium: `pip install cocoindex`, but the declarative flow model
(sources/targets/flows) has its own learning curve versus an imperative embed-and-upsert
script.
**Maturity** — Emerging (created March 2025, ~11.6k stars, tagged v1.0.24; two contributors
account for most commits).
**License** — Apache-2.0, no restrictions; a paid Enterprise tier exists for PB scale.
**Alternatives** — Airbyte/Debezium (general ELT/CDC, not RAG-aware), LlamaIndex/LangChain
ingestion (batch-oriented by default).
**Why this one** — The "React for data engineering" mental model and Rust-backed
retry/lineage machinery are a genuine step up from hand-rolled incremental sync.
**Recommendation** — Trial on a real RAG or code-embedding use case where re-indexing cost
or staleness is currently a manual/cron problem.

### 3. seekdb — 8.0/10
**Decision:** PROTOTYPE

**What it is** — OceanBase's MySQL-protocol-compatible database, embeddable or server,
unifying vector, full-text, and scalar search behind one SQL query, with an async
Change-Stream index pipeline and copy-on-write `FORK DATABASE`/`MERGE TABLE` sandboxes for
agent-state exploration.
**Why I should care** — The FORK/MERGE sandbox is a genuinely novel primitive: letting an
autonomous agent write state and safely roll it back is normally hand-rolled
application-layer logic; here it's a kernel-level database feature.
**What it could replace** — Running three separate systems (relational DB, vector DB,
full-text engine) and merging their results client-side for an agent-memory feature.
**Ways I could use it** — Single embedded store for agent episodic memory; snapshot agent
state before a risky autonomous action, merge or drop depending on outcome; hybrid
vector+full-text+scalar retrieval in one query; existing Node MySQL drivers work
unmodified; has merged integration PRs into LangChain, LlamaIndex, and Dify already.
**Agent opportunity** — Positioned explicitly as "the state store for AI agents" — the
async index pipeline targets exactly the continuous-write-then-immediate-read agent loop.
**Integration effort** — Medium: `pip install pyseekdb` for embedded mode or Docker/binary
for a server, but FORK/MERGE and hybrid-search syntax are seekdb-specific SQL to learn.
**Maturity** — Emerging (created October 2025, 3,061 stars, v1.4.0) but built by the
OceanBase team — a mature database vendor, not a solo project.
**License** — Apache-2.0, no restrictions.
**Alternatives** — Postgres+pgvector+a search engine (more moving parts); Milvus/Qdrant for
vector-only (seekdb's own unverified benchmark claims 10.7x its QPS).
**Why this one** — No other catalogued vector/search database offers a built-in
copy-on-write rollback primitive for agent state.
**Recommendation** — Hands-on trial for an agent-memory or hybrid-search use case,
specifically to test the FORK/MERGE pattern and streaming-write latency under load.

### 4. FrankenSearch — 7.6/10
**Decision:** PROTOTYPE

**What it is** — A two-tier hybrid local search engine for Rust plus a standalone CLI
(`fsfs`): sub-millisecond lexical+tiny-embedding first pass, MiniLM-L6-v2 quality
refinement pass, fused with Reciprocal Rank Fusion.
**Why I should care** — A genuinely embeddable, fully offline hybrid search engine with a
checksum-verified installer and extensive troubleshooting docs is unusual at 86 stars —
classic hidden-gem territory, and the same author's prior tool is already a catalogued
USE NOW pick.
**What it could replace** — Standing up Elasticsearch, Meilisearch, or a vector database
for a local or single-machine search feature.
**Ways I could use it** — Local search over a notes/docs vault; a fast search feature
inside a Rust or Tauri desktop tool; search-as-a-library inside a larger Rust service;
offline search for privacy-sensitive local tooling.
**Agent opportunity** — None built in — a general-purpose search building block, not
agent-facing itself.
**Integration effort** — Low as the `fsfs` CLI; Medium to embed the Rust crate in a
service.
**Maturity** — Emerging (created February 2026, v1.10.0 on crates.io), single maintainer.
**License** — MIT with a custom OpenAI/Anthropic Rider — standard MIT for everyone except a
named "Restricted Parties" list (OpenAI, Anthropic, their affiliates, and anyone acting on
their behalf), who are barred from any use at all. No restriction on Sourav's own use,
hosting, or commercial embedding. Same pattern as the already-catalogued Destructive
Command Guard from the same author — flagged loudly per licensing policy, not a blocker.
**Alternatives** — Meilisearch/Typesense (heavier to run), SQLite FTS5 (lexical only,
no semantic tier).
**Why this one** — Real engineering signals (checksum-verified installer, granular
cross-release compatibility docs) at a star count most runs would skip past.
**Recommendation** — Try the `fsfs` CLI on a local search use case before considering the
Rust crate for embedding into a service.

### 5. DatI — 7.5/10
**Decision:** PROTOTYPE

**What it is** — A self-hosted semantic gateway turning a relational/analytical database
(MySQL, PostgreSQL, ClickHouse, Doris) into a governed MCP service: enrich tables/columns
with business-term metadata, then publish built-in or parameterized SQL tools with
per-user credentials and data-scope isolation.
**Why I should care** — A narrow, concrete implementation of exactly the capability named
in the operator profile — "expose it through an API, CLI, MCP server" — applied to the
most common product-building block, a database, with real permission/scoping rather than
a toy NL2SQL demo.
**What it could replace** — A hand-built schema-aware SQL-generation layer with credential
isolation and per-user data scoping, rebuilt from scratch per project.
**Ways I could use it** — Turn a product database into a governed, natural-language-
queryable MCP tool; give a coding agent scoped read access to staging via per-user
credentials instead of a shared superuser connection; business-term enrichment so an LLM
understands internal jargon; NL2SQL over an analytics warehouse for ad hoc reporting.
**Agent opportunity** — The entire product is the agent integration — publishes MCP
(Streamable HTTP) tools consumable by any MCP host.
**Integration effort** — Medium: `docker compose up` (Spring Boot + Vue + Elasticsearch),
self-hosted only, Java stack rather than Node.
**Maturity** — Experimental (created August 2026, 54 stars, single developer) but ships a
real end-to-end test suite and two worked examples (BI warehouse, family-finance app).
**License** — Apache-2.0, no restrictions.
**Alternatives** — AgamiAI/agami-core (evaluated today, not catalogued, less concrete on
the MCP-publishing workflow); hand-rolled NL2SQL agents lacking the permission layer.
**Why this one** — No other catalogued entry currently covers this specific "governed
DB-to-MCP gateway" niche.
**Recommendation** — Trial against a non-critical database to evaluate the permission
model before considering it near production data.

## Small but High-Leverage Utility
**DocIngest** (Amal-David/docingest, MIT, 18 stars) crawls documentation sites, stores them
as clean Markdown, indexes them for search, and exposes the corpus through a web UI, CLI,
and MCP server (`find-docs`, `read-docs`, `query-docs`). It runs a live hosted index at
docingest.com (1,635 sites as of its last count) and installs into Claude Code with one
`claude mcp add` command. For a five-minute setup, it removes the recurring "which version
of this library's docs is the agent actually reading" problem — genuinely useful even
though it isn't mature enough yet (own README: search ranking "needs deeper tuning", no
permissions/collaboration) to take a full catalog entry today.
