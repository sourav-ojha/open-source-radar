# Open Source Radar — 2026-10-01
_Rotation slot 2 — product infrastructure, APIs, backend components_

## Executive Summary
Today's slot-2 sweep across authorization, durable workflows, local-first sync, and full-stack scaffolding surfaced a cluster of genuinely new product-building primitives rather than another wave of near-duplicate SaaS clones. The standout theme: three separate projects (Grit, Vercel Workflow SDK, OpenFGA) each remove a specific multi-week "plumbing" problem — full-stack scaffolding, durable execution, and fine-grained authorization — that would otherwise be rebuilt by hand on every new product. A smaller but notable find, model-compose, applies the docker-compose pattern to AI pipeline definition, letting a workflow become an MCP server with a one-line change. The authorization and workflow-engine spaces both show a mainstream-adjacent project (OpenFGA, Vercel Workflow SDK) backed by a credible company/foundation sitting next to several near-identical but less differentiated alternatives — a sign these categories are consolidating around a couple of strong defaults rather than still being wide open.

## Today's Best Discoveries

### 1. OpenFGA — 8.0/10
**Decision:** PROTOTYPE

**What it is** — A Zanzibar-inspired authorization/permission engine: model access control as relationship tuples, query a stateless Policy Decision Point over HTTP/gRPC, with SDKs for Node.js, Go, Python, Java, .NET.
**Why I should care** — Authorization logic sprawls across controllers and grows inconsistent as permission models get more granular; this centralizes it, and is directly applicable to the MSSP admin-portal SaaS where per-tenant, per-resource permissions matter.
**What it could replace** — Scattered `if (user.role === 'admin')` checks, and the rewrite that happens when a roles table needs to express relationships instead of flat roles.
**Ways I could use it** — Fine-grained per-resource permissions for a multi-tenant admin portal; policy-as-code via Terraform for pull-request-reviewed access control; ReBAC modeling ("can view if a member of the team that owns this"); centralizing authorization ahead of a commercial product needing per-object sharing.
**Agent opportunity** — Usable as the authorization layer behind an MCP server or agent tool that needs to enforce per-user/per-resource access before executing an action.
**Integration effort** — Medium: Docker/binary/Helm to run, SDK to call from the app, but relationship-tuple modeling has a real learning curve and the default in-memory store is non-persistent.
**Maturity** — Mature: created 2022, CNCF Sandbox, 5,892 stars, production-adopted by Auth0, Grafana Labs, Canonical, Docker.
**License** — Apache-2.0, fully permissive.
**Alternatives** — Cerbos (close competitor, YAML-policy model, open-core with an optional proprietary Hub); Keycloak/Auth0 built-in authorization (heavier, identity+authz bundled).
**Why this one** — Strongest adoption signal and CNCF backing of the authorization engines reviewed; composes with any identity provider rather than bundling one.
**Recommendation** — Prototype against the MSSP admin-portal's permission model.

### 2. Vercel Workflow SDK — 7.9/10
**Decision:** PROTOTYPE

**What it is** — A TypeScript/JavaScript durable-execution library: persists workflow progress, retries failed steps, lets workflows suspend without consuming compute, with a Next.js integration and a CLI observability UI.
**Why I should care** — Durable execution is a recurring need in any Node/Next.js product (onboarding flows, agent pipelines, sagas), and this is a TypeScript-native implementation from Vercel rather than a heavyweight multi-language platform.
**What it could replace** — Hand-rolled retry/job-state tracking for multi-step server processes; bespoke saga/compensation logic for chains of API calls.
**Ways I could use it** — Onboarding flows that survive a deploy mid-flight; AI agent pipelines needing replay-safe retries across tool calls; long-running background jobs without hand-rolled state tracking; sagas across multiple third-party APIs.
**Agent opportunity** — Suspending a workflow mid-execution without holding compute is directly useful for agent steps waiting on slow tool calls or human-in-the-loop approval.
**Integration effort** — Low for local dev (`npm install workflow` + one Next.js config line); Medium to self-host via the Postgres-backed "World."
**Maturity** — Emerging: created October 2025 (~1 year), 2,442 stars; 424 open issues is a high ratio worth investigating before depending on it in production.
**License** — Apache-2.0.
**Alternatives** — Temporal (mainstream, heavier, multi-language); Inngest (close competitor, hosted-first); durable-workflow/workflow (same category but Laravel/PHP-only — rejected today as not applicable to a Node/Next.js stack).
**Why this one** — Zero-infra TypeScript-native DX with first-class Next.js integration, versus Temporal's generality or Inngest's heavier hosted-first model.
**Recommendation** — Prototype for an AI-agent pipeline or onboarding flow.

### 3. Grit — 7.8/10
**Decision:** PROTOTYPE

**What it is** — A full-stack scaffolding framework for Go + Next.js: one command generates a monorepo with auth, 2FA, passkeys, RBAC, an admin panel, jobs, storage, email, audit log, and deploy already wired; `grit generate resource X` writes the model/API/types/UI for a new entity from one field definition.
**Why I should care** — Directly hits the micro-SaaS leverage axis — it removes the week-one setup tax (auth, admin panel, jobs, deploy pipeline) that gets rebuilt on every new product idea.
**What it could replace** — Hand-assembling a router, ORM, auth library, admin kit, and deploy pipeline per project; a hand-built admin panel per project.
**Ways I could use it** — Standing up a client-facing or internal SaaS MVP in hours; validating a micro-SaaS idea before a hand-built backend; generating an internal admin tool for an existing data model; a reference architecture worth studying even without direct adoption.
**Agent opportunity** — None exposed as MCP/agent tooling directly; README mentions AI-assisted building against the generated codebase, not reviewed in depth.
**Integration effort** — Medium: easy to scaffold, but adopting it means maintaining a Go backend alongside (or instead of) the existing Node/Express stack.
**Maturity** — Emerging: created February 2026 (~8 months), 136 stars, calendar-style versioning (v3.337.1) suggests fast-moving but not yet settled development.
**License** — MIT.
**Alternatives** — Laravel + Filament (the PHP model it's copying); AdminForth (already catalogued — narrower, admin-panel-only over an existing backend).
**Why this one** — Generates the *whole* stack, not just an admin layer, as plain readable code rather than framework magic.
**Recommendation** — Trial-scaffold a real side project before trusting it with anything load-bearing.

### 4. model-compose — 6.9/10
**Decision:** PROTOTYPE

**What it is** — A docker-compose-style YAML DSL for defining AI systems: chat APIs, RAG pipelines, ReAct agents, and MCP servers composed from interchangeable components, with no orchestration code.
**Why I should care** — Collapses the orchestration boilerplate that gets rebuilt per AI-pipeline project; can turn a defined workflow into an MCP server with a one-line change.
**What it could replace** — Hand-written glue code for chaining models/retrieval/tools; custom MCP server wrapping.
**Ways I could use it** — Fast RAG pipeline prototyping; exposing an existing workflow as an MCP server for Claude/Cursor with one line; declarative ReAct agent definitions; validating an AI feature's shape before committing to custom code.
**Agent opportunity** — Agents and MCP servers are first-class YAML constructs — one of the more direct MCP-authoring shortcuts seen recently.
**Integration effort** — Low: `pip install model-compose`, write one YAML file, `model-compose up`.
**Maturity** — Emerging: created May 2025, 117 stars, apparent single maintainer; GitHub release tags are stale (v0.4.0 from Sept 2025) despite PyPI publishing continuously to 0.4.113 — track PyPI, not GitHub releases, for currency.
**License** — MIT.
**Alternatives** — LangChain/LlamaIndex (mainstream, Python framework to code against instead of YAML); n8n (mainstream, visual canvas instead of a git-friendly text file).
**Why this one** — Zero orchestration code and native vector-DB drivers (Chroma, Milvus, Qdrant, FAISS, Neo4j, ArangoDB, Redis) out of the box.
**Recommendation** — Worth a quick prototype trial; not a long-term production dependency given the bus-factor risk.

### 5. Evolu — 7.2/10
**Decision:** STUDY

**What it is** — A TypeScript local-first platform: a typed, SQLite-backed local data store with built-in end-to-end encryption and CRDT-based sync via a relay server, with bindings for React, Next.js, Svelte, Vue, and React Native.
**Why I should care** — Offline-first product features are a recurring category, and this removes the sync-engine problem (conflict resolution, encryption, relay protocol) that normally takes weeks to build correctly.
**What it could replace** — A hand-built offline-sync layer for any product needing to work without a reliable network connection.
**Ways I could use it** — Offline-first field-service, inventory, or note-taking features; E2E-encrypted sync without a custom backend; PWA/mobile apps prioritizing instant local reads/writes.
**Agent opportunity** — None identified — a client-data-layer tool, not agent-facing.
**Integration effort** — Medium: straightforward for local-only use, more involved once cross-device sync and a self-hosted relay server are in scope.
**Maturity** — Created September 2022, 1,899 stars, 15 open issues (healthy ratio); npm publishing is frequent despite a thin top-level README.
**License** — MIT.
**Alternatives** — RxDB (broader ecosystem, ~23k stars, less built-in encryption focus); Yjs/Liveblocks (document/rich-text CRDT focus vs. Evolu's relational/SQLite model); Supabase (server-first, mainstream, excluded).
**Why this one** — Built-in end-to-end encryption and a smaller, SQLite-native, typed-schema surface than RxDB.
**Recommendation** — Study the architecture now; revisit for direct adoption if a specific offline-capable product idea comes up.
